### [3] 缓存命中看来源 SHA-256 与历史输出文件存在性，不校验输出内容
- quote: `entry.hash !== currentHash`
- url: [ingest cache validation](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src/lib/ingest-cache.ts#L55-L99)；[cache write condition](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src/lib/ingest.ts#L1540-L1549)
- source_type: code
- published: 2026-10-22（固定提交对应 v0.6.13）
- confidence: high
- 交叉验证: 缓存检查函数与成功 ingest 后的缓存写入条件
- 口径说明: 来源文本哈希未变且缓存记录的每个输出路径仍存在时，检查函数返回缓存命中；它检查路径存在，不比较 wiki 输出文件内容哈希。因此仅按源码中的此缓存检查，用户手改但仍存在的输出页不会单独令缓存失效。只有无硬写入失败且无未恢复截断时才写缓存。

### [4] 导入准备可并行，项目提交按顺序串行；切换项目会中断准备并恢复未完成任务
- quote: `Preparation is safe to abandon after abort`
- url: [commit coordinator](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src/lib/ingest-commit-coordinator.ts#L8-L36)；[project mutex](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src/lib/project-mutex.ts#L2-L14)；[project switch and queue restore](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src/lib/ingest-queue.ts#L887-L1004)
- source_type: code
- published: 2026-10-22（固定提交对应 v0.6.13）
- confidence: high
- 交叉验证: 队列提交协调器、按项目互斥器、切换与恢复状态流相互核对
- 口径说明: 队列可并发准备，但提交预留按任务启动顺序执行；每项目写入区由 `withProjectLock` 串行。切换时 abort 活动任务、等待已进入提交区的任务完成、将 processing 归回 pending 并持久化；打开项目时从该项目队列恢复 pending。队列源码默认 worker limit 为 1，仍允许内部设置不同值。

### [5] 来源更名迁移要求调用方先确认内容相同，来源删除按 frontmatter 来源列表处理 wiki 页

- source_type: code
- published: 2026-10-22（固定提交对应 v0.6.13）
- confidence: high
- 交叉验证: 更名迁移、来源删除和 wiki 页删除级联分别读取
- 口径说明: 更名函数要求调用方先依据 watcher 内容 hash 确认是未变文件的移动；迁移来源 frontmatter、来源摘要路径和缓存身份，失败时对部分写入做尽力回滚。删除来源会清理原始/解析缓存与 ingest cache；按 wiki 页 `sources` 列表保留并重写仍有其他来源的页，单一来源页进入删除级联，并移除对应向量 embedding；来源摘要页级联还处理该来源媒体目录。
