# 并行与滚动续派

## 准入

- 最多同时运行 3 个执行子会话，父会话不计入。Codex 按项目委派规则使用普通独立会话。
- 父会话可用一条消息把多张相关卡派给同一执行子会话（如同一系统的多张缺陷卡）。逐卡列出完整 UUID、工作区、范围、目标与禁止文件、依赖、执行顺序及验收标准。
- 派发前逐卡检查状态、占用、决策锁和依赖。批次内后继可预先指派，等前置到「待验收」或「已关闭」后才可领取。
- 比较各会话所负责的文件集，含父会话自做的卡。同文件或目录前缀重叠时，归同一会话逐卡串行，或排队等文件 owner 释放。
- 跨工作区逐区取得授权。

## 批次执行

- 按派工顺序，每张卡开工前重新检查依赖、状态、决策锁和文件 owner，领取后单独验证、汇报和收尾。
- 受阻卡单独回报，可继续批次内已指派且不依赖该卡的就绪卡。失败卡的后继继续等待前置解除。

## 父代理续派

执行子会话回合结束后，父会话立即回读该批次各卡：

1. 用 `kb show` 逐卡核对状态、占用和决策锁。
2. 进行中且同一 owner：继续该卡。进行中但无 owner：重新核依赖与文件 owner，再 claim。
3. 待验收 / 已关闭：记为完成。待规划：记录失败或释放，保持未完成，不自动重试。待决策：按 `ask-user` 处理。
4. 该批次没有可继续的卡时，用 `kb --json next` 与 `kb dep ls` 按依赖优先级选择可派卡，复核文件 owner 后，将单张或一批相关卡续派给同一子会话。

## 依赖优先

- 已完成卡的已就绪下游优先。
- 下游仍被其他 blocker 挡住时，优先推进当前可 claim 的前置。
- 候选都不合格时，让 worker 空闲，不扩大授权。

## worker 输出

按卡回报：

- 卡号；
- 结果；
- 提交短 hash；
- 一句话阻塞。

禁止贴完整测试日志、整段 diff 或大段命令输出。
