# AgentBoard 坑与注意点

## 进程与服务

- 直接 `node apps/server/dist/index.js` 起的实例会在 agent 回合结束后被连带杀掉：日志里能看到 `listening … pid=X` 之后**没有任何退出行**就消失。统一用 `pnpm server:ensure`。
- `kb fail` / `kb close` 只改看板状态，**不会停在跑的 agent 回合**；释放任务后若成员仍 `running`，要用消息让其收尾，必要时 `interrupt_agent`，并复核 `list_agents` 已 `inactive`。
- `.logs/server.log` 是多实例共享文件（同 cwd），排查时按 `pid` 过滤，别把别的实例日志当主服务。

## 前端

- `@theme inline` 漏映射 = 工具类不生成：改令牌时同时验证「类是否真的出现在构建产物 CSS 里」。
- 条件渲染 vs CSS 遮蔽：右侧面板/浮窗类结构一律条件渲染；靠 `transform`/`aria-hidden` 遮蔽会随层叠或过渡变化重新叠出问题。
- `createPortal` 出去的节点**继承不到 App 容器的文字色**：portal 目标要在 `html,body` 设基准色，否则暗色下黑底黑字。
- 原生 `<select>/<option>` 在暗色下按系统主题绘制：必须显式设 `color-scheme` 与 `option` 的 `color/background-color`。
- 测试里 mock 会**镜像实现里的错**：字段名读错（`migrated` vs `migrated_issue_count`）、断言写死实现值，都会让 bug 全绿。字段级断言要对着真实响应体写。
- 服务端字段改名/新增后，先 grep 前端读的**字段名**，不要只改类型。

## 数据

- SQLite 复制必须处理 `-wal`/`-shm`（成对），只拷主文件会丢最近提交。
- `knowledge_revision` 不可变触发器会挡住「删工作区」，正确处理是事务内临时摘除并 `finally` 复原。
- 软删除的页在同一 slug 上会阻止重建（`KNOWLEDGE_EXISTS`），要先 `--status all --include-expired` 查到再决定修订或换 slug。
- 知识页 `sources` 用 `file` 类型时**不要带 `snapshot`**（本地代码来源只存路径与 hash），否则被拒。

## 外部工具

- `resolveWindowsSpawnForm` 优先取 `.exe`：同名工具在 `D:\tools\bin` 有旧 exe 时，即使 PATH 里 npm 版本更新也会用旧的；要换版本得处理那个 exe。
- codebuddy 401 曾自愈：`user-state.json` 的 mtime 刷新说明登录态被刷新，别急着归因到端点或版本。
- PowerShell 5.1 发请求体/写文件会走控制台码页：中文可能变 `???` 或加 BOM。**取证脚本的编码问题不要当成产品 bug**——用 Node 直发 UTF-8 或 `utf8NoBOM` 复测。
- 探活域名先看是否存在：曾把 `api.workbuddy.cn`（NXDOMAIN）当正式 host 用了很久，改前必须 `Resolve-DnsName`/curl 实测。

## Node 版本分裂与 better-sqlite3（原 IMG-04 环境坑）

- 本机 PATH 默认 Node 22.22.2，但 `node_modules` 里的 better-sqlite3 按 MODULE_VERSION 137（Node 24）编译：跑 server 测试与服务进程必须把 `C:/Program Files/nodejs` 放到 PATH 最前，否则 vitest 全红并报 `ERR_DLOPEN_FAILED`。

## 后台服务、端口与代理由（原 IMG-04 / CHAT-RENDER01 结论）

- 后台服务不能用 `nohup … &`：shell 退出即被杀；要用工具托管的后台任务。
- 本机代理会拦 127.0.0.1：抓本地服务用 `curl --noproxy '*'`。
- `vite` 只监听 `::1`：隔离实例必须用 `http://localhost:5174`，`127.0.0.1` 连不上。
- `agent-browser` 0.27.0 在沙箱内无法启动（`open`/`doctor` 均无输出 + SIGTERM）→ 浏览器视觉验收要在能用 CDP 的通道上做，或交人工。

## React hooks 顺序（原 UI-FILTER01 结论）

- `useMemo`/`useState` 等不能放在提前 `return` 之后：分支不同会让 hook 数量变化，浏览器直接报 `Rendered more hooks than during the previous render`（测试环境常不报，只在真机复现）。
- 改动带提前返回的组件时，要核对同文件相邻组件的 hook 顺序。

## 服务单例、陈旧锁与硬杀残留（KB-TECH-01 / fca77f0e）

- 硬杀（`taskkill /F`、强退）不执行 `process.on('exit')` → `server.lock` 残留；下次启动读到 pid 已死即接管。**不要手删锁**：手删会与仍在跑的健康实例并存。
- 「锁被占」≠「服务在跑」：判活要同时看 pid 存活 + 端口健康；只看锁文件会误判。
- `exit 4` 是复用信号不是错误，脚本把它当失败会误报。

## Node 24 默认不读 HTTPS_PROXY（KB-TECH-01 / c1eab19c）

- Node 24 起 `fetch`/undici **默认不读** `HTTPS_PROXY` / `HTTP_PROXY`，必须显式 `NODE_USE_ENV_PROXY=1` 才走系统代理；未设时只表现为 `fetch failed`。
- `NO_PROXY` 必须含 `127.0.0.1`（及 `localhost`），否则回环请求也被送进代理 → 本地健康探测假失败。
- 诊断先确认代理注入是否生效（`server:ensure` 已统一注入），再怀疑网络，不要先改代码。

## 星图 PIXI WebGL 上下文耗尽（KB-TECH-01 / 星图卡）

- 反复挂载/卸载 PIXI 应用会累积 WebGL context，到浏览器上限（通常 8–16）后新上下文创建失败、旧图变黑。
- 卸载必须显式 `forceContextLoss()`（或 `getExtension('WEBGL_lose_context')?.loseContext()`），只 `destroy()` 仍漏 context。
- `hasWebgl()` 探测结果可缓存，但探测用的临时 canvas 必须即时释放，否则每次探测吃掉一个额度。
- 验收看 `webglcontextlost` / `webglcontextrestored` 事件计数，不看画面是否还在。

## 前端测试日期断言的时区口径（ACC-B1 / dueDate 实证）

- `new Date(Date.now() - N*DAY).toISOString().slice(0, 10)` 按 **UTC** 切日期；组件逾期天数按**本地时区**算。UTC+8 每天 0–8 点窗口 UTC 日期比本地早一天，`逾期 N 天`断言必然差 1（本地 07:06 实测报「逾期 6 天」）。
- 修复口径：测试用本地日期回退合成（`new Date()` + `setDate(getDate()-N)` + 本地年月日拼接），与组件口径一致；不要用 `toISOString` 做本地日期字面量。

## 主从/tablist 布局下的文本断言（ACC-B1 / SideBar 实证）

- 同一文案同时出现在左栏索引项与右栏标题（选中平台）时，`getByText` 多元素命中直接抛错（`getMultipleElementsFoundError`）。
- 断言口径：平台可见性用 `accounts-index-item-<app>` testid；只渲染在选中平台的内容（如 `accounts-capability-<app>`）先点索引项切平台再断言，顺带覆盖切换行为。

## 真机键盘取证的通道坑（ACC-B1-2 实证）

- 宿主 IAB/CDP 的 `cua.keypress` 在新开 tab 上**不进页面**：document 捕获探针收不到任何 keydown；先 `cua.click` 一次真实坐标激活 guest 输入后才生效。
- 判定「键盘失效」用探针分层，不要直接改代码：document 捕获阶段 `addEventListener('keydown', …, true)` 记录 → 合成 `dispatchEvent(new KeyboardEvent('keydown', { bubbles: true }))` 验证组件 handler 链。合成事件能触发 + 系统按键探针为空 = 自动化通道问题，非组件缺陷。
- 单测绿 ≠ 真机键盘绿：jsdom/userEvent 与宿主按键通道语义不同，键盘取证必须在真机重做一遍并贴 `aria-selected` / 焦点序列。

## vitest fake timers 与 testing-library 的坑（ACC-B4 实证）

- `vi.useFakeTimers()` 之后**不要用 userEvent**：其内部时钟等待（advance timers / delay）在假时钟下会挂起，级联超时把整条用例拖死。假时钟窗口内的交互用 `fireEvent.click` 直发。
- describe 级加 `afterEach(() => vi.useRealTimers())` 兜底假时钟泄漏——泄漏会把同文件后续用例的 waitFor 全部打乱。
- 验证「N 秒自动收回」类行为：advance 到阈值后必须断言 DOM 回到初态（如确认行消失且账号状态字段不变），只断言定时器被调用不算数。

## 并行 worker 同仓全量的噪声判定（ACC-B3/B4 并行实证）

- 两个 worker 同时在同一仓库跑 vitest 全量时，setup 累计暴涨（单轮 300s+），出现**跨文件随机失败**（首轮失败集与次轮不同、空闲单跑全过）＝负载噪声，按「并发结果不作数」处理：以父代理在两 worker 收尾后的空闲全量为验收依据。
- worker 回报全量数字时必须附「哪些失败判定为噪声 + 单跑复核结果」，否则父代理无法区分真实回归。

## SQLite 自引用外键无子列索引 → 批量删除 O(n²)（STORE-3a 真跑实证）

- `issue.parent_issue_id` 是自引用外键（ON DELETE RESTRICT）。SQLite 每删一行都要检查「是否还有子行引用它」，**子列无索引时这个存在性检查是全表扫描**，整区清场删除退化为 O(n²)：万卡 15s、十万卡 300s+（localize switch / revert copy_back 与普通删卡全部踩中）。
- 修复：`CREATE INDEX IF NOT EXISTS idx_issue_parent ON issue(parent_issue_id)`（migrations/issueParentIndex.ts，放迁移链末尾——任何 issue 表重建都会带走索引，这里幂等补回）+ 批量删除改子表先删（显式 IN 子查询）；十万卡清场降至 1.7s。
- 通则：**新增任何外键（尤其 RESTRICT/自引用）必须同时给子列建索引**；小数据量单测永远发现不了，只有万级以上真跑才暴露——迁移类功能的验收必须含大体量 fixture。

## 写入静默丢中文：CLI 侧回读校验的四条口径（MOJI-GUARD / 77e7a16a）

历史事故：14 张卡的 description 落库成 `????` 串（U+003F），POST/PATCH 返回 2xx、CLI 回执成功，验收时才发现基准错位。结论是**写入成功不等于内容落库成功**，`kb create-issue / update / comment` 现在写完后一律 GET 回读逐字比对，不一致就 exit 1 并回显已写入 id（不重试、不删除，交人工处置）。

四条容易踩的口径，都是这次实现时对着服务端代码核出来的：

- **标题不能逐字比**：`createIssueSchema`/`patchIssueSchema` 用 `z.string().trim()`，落库标题天然去了首尾空格。CLI 比对前先 `sent.trim()`，否则 `-d` 之外只要标题带个尾空格就是假阳性；描述是原样存储，不能跟着 trim。
- **标签不能比**：labels 过 `normalizeLabels`（拆空格/全角逗号、trim、去重），提交形态和落库形态本来就不一样。回读只覆盖标题、描述、评论正文三类文本。
- **评论正文要按窗口翻页读**：`GET /api/issues/:id/comments/:commentId` 默认只回 12000 码位（`sizeQuery` 上限 40000），一次读完会截断成假不一致；按 `truncated` + `content_offset_chars` 续读拼回来。卡面 `GET /api/issues/:id` 不带窗口参数时返回全文，没这个问题（列表接口 `listIssuesPage` 才截断）。
- **合法问号不能误伤**：只有当落库文本出现「连续 ≥3 个 `?` 而提交原文里没有同样片段」才判编码丢失；提交本身就写着 `???` 的属于正常内容。


## GET 网络抖动自动重试一次：undici 断连形态与三类文案（CLI-RETRY / 6df8531d）

`kb` 的网络层只有一条 `fetchResponse`，重试与分类都收在这里。实测（Node 24 + undici，Windows）断连有三种形态，**只有前两种能靠 `code` 认出来**：

- 端口无监听 → 外层 `TypeError: fetch failed`，cause 上 `code = ECONNREFUSED`。
- 对端发 RST（Node 里是 `res.socket.resetAndDestroy()`）→ cause 上 `code = ECONNRESET`，message `read ECONNRESET`。
- 对端收连接后不响应就 `destroy()` / `end()` → cause 是 `SocketError`，`code = UND_ERR_SOCKET`，message `other side closed`，**不带 ECONNRESET**。

由此定下五条口径：

- **测试要造真 ECONNRESET 只能用 `resetAndDestroy()`**：普通 `socket.destroy()` 造出来的是 `UND_ERR_SOCKET`，据此写断言会得到「代码看起来对、错误码永远不匹配」的假绿/假红。
- CLI 只对 `ECONNREFUSED` / `ECONNRESET` 自动重试，**且只重试一次、只重试 GET**（间隔 200ms，`GET_RETRY_DELAY_MS`）；`UND_ERR_SOCKET`（服务端半关闭，常见于进程被硬杀）暂未纳入，留作后续。
- **写请求（POST/PATCH/DELETE）一律不自动重试**，断连时提示「网络中断；重试请复用 --request-id」：真正的安全网是服务端的幂等记录（KB-CLI-1，命中时回 `x-agentboard-replayed: 1`），不是 CLI 盲重试。HTTP 4xx/5xx 是服务端的明确答复，同样不重试、原样透出。
- **与 MOJI-GUARD 的交叉边界**：内容漂移（校验失败）不是网络错误，绝不重试；但校验用的那次回读 GET 本身遇抖动可以重试——它是只读请求，补发不会重复写。
- 重试提示与版本警告同口径走 `process.stderr`，不经过注入的 Io；单测要 `vi.spyOn(process.stderr, 'write')` 才断言得到「已重试 1 次」。


## kb knowledge CLI 操作坑（2026-11-09 实测，RESEARCH-X/CR2 轮）

- `kb knowledge show` / `resolve` 按 **slug** 查新建页报「知识页不存在」：必须用完整 36 位 id；`revise` 对 8 位前缀同样报不存在——三者都全 id 走。
- file 来源**及其 evidence 条目**一律禁 `snapshot`：服务端拒「本地代码来源只保存路径和 hash」；snapshot 只允许 url/agent 来源。
- `agent` 来源同样必填 `content_hash`（64 位 sha256，可对 snapshot 摘要文本计算）。
- 超长中文正文（>150 行含表格）用 heredoc 直喂 `--stdin` 会终止符失配（整段被吞进正文、后续命令被吞）：改用编辑工具落 `.tmp` 文件 + `< 文件` 重定向直喂，写完即删。
- `create` 后立即按 slug `show` 回读会误判「未保存」——回读一律用返回的 page id。
