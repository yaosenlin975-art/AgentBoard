# kb show / claim 评论限量（OPT-04）

## 口径

- 缺省只渲染最近 5 条评论（`COMMENT_DEFAULT_LIMIT`）；`--comments <n>` 覆盖；`--comments all` = 全量原文，与改造前逐字一致（`commentLines(raw, { totalComments: raw.length })` 与 `commentLines(raw)` 深度相等，单测锁定）。
- 未读优先：`--mark-read` 的 consume 响应带 `is_new` 时，先按未读占位（未读超过上限时保留最近未读），剩余名额用最近已读补满，输出仍按服务端时间序；默认只读（无 `is_new`）时等价于「最近 N 条」。
- 有隐藏条数时表头显示 `评论（5/17）:`，末尾单独一行 `另有 12 条，--comments all 查看`。
- 单条正文按 500 码位窗口截断（`COMMENT_PREVIEW_CHARS`），尾部追加 `…（已截断，全文 N 字符；续读：GET /api/issues/<issueId>/comments/<commentId>?content_offset_chars=500）`。续读复用服务端既有评论窗口参数，不新增字段、不改存储。
- `--json` 不变：仍返回全量 `comments`，避免破坏脚本消费；限量只作用于文本渲染。`--mark-read` 语义不变（仍只推进游标）。
- 卡描述不截断（属另一张卡的范围）。

## 坑

- TS 弱类型：`selectRecentComments<T extends { is_new?: boolean }>` 会让 `IssueComment[]` 报「类型没有共同属性」（weak type 检测）。改为无约束泛型 + 内部 `(comment as { is_new?: unknown }).is_new === true` 探测。
- 截断必须按码位（`Array.from`），按 `string.length` 会在中文/emoji 的 UTF-16 代理对处切坏，续读偏移也随之错位。
- `kb claim` 回执同样收敛，但 `status / claimed_by / 工作空间路径` 等判定字段在评论之前输出、不受限量影响（测试锁定）。

## 验证

- `pnpm --filter @agentboard/cli exec vitest run` → 31 文件 / 412 例全过；`test/commentWindow.test.ts` 12 例覆盖选择、未读优先、截断、all 逐字一致、show/claim 文本与 CLI 入口接线。
- 真机（构建后）：`kb show 6549eb8d` → `评论（5/17）:` + `另有 12 条` + 2 处 `已截断`；`kb show 6549eb8d --comments 2` → `评论（2/17）:`；`--comments all` → 17 条、无「已截断/另有」；`--comments zero` → exit 1。
