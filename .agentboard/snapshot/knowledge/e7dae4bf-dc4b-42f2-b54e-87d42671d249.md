# done 自动提交：路径限定、失败可观测与权威正文校验

## 结论（照做即可）

1. **提交范围只认 `--scope`**：`kb done` 按声明路径提交；同文件里别人的 hunk 不会被内容级隔离，路径限定的边界就是「文件」。收尾前必须确认共享文件里没有他卡未提交内容，否则要么串卡提交、要么先把对方 hunk 排除。
2. **提交失败必须可感知**：done 响应新增 `git_commit = { status, reason, note, pending }`；`status='not-committed'` 且 `reason ∈ NO_BASELINE|COMMIT_FAILED|ZERO_HIT|PARALLEL_UNDECLARED` 时，CLI 把「未提交 + 原因 + 可照抄补救命令」写 stderr 并以 **1** 退出；`unavailable`（未装 git / 非仓库 / 仓库损坏）只警告、退出码 0。`--close` 遇到阻断性缺口会跳过 close。
3. **不再删 claim 基线**：租约过期清扫只清占用、保留 `issue_git_baseline`，原代次仍可 LEASE-GAP `done` 并自动提交。删基线会让「租约过期后 done」退化成无基线静默丢失。
4. **快照只读 DB 权威正文**：知识页快照渲染只用 `page.body_md`；落盘后回读、`git add` 后用 `git show :<path>` 复核暂存内容，逐字节（LF 归一）比对，发现 `<<<<<<<` / `=======` / `>>>>>>>` 立即失败并回滚。
5. **幂等重放要补写提交结果**：提交晚于业务事务，首次响应落账后用 `amendIdempotentResult` 把 `git_commit` 补写进幂等记录的嵌套结果，重放才逐字一致且不重复提交。

## 坑

- `git commit -- <path>` 提交的是该路径的**整份工作树内容**，不是部分 hunk；想只提交自己的改动，只能在 done 前控制文件内容（排除他卡 hunk），提交后再还原。
- `kb done` 的 `workspace_id` 缺失时不进幂等；带 `Idempotency-Key` 必须带 `workspace_id`。
- 全量 server 测试并发跑会因临时 git 仓库/目录回收互相干扰（EPERM、5s 超时），git 相关夹具单文件复跑才可信。
- PowerShell 5.1 不支持 `&&`，补救命令统一用 `;` 连接。

## 验收命令

- `pnpm --filter @agentboard/server test -- gitOnDone gitDetect claimLease knowledgePageCommit`（无基线、hook 失败、租约过期+脏树、快照污染）
- `pnpm --filter @agentboard/server test -- idempotency knowledgeNudge`（重放逐字一致）
- `pnpm --filter @agentboard/cli test`（done 退出码/`--close` 跳过/`unavailable` 放行）
