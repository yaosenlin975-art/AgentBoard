## 结构

ChatPanel 头部 ⋯ 菜单 →「会话设置」→ Modal 三节：人设 / 工具 / 技能。session 设置字段编辑后 500ms 防抖自动 PATCH，只发送本次修改字段；请求串行执行。组件卸载或 session 切换时 flush 待发载荷，使用旧 session id。

人设正文属于全局 persona 资源，继续通过 PATCH /api/personas/:id 显式保存；builtin 正文只读。

## 保存载荷

- 人设段：persona_id（选择「不使用人设」= null 解绑）与 persona_injection；各字段仅有修改时发送。
- 工具段：tool_policy 整对象 { approval_mode, allow[], deny[] }（PATCH 是整字段替换，必须带全）。
- 技能段：skill_policy 整对象 { allow[], deny[] }，原样保留读到的 mcp 键避免覆盖。

## 失败处理

保存失败时显示错误并回滚到最近已保存值。若同字段已有更新编辑/请求排队，则保留最新草稿，旧请求失败不得覆盖它；后续 PATCH 按编辑顺序执行。

## 读取当前值的坑

shared.Session 未声明 persona_id/tool_policy/skill_policy/persona_injection，但 GET /api/sessions 走 SELECT *，运行时四列存在；前端用本地 SessionPersonaFields 扩展类型读取即可，不必改服务端与 shared。
tool_policy / skill_policy 在库里是 JSON 字符串，必须 parse；解析失败回退空策略，不能整页崩。

## 能力置灰口径

GET /api/cli-capabilities?adapter= 只覆盖 codebuddy / codex / opencode / dsh；未知 CLI 不发请求、不置灰。
personaFlag=false 只置灰 flag 注入（file/off 不依赖 CLI flag）；探测失败只给提示不置灰（不猜能力）。
当前 CliCapabilities 没有 approve_mode_options 字段：approval_mode 四选取自前端枚举（inherit/plan/acceptEdits/bypass）。

## builtin 人设

builtin 正文只读：前端 textarea readOnly 且不渲染正文保存按钮；服务端 PATCH /api/personas/:id 也拒绝改写 builtin。导入/自定义人设可编辑正文。

## 测试口径

MSW stub /api/personas、/api/cli-capabilities、PATCH /api/sessions/:id，断言变更字段载荷、500 错误回滚、builtin 只读、能力置灰，以及 debounce 合并、卸载与切 session flush 和旧请求失败不覆盖最新草稿。
