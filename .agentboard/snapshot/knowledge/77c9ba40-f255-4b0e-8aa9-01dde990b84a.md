# 会话设置三节 UI 的契约与坑（P1-C）

## 结构
ChatPanel 头部 ⋯ 菜单 → 「会话设置」→ Modal(size=lg) 三节：人设 / 工具 / 技能。每节一个显式保存按钮，只 PATCH 本段字段；不做防抖自动保存（CR2-6 的卸载 flush 语义未落地前不引入半落盘状态）。

## 保存载荷
- 人设段：`persona_id`（选择「不使用人设」= null 解绑）+ `persona_injection`，仅相对基线有变化时才带。
- 工具段：`tool_policy` 整对象 `{ approval_mode, allow[], deny[] }`（PATCH 是整字段替换，必须带全）。
- 技能段：`skill_policy` 整对象 `{ allow[], deny[] }`，并原样保留读到的 `mcp` 键避免覆盖。
- 失败：用保存前基线回滚控件值并展示错误文案（不要用「当前值」回滚，会等于没回滚）。

## 读取当前值的坑
`shared.Session` 未声明 `persona_id/tool_policy/skill_policy/persona_injection`，但 `GET /api/sessions` 走 `SELECT *`，运行时四列是存在的；前端用本地 `SessionPersonaFields` 扩展类型读取即可，不必改服务端与 shared。
`tool_policy`/`skill_policy` 在库里是 JSON **字符串**，必须 parse；解析失败回退空策略，不能整页崩。

## 能力置灰口径
`GET /api/cli-capabilities?adapter=` 只覆盖 codebuddy / codex / opencode / dsh 四家；未知 CLI 不发请求、不置灰。
`personaFlag=false` 只置灰 flag 注入（file/off 不依赖 CLI flag）；探测失败只给提示不置灰（不猜能力）。
当前 CliCapabilities 没有 `approve_mode_options` 字段：approval_mode 四选取自前端枚举（inherit/plan/acceptEdits/bypass）。

## builtin 人设
builtin 正文只读：前端 textarea readOnly 且不渲染正文保存按钮；服务端 `PATCH /api/personas/:id` 也拒绝改写 builtin（双端一致）。导入/自定义人设可编辑正文。

## 测试口径
msw stub `/api/personas`、`/api/cli-capabilities`、`PATCH /api/sessions/:id`，断言载荷键集合只含本段；500 时断言错误文案且控件回滚到基线值；未知/已删人设渲染「未知人设 <id>」并可切空保存为 null。
