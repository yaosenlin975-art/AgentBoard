# 需求

账号行（AccountCard）内显示所属平台的余额/积分（按 unit 格式化）与窗口剩余；status≠ok、无数据、无额度来源时显示明确占位文案。

已落地（2026-11-08，与实际实现一致；差异：无）：

# 数据方案（不改服务端）

- 复用 `GET /api/managed-account-quotas` 与 `useQuotaSnapshot`（queryKey `managed-account-quotas`，staleTime 30s）。AccountCard 自取该 query：react-query 按 key 去重，面板左栏指标、右栏 QuotaDetail、各账号行共享同一次请求，不新增端点、不改聚合粒度、不改 QuotaResult 结构。
- 额度数据是平台级：同平台各账号行显示同源数据（各卡自取同一 query 天然满足）。
- app_id → QuotaSourceId 映射（QuotaCards.tsx 导出 `quotaSourceOfApp`）：workbuddy_desktop→workbuddy；minimax/trae/qoder_cn/zcode 同名；其余（commandcode、CLI 来源等）→ null。

# 展示实现（AccountCard 卡面下方一行，testid accounts-quota-<account.id>，data-status 供测试）

状态分支（互斥）：
1. 映射为 null（无额度来源平台）→「该平台无额度数据源」（data-status=unsupported）。
2. query pending →「额度读取中…」；query error →「额度读取失败」（data-status=error）。
3. 快照缺该来源（item undefined）→「暂时取不到额度」（data-status=missing）。
4. item.status ≠ ok → `quotaReasonView(item).text` 中文原因（data-status=error/unsupported）。
5. ok → 余额 + 全部窗口，` · ` 连接：余额 `quotaRowBalance`（CNY→¥xx.xx；积分/次→`xx 积分`/`xx.00 次`，toFixed(2)；0→「额度内」）；窗口 `quotaWindowsOf` 逐个 `${kindLabel} ${used}/${total}`（无 total/used 回落 `${pct}%`；`isWindowLimited` → `${kindLabel} 已限额`），与 QuotaRow 同口径；余额与窗口都空 →「正常」。

格式化全部复用 QuotaCards.tsx 既有导出（quotaRowBalance/quotaAmountText/quotaWindowsOf/quotaWindowKindLabel/windowBarWidth/isWindowLimited/quotaReasonView/QUOTA_UNKNOWN_REASON_LABEL），未新抄分支，未再抽公共函数（既有导出即共享点）。

# 验证

- 单测 apps/web/src/test/accountRowQuota.test.tsx 11 例全过（ok CNY/积分/次、多窗口、已限额、额度内、正常、error/unsupported 原因、缺来源、请求失败、无来源 app、面板同平台两卡同源）。
- 真机 5174：workbuddy 4 行同源「凭据已失效，请更新后重试」；trae「1782.83 积分 · 积分 7417/9200」；zcode「2000.00 次 · 5h 0/5 · 月 已限额」。

# 不做

不为 commandcode 等无源平台新接余额 API；不动 QuotaDetail/左栏指标；额度行不参与账号操作（切换/删除）的禁用逻辑。
