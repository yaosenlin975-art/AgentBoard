# 目标
账号行展示对应 managed account 的额度；共享同一平台的账号必须按各自凭据读取。左栏指标与 QuotaDetail 保持平台级聚合语义。

# 接口与数据流
复用 `GET /api/managed-account-quotas`，增加可选 `account_id` 查询参数。省略参数时保持原聚合响应、`QuotaSnapshot` 形状与现有调用行为。传入时校验 UUID，读取真实 managed account，并由其 `app_id` 映射唯一额度来源；响应继续使用既有 `QuotaSnapshot`，只加载该来源。

无效 UUID 返回参数校验错误；账号不存在返回 not found。平台不匹配、账号禁用或凭据缺失时，以现有额度状态/原因明确返回，不回退到同平台其它账号，也不使用 ZCode 本机 token。

# 凭据与缓存
账号模式只选择该 `account_id` 对应且启用、平台匹配的凭据。缓存与 in-flight 请求按 `source + account_id` 隔离。无 `account_id` 的平台聚合继续使用原 source 级缓存键。reset 同时清理所有账号与聚合缓存。

# Web 读取与展示
`useQuotaSnapshot(accountId?)` 复用现有 hook。全局指标与 QuotaDetail 不传 ID，并保留既有 query key 和请求；账号行传当前 `account.id`，query key 使用既有前缀加 ID，并在请求中传 `account_id`。

余额、积分单位和窗口格式化继续复用 QuotaCards 中现有工具。只有当对应账号真实返回了可计算百分比的用量与总量时显示百分比；缺少依据时显示未知状态，不以 0% 代替。

# 边界
不新增 HTTP 路由、shared types、数据库 schema 或迁移；不改变平台级聚合调用者及无关额度解析算法。
