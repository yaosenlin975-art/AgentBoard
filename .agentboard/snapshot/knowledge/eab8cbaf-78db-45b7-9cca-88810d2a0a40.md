# 目标
账号行显示当前 managed account 对应的额度；同平台多个账号按各自凭据读取。左栏指标与 QuotaDetail 继续使用平台级聚合数据。

# 接口与数据流
复用 `GET /api/managed-account-quotas`，增加可选 `account_id`。不传时保留既有聚合响应及 `QuotaSnapshot` 形状；传入时校验 UUID，读取 managed account 并由 `app_id` 映射唯一额度来源，只加载该来源。账号不存在返回 not found；不支持额度来源返回参数错误。

账号凭据必须匹配传入账号、来源平台且账号启用。账号缺失、平台不匹配、停用或凭据缺失时返回明确额度状态；不回退到其它账号或 ZCode 本机 token。

# 凭据与缓存
账号请求按 `source + account_id` 隔离 cache 与 in-flight；平台聚合继续使用 source 级缓存键。reset 清理全部账号与聚合缓存。

# Web 读取与展示
`useQuotaSnapshot(accountId?)` 复用现有 hook。全局指标与 QuotaDetail 不传 accountId，保持原 query key 和请求；账号行传当前 `account.id`，query key 使用聚合 key 前缀加 ID，并请求额度 GET 的 `account_id`。

余额与窗口继续复用现有格式化 helper。窗口有 `total` 和 `used` 时显示已用/总量；否则只有 `used_percent` 是有限数值时显示百分比。显式 `0` 是有效值；`null`、`undefined` 或非有限数值不转换成 `0%`。

# ZCode 编码配额映射
- `CREDIT_LIMIT` 为编码积分窗，`usage` 是总量、`currentValue` 是已用量、`remaining` 是剩余量。
- `unit=3, number=5` 映射 5 小时滚动窗；`unit=6` 映射 weekly 窗。
- `TIME_LIMIT` 保留为独立的 MCP 月度工具调用窗，不参与顶层余额选择；顶层余额优先 5 小时窗，其次 weekly。
- `TOKENS_LIMIT` 旧格式保留为编码额度窗，单位依据不足时使用中性“额度”。缺少总量、已用量与剩余量时不伪造 0。

# 边界
不新增 HTTP 路由、shared types、数据库 schema 或迁移；不改变平台级聚合调用者及无关额度解析算法。
