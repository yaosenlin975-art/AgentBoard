# MCP 待决策工具契约（MCP-D1：读取 / 停止信号 / 提问）

覆盖卡 `64acde61-a358-44c4-8bf0-10a3776363b6` 落地的 4 个 MCP 工具。D1 之后 MCP 主名 29、`tools/list` 总数 58（29 主名 + 29 `agentboard_*` alias）。

## 1. 工具与端点映射

| 工具 | 读/写 | 端点 | 关键入参 |
| --- | --- | --- | --- |
| `list_decisions` | read | `GET /api/decisions` | `workspace_id`（未绑定必填）、`issue_id`、`state=grace\|open\|answered\|withdrawn`、`stale`、`limit`(1–100，默认 50) |
| `get_decision` | read | `GET /api/decisions/:id` | `decision_id`（≥8 位前缀由服务端解析） |
| `stop_check` | read | `GET /api/issues/:id/stop` | `task_id` |
| `ask_decision` | write | `POST /api/issues/:id/ask` | `task_id`、`request_id`(uuid 幂等键)、`question`、`options`(≥2)、`context_md?`、`trigger?`、`grace_seconds?`(0–600)、`checkpoint?`、`on_expire?`、`fence?` |

- `ask_decision` 需要 `AGENTBOARD_AGENT_ID`，缺失返回 `AGENT_ID_REQUIRED`；`fence` 同时作为请求体字段与 `x-claim-fence` 头。
- 一律 `.strict()` 校验；拒绝未知参数，避免拼写错误被静默忽略。

## 2. 结果有界（防单次结果击穿 40k 上限）

- 列表只回摘要：`question` 窗口 2000 字符，不含 `context_md` / `checkpoint_json` / 完整 `answers`；`options` 仅保留 `id/ord/label/consequence/is_default`。
- 详情 `get_decision` 才回正文：`context_md` 窗口 12000、`checkpoint_json` 窗口 4000，并回 `answers` 全 revision 链与 `capabilities`。
- 截断时返回 `*_truncated` 与 `next_*_offset_chars`，客户端据此续读。

## 3. locked / stop_requested 语义

- 工具**不阻塞等待宽限**；`ask_decision` 只回 decision 快照。
- `locked = state === 'open'`，即 `grace_seconds=0` 时立即落锁（返回 `locked=true`、`stop_requested=true`），否则处于 `grace` 时 `locked=false`，轮询交给客户端（`get_decision` / `stop_check`）。
- 不新造状态机，完全沿用 ask-user 契约（默认宽限 180 秒，上限 600 秒）。

## 4. 工作区绑定

- `list_decisions` 未绑定 `AGENTBOARD_WORKSPACE_ID` 时必须显式传 `workspace_id`，否则 `WORKSPACE_REQUIRED`。
- `get_decision` / `ask_decision` 返回的 `decision.workspace_id` 与进程绑定的工作区不一致时抛 `WORKSPACE_BOUND`，阻断跨工作区读决策正文。

## 5. 错误码映射（服务端状态 → isError 安全码）

409 → `DECISION_ALREADY_OPEN` / `DECISION_ALREADY_ANSWERED` / `DECISION_REVISION_CONFLICT` / `DECISION_NOT_ACTIVE` / `DECISION_WITHDRAWN` / `DECISION_NOT_GRACE` / `ISSUE_STATUS_NOT_RUNNING`；400 → `ASK_TOO_FEW_OPTIONS` / `INVALID_GRACE`；404 → `DECISION_NOT_FOUND` / `TASK_NOT_FOUND`。文本只回安全文案，不回服务端原文。

## 6. 真实调通方法（可复用的 MCP 验收通道）

1. 建一张临时卡并 claim（占用的 agent 名要与 `AGENTBOARD_AGENT_ID` 一致）。
2. 直接 `spawn` 构建产物 `apps/mcp/dist/index.js`，走 `initialize` → `tools/call`；参数含双引号时不要经 PowerShell 命令行传，改为写入 calls.json 文件（PS 5.1 会吞引号导致 `JSON.parse` 失败）。
3. `ask_decision` 用 `grace_seconds=0` 断言 `isError` 为空且 `structuredContent.data.locked=true`。
4. 清理：先 `kb decision withdraw <decision_id>` 撤回决策，再 `kb delete-issue <临时卡> --yes`。
   注意：claim 代次变化后 `kb release` 会报「占用代次已过期」失败，但 `delete-issue` 仍可删除；不先 withdraw 会在卡上留下 open 决策锁（后续 claim 被决策锁挡住）。

## 7. 坑

- `MCP_TOOL_RESULT_LIMIT = 40_000`：详情工具必须做窗口截断，否则大 checkpoint 直接超限。
- alias 在注册器里统一产出，新增工具默认两倍计数；更新 `tools/list` 断言与 README 工具数时按 2× 主名核对。
