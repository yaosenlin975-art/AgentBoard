桌面壳（Tauri v2，`.decorations(false)` 全自绘）顶栏的平台自适应契约。

## 平台判定

`apps/web/src/components/shell/WindowTitleBar.tsx` 导出纯函数 `detectPlatform(): 'macos' | 'windows'`，取值优先级：

1. `window.__AB_PLATFORM_OVERRIDE__` —— 壳注入（`platform_init_script()`，`initialization_script` 在任何页面脚本前执行；值由 `cfg!(target_os)` 在编译期决定）
2. `?platform=macos|windows` —— 开发预览，仅在 `import.meta.env.DEV` 求值；正式构建被常量折叠，产物内无该分支
3. `navigator.userAgentData?.platform`（Chromium 系可用）
4. `navigator.userAgent` 正则 `/Macintosh|Mac OS X/i` → macos；`/Windows/i` → windows
5. 兜底 `'windows'`（保持历史行为）

取值归一化：`macos|mac` → macos，`windows|win` → windows，其余（含空串、`linux`）视为未识别并继续降级。不新增运行时依赖（`@tauri-apps/plugin-os` 未安装，也不引入）。

## 分支形态

| 分支 | 控制区位置 | 顺序 | 元素 |
| --- | --- | --- | --- |
| windows | 右侧 | minimize → maximize → close | `h-8 w-11` 方形按钮，`CONTROL_BASE` 不变 |
| macos | 左侧 | close → minimize → maximize | 12×12 圆点组，`pl-[13px]`、`gap-2`（8px） |

mac 圆点色值：关 `#FF5F57` / 最小化 `#FEBC2E` / 最大化 `#28C840`。符号（× − +）默认 `opacity-0`，`group-hover/dots` 才到 `opacity-100`；描边 `rgba(0,0,0,0.55)`。标题（A 图标 + 文字）距圆点组 12px（`ml-3`），拖拽填充区在两分支都位于标题与控制区之间，`data-tauri-drag-region="deep"` 留在 `<header>` 上。

窗口命令语义不变：`plugin:window|close`（壳侧拦截 CloseRequested → 隐藏到托盘）、`plugin:window|minimize`、`plugin:window|toggle_maximize`、`is_maximized`。mac 分支没有右侧控制区，因此 `header` 不再带 `pl-3`。

## 验证方法（坑）

- **Windows 零差异**只能靠结构化快照对比：同一份 CDP 脚本分别对「改动前工作树」与「改动后工作树」抓 `header.outerHTML`（剔除新增的 `data-platform` 标记属性）+ 每个节点的 20 项计算样式 + 控件盒子，再做递归 diff。截图对比不可靠（子像素/字体渲染抖动）；只在视觉上「看着一样」不算证据。
- **合成 hover** 必须在真实浏览器里用 `Input.dispatchMouseEvent` 触发，jsdom 下 `:hover` 不生效，没法断言符号从不可见变可见；单测只断言类名契约（`opacity-0` + `group-hover/dots:opacity-100`）。
- **Tauri 运行时垫片**：`window.__TAURI_INTERNALS__ = { invoke, metadata: { currentWindow: { label: 'main' } } }` 即可让顶栏在普通浏览器里渲染，`invoke` 收面命令名做断言。
- **DEV 预览参数与 override 的顺序**：override 先于 `?platform=`，否则壳注入的真值会被 URL 覆盖；prod 产物中 `?platform=macos` 必须仍渲染 windows。
