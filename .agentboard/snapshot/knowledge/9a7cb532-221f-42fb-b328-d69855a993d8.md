## 切换（ACC-SW-MAX，2026-11-07 真机实证补充）

minimax 桌面切换已落地（commit 38a4ab8，卡 8b120daa）：start 装配（spawn detached）+ refresh_token 同写 + 能力表/gate 按探测置 true。真机单活跃账号 capture+switch 同号切换 succeeded。追加实证坑：

1. **verify 不能启动后立即读**：客户端启动会归一化重写 `auth.json`（字节变、token 一般不变）。启动后立即读会读到中间态；回滚写盘再与客户端启动写盘**竞态**，会把登录态重置 `auth-state.json: status=anonymous`。修复：verify 在窗口内轮询（默认 20s）到目标 token 才算落地；回滚前必须先 `stop` 客户端。
2. **signin/status 探针必须带 `timezone_id`**：不带时服务端恒回 HTTP 200 + `base_resp.status_code=1406010011`（invalid timezone_id），有效凭据也拿不到结果。带 `timezone_id=Asia/Shanghai`（query 参数）后：有效凭据 200/ok，无效凭据 HTTP 401。该响应**不含任何身份字段**（只有 scene/days），uid 只能走 ACC-FIX-6 同链兜底：JWT sub → 响应字段 → `sha256(token).hex[:16]`。200 但 `base_resp.status_code != 0` 也要按服务端拒认处理。
3. **客户端会自轮换 access_token**：客户端启动/使用会刷新 token 并使 vault 里捕获的凭据服务端失效（401）。capture 与 switch 间隔一久（中间客户端跑过），切换必然在 S5 被服务端拒认 → 安全回滚（回滚后 auth.json 字节级一致）。待办：switch 前用本机快照/refresh_token 自愈凭据，再做切换。
4. **records 键不可从凭据推导**：真实键形 `com.minimax.mcode.oauth.prod.cn\x00<43字符摘要>`；sha256(accessToken/refreshToken/clientId/uid/generation) 全不匹配摘要。实现：优先复用目标账号被捕获快照里的记录键并收敛为单条记录；快照缺失沿用源键（假设单记录原地覆盖不产生并存键）。跨账号互切客户端实际读哪条仍未双号验证。
5. 真机单号验证口径：capture-current → 立即 switchAccount(同号) → succeeded（终态 verify）；能力表 `switch:true / switch_reason_code:OK` 由真探测推导（gate 与能力矩阵同口径，accountRoutes requireProvider 改异步带探测）。
