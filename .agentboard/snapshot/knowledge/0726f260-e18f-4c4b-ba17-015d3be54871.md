## 是什么

知识页正文平时只在库里（`knowledge_page.body_md`），git 里看不到。BORROW-5.1 在每次 **create / revise / archive（含 restore）** 之后，额外把该页写一份可读快照到：

```
<工作区>/.agentboard/snapshot/knowledge/<page_id>.md
```

并**只提交这一个路径**。库仍是唯一事实源，快照是派生物：删掉文件不影响数据，提交失败也不影响知识页写入。

## 文件格式

front matter 字段顺序固定（同一 revision 重复渲染逐字节一致，避免无意义 diff）：

```
---
id: <page id>
slug: <slug>
title: <title>
scope: workspace
revision: <n>
status: active|archived
updated_at: <ISO8601>
---

<正文>
```

`status` 必须写：归档页的快照若仍标 active，会被误读成活跃内容。

## 提交口径

- `git add -A -- <path>` + `git commit -m "knowledge(<slug>): r<n> <title>" -- <path>`：路径限定，绝不整索引提交，避免把并行卡已暂存的改动卷进来。
- 内容未变化（例如只改了不进快照的字段）时不造空提交：返回 `committed=true`，`commit` 指向已有 HEAD。
- 仓库没配 `user.name`/`user.email` 时补 `-c user.name=AgentBoard -c user.email=agentboard@local`（与 GIT-ON-DONE 同口径，不覆盖已有署名）。

## 状态规则

| 动作 | 文件处理 |
| --- | --- |
| create / revise / restore | 重写同一路径，front matter 的 `status` 跟随库 |
| archive | 重写同一路径，`status: archived`，文件保留（可 restore） |
| delete（软删） | 删除文件并提交删除；库已视该页不存在，留可读正文等于泄漏已删内容 |
| 快照不存在时 delete | 不造空提交，`reason` 说明「快照文件不存在，无需提交删除」 |
| `/pages/import` 批量导入 | **不接线**：一次请求写多页，与「只含该页路径」冲突 |

## 失败语义（验收 3「失败回滚不留半提交」）

- 写文件或 git 失败：新建的文件删掉、已有的还原到改动前内容，并尽力 `git reset -q HEAD -- <path>` 清掉暂存，返回 `committed=false` + `reason`。
- **不回滚知识页**：库是事实源，提交失败只在响应 `page_commit.reason` 里告知，不让派生物失败变成数据写失败。
- 软删是例外：文件先删、再提交删除；git 失败也不还原文件（删除态优先），`reason` 说明原因。

## 接线与验证

- 三个写端点（`POST /pages`、`PUT /pages/:id`、`POST /pages/:id/actions`）响应新增 `page_commit: { path, relative_path, committed, commit, reason } | null`；`scope=common` 或无对应工作区时为 `null`（只做工作区页）。
- 单测 + 真实 app（`createApp` + supertest）覆盖 create → revise → archive → restore → delete 五步：每步 `git show --name-only --format=HEAD` 都只含该页路径，删除后工作树 `git status --porcelain` 为空。

## 坑

- `PUT /pages/:id` 的 zod schema 是 strict，**不收 `slug`**：复用创建 payload 做修订会 400，需先摘掉 `slug`。
- 创建端点自 KB-CR-1 起 `domain` 必填，测试 payload 漏掉会 400。
- 该文件曾被他人在飞改动写入 UTF-8 BOM，导致全局 `check-bom` 红；写仓库文件一律走无 BOM 路径（编辑器 / `fs.writeFileSync` / `UTF8Encoding($false)`）。
- 工作区不是 git 仓库或仓库不健康时，功能降级为「只写文件不提交」，原因在 `page_commit.reason`，不阻断知识页写入。
