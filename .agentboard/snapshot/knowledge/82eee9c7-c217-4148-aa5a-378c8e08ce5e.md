# Express 静态托管的 dotfiles 语义：SPA 入口必须显式 allow，静态目录不要全局放宽

## 结论

1. `res.sendFile()` 与 `express.static()` 内部的 send/serve-static 都有 `dotfiles` 选项，默认值 `'ignore'`。
2. `'ignore'` 的判定对象是**目标绝对路径里的每一段**，不只看 URL 里的文件名。只要任一段以 `.` 开头（`.tmp`、`.local`、`.hidden-env`、`.config`），该文件就被判为隐藏文件 → `NotFoundError: Not Found`。
3. 因此「webDist 落在含点开头的父目录下」会让 SPA 入口整体失效，而 URL 里根本没有点。
4. 修复口径：**只对 SPA 入口这一个文件显式 `{ dotfiles: 'allow' }`**；`express.static(webDist)` 保持默认，隐藏文件仍不可下载。

## 为什么不能全局放宽

`express.static(webDist, { dotfiles: 'allow' })` 会把 `webDist` 下所有 `.env`、`.git`、`.map`、备份文件一起暴露。打包产物目录里通常混有 sourcemap、`.DS_Store`、`.gitignore`、`.vite` 缓存，全局放宽等于把它们变成可下载资源。只放宽 `index.html` 这一个显式路径，暴露面不增加。

## 判定方法（三步定位）

现象：`GET /` 404 但 `GET /index.html` 200 —— 首页空白，深链路由报 500。

1. **确认路径推导本身没错**：打印 `join(webDist, 'index.html')`，并 `existsSync` 为 true。若为 false，是路径推导问题，不是 dotfiles。
2. **确认路径里有以点开头的段**：对该绝对路径按分隔符切段，检查是否任一段以 `.` 开头。
3. **确认是 send 层而不是自己的代码**：在 sendFile 回调里打印 `err.name / err.message`；`NotFoundError: Not Found` 且文件确实存在，就是 send 的 dotfiles 判定。

对照实验：同一份构建产物复制到不含点段的目录再跑一次，`GET /` 立即 200，即可锁定 dotfiles。

## 复现路径（AgentBoard 实测）

修复前（`apps/server/dist` 未打补丁，webDist 指向 `<tmp>/.hidden-env/.tmp/web/dist`）：

```
GET /            => 404  text/plain  "index.html missing"
GET /board/xyz   => 500  application/json（fallback 的 err 交 errorHandler）
GET /index.html  => 200  text/html
```

修复后同一组请求：`/` → 200 html，`/board/xyz` → 200 html，`/index.html` → 200 html。

不含点段的路径（`<tmp>/app/apps/web/dist`）修复前后都是 200 —— 这正是「同二进制、只改路径」的对照。

## 代码位置（apps/server/src/index.ts）

静态托管块内两处：

- `app.get('/', ...)` —— 根路径显式回 `index.html`
- SPA fallback（`app.use((req,res,next) => ...)`）—— 非 `/api` 的 GET 回 `index.html`

两处都必须是：

```ts
res.sendFile(join(webDist, 'index.html'), { dotfiles: 'allow' }, (err) => { /* ... */ });
```

遗漏任一处，表现不同：漏根路径 → `/` 404 而深路由正常；漏 fallback → `/` 正常而深路由 500。**两处必须一起改**。

## 统一判定清单（新增静态托管逻辑时照此检查）

- 用 `res.sendFile` 返回固定文件：显式传 `{ dotfiles: 'allow' }`，否则部署路径带点段就 404。
- 用 `express.static` 返回目录：保持默认 `'ignore'`，不要为了修首页把目录放宽。
- 新增 `sendFile` 调用点前先 `grep -n "sendFile" apps/server/src` 对照既有写法（附件、图片等路由已用 `{ dotfiles: 'allow' }`）。
- 测试要用**含点开头的父目录**构造 webDist，否则在无点段的 CI 沙箱里永远测不出来。
