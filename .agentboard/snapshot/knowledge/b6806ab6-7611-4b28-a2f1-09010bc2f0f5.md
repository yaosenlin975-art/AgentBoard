# 第二轮审查：可复用结论（2026-11-10）

## 1. Web fetch 超时：jsdom 下传 AbortSignal 会静默挂死

- 生产目标：超时必须同时 `controller.abort()`，否则浏览器同源 HTTP/1.1 的 6 条连接会被挂死请求占满，用户点「重试」也拿不到连接。
- 坑：在 jsdom + MSW 的测试环境里，把页面 realm 的 `AbortSignal` 传给被 MSW 接管的 `fetch`，**不抛 TypeError，而是请求永不回包**（2026-11-10 实测 701 个用例超时；此前知识页记录的是「抛 TypeError」，现象已变）。
- 定案：`apps/web/src/api/client.ts` 用 `import.meta.env.MODE !== 'test'` 分流——浏览器产物传 signal 走真中断，测试环境保持竞速超时。测试用 `expect(init.signal).toBeUndefined()` 锁住回落分支；浏览器分支由构建期常量决定，未做自动化验证。
- 另一处顺序要求：定时器里必须**先 reject ApiError，再 abort**；先 abort 会让 `request` 以 AbortError 抢先赢下 `Promise.race`，超时错误被覆盖成 DOMException。

## 2. 语音模型就绪判定：缓存必须带 mtime

- `voiceRoutes` 的 SSE 每 250ms 调一次 `voiceModelProgress`，而 `statusOf` 原本对每个已落盘文件 `readFileSync` 整块算 sha256；200MB 模型 = 每秒数百 MB 读盘 + 主线程哈希。
- 定案：`(size, mtimeMs)` 进程内缓存 + `meta.json` 存在且各文件 size 与清单一致时直接信任；只有一个文件的 mtime 变了（下载完成改名）才重算。
- 实测（120MB 单文件）：首次 90ms，第二次 0.2ms；`GET /api/voice/models` 的重复请求不再读盘。
- 注意：缓存键是绝对路径，删模型时要按 `dir + sep` 前缀清理，不能只清单文件。

## 3. SQLite 约束错误映射：TRIGGER 不能一刀切

- `SQLITE_CONSTRAINT_*` 前缀归并成 400 只对 CHECK/UNIQUE/FK/NOT NULL/PK 成立。
- `SQLITE_CONSTRAINT_TRIGGER` 是 schema 里 `RAISE(ABORT)` 主动拒绝，必须按消息分流：
  - `issue parent workspace mismatch` / `issue dependency workspace mismatch` → 400 `WORKSPACE_MISMATCH`
  - `issue parent cycle` / `issue dependency cycle` → 409 `DEPENDENCY_CYCLE`
  - `Knowledge history is immutable` → 500（服务端不变量）
  - 其余 → 500，只记类别不回显 SQL
- 事实纠正：附件相关触发器只有 INSERT/DELETE，没有 `RAISE(ABORT)`，不能拿它当 TRIGGER 例外存在的理由。

## 4. 快照清单必须校验路径包含

- `traeSnapshot` 的 manifest 来自加密 vault，正常不可注入；但恢复路径直接 `fs.remove` 清单里的相对路径，清单损坏/被改写时 `../` 可逃出 dataDir。解析阶段统一 `assertSafeSnapshotPath`（禁 `..`、绝对路径、盘符、NUL），拼接函数复用同一校验。

## 5. 门禁与临时目录

- `scripts/check-bom.mjs` 的 `SKIP_DIRS` 必须包含 QA 临时目录（`.qa-temp`），否则界面验证留下的草稿会让 `pnpm build` / `apps/web prebuild` 直接失败。
- 派工模板第 5 条与技能口径冲突（要求 `handoff-<uuid>` slug）会让每个被派工 agent 批量建违规知识页；模板已改为「有可复用结论才写/更新领域知识页，否则 notes 声明原因」。
