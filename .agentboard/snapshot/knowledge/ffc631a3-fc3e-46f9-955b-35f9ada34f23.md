# CLI 输出体积可观测（KB_METRICS）

## 结论

- 在 `io.ts` 新增 `meterIo(inner)`：只统计最终写 stdout 那一层的 UTF-8 字节与行数，跨 write 分片不重复计行；stderr 原样透传不计数。
- `KB_METRICS=1` 时，`main` 在 `finally` 里向 `io.writeErr` 追加一行 `[kb] cmd=<顶层命令> out=<n>B lines=<m>`；未设或设 `0` 时不输出任何字节。
- cmd 由 commander 的 `preAction` 回溯顶层子命令得到，未进 action 时为 `-`。

## 真机基线（同一张待验收卡 a4e08873）

- `kb show`：7321B / 76 行
- `kb show --comments all`：51981B / 433 行 → OPT-04 限量省 44660B（约 -85.9%）
- `kb list-tasks`：148687B / 831 行
- `kb knowledge search`：1873B / 17 行
- `kb claim <不存在 id>`：0B / 0 行、exit 1（未写看板）

## 约束

- 只走 stderr，`--json` 的 stdout 仍可直接 `JSON.parse`（实测 57328B 可解析）。
- 退出码与 stdout 逐字节不变：开/关两次 `kb show` stdout sha256 相同，关时 stderr 0B。
- 不落库、不上报服务端、不默认开启。

## 用途

- 回答「一次调用让 agent 读了多少」；OPT-04 的评论限量收益可直接用 `show` vs `show --comments all` 复算。
