# kb claim / kb done 状态核对取材（OPT-08）

## 结论

- `kb claim` 与 `kb done` 的文本输出本来就带 `状态:` 行，`done` 额外带 `占用者:`（释放后为「（未占用）」）；`--json` 保留服务端原字段 `status` / `claimed_by`。**完成后的状态核对直接读这条命令输出即可，不必再手动 `kb show` 一次。**
- 核对步骤没有被取消：输出缺失/不可解析/没有状态字段，或状态与预期不符时，仍必须 `kb show <id> --json` 复核，并以 `status` 为准按未完成处理。

## 行为硬化（状态不符即报错）

- claim：POST 返回后若 `status !== '进行中'`，直接 `throw`（退出码 1），不打印「领取成功」。避免「命令显示成功、卡片状态没变」的假成功。
- done：POST 返回后若 `status !== '待验收'`，直接 `throw`（退出码 1），不打印「已完成」，本地 fence 不清除（等复核后再处置）。
- 只校验 status，不对 `claimed_by` 做值相等校验：服务端可能对 agent 名做归一化（如加前缀），强等会误伤；占用者释放后的展示由输出行直接给出。
