# WorkBuddy 协议账号的逐账号切换能力与本机快照补齐

## 目标
逐账号展示真实可用的桌面切换能力。完整方案允许用户在 WorkBuddy 客户端手动登录目标账号后，将当前本机原生登录态快照补到原协议账号行，保留账号 ID、名称及签到/操作历史。OneID 凭据不得直接伪造成桌面登录文件；身份无法验证时不写入。

## 已核实材料与未知项
2026-11-09 本机两条 WorkBuddy 账号 metadata：600f9d7c 是当前安装实例的原生行，有 snapshot，身份与当前客户端一致；88ab0992 是 protocol 行，无 snapshot/hint，有签到凭据，当前客户端身份不匹配。完整 identity hash、vault 引用和凭据内容未读取。用户本轮反馈仍显示“目标账号实例不匹配”；前序截图同样显示该错误，并非切换成功证明。

当前 OneID 流程把 access token 存为签到凭据，账号 client_instance_id=protocol，identity_hash=sha256(app_id + NUL + uid)。原生捕获读取当前 .info UID 与 skeleton，身份散列为 sha256(uid)，校验 v2 加密格式后把完整文件快照放入 vault。切换要求账号 instance 与本机一致且 snapshot 存在。未实测目标 OneID UID 与手动登录后的原生 UID 对应关系；不得以显示名或未经服务端校验的 JWT 声明替代。

## 方案

### A（推荐）：逐账号能力 + 原记录快照补齐
账号列表增加不含敏感路径/引用的 switch_available 布尔值及 switch_reason_code。只有当前安装实例存在有效 snapshot 的 WorkBuddy 行显示可切换。无 snapshot 的协议账号显示“先在 WorkBuddy 手动登录，再补齐本机登录态”。沿用现有 capture-current 入口，增加可选 target_account_id。

用户手动登录目标账号并明确选择原协议行后，服务端只读本机原生 UID，以 sha256(app_id + NUL + native_uid) 与原行 OneID identity_hash 比对。身份匹配后使用现有 native snapshot 与 SecretVault 机制创建当前安装快照；按原 scope 解开既有签到凭据并按 native scope 重新保护。SQLite 事务更新原行的 instance、canonical identity hash、hint、snapshot 与签到凭据引用；原 ID、名称、启用态和历史行不变。事务冲突或 vault 步骤失败时保留原行和原凭据并删除本次暂存密文；已有 native 同身份行触发唯一约束时明确拒绝，不自动合并或删历史。身份比对不通过时拒绝补齐。切换/回滚继续使用现有安全骨架，不新增数据库列或 HTTP 端点。

未知：OneID 的 oneidAccountId 是否等于客户端 .info 的 account.uid。没有真实目标登录样本前不能声称 A 可完成；若摘要比对失败，原记录保持不变并提示无法验证身份。

### B：仅纠正逐账号可用性
同样增加 switch_available 与 switch_reason_code，并隐藏无 snapshot 或实例不匹配行的切换按钮；协议行继续支持已有签到/额度功能，不添加原生快照补齐。此方案不能让该协议账号真正切换。

### GitHub 方案对比
- [Danjack85/workbuddy-switch v2.0.0](https://github.com/Danjack85/workbuddy-switch/releases/tag/v2.0.0)，短 commit eb8e412，MIT。profiles.py 的 capture_current / adopt_accounts_from_auth 复用用户已登录后的本地 auth 文件；switcher.py 说明凭据不匹配时仍须用户登录。流程概念匹配 A，但项目围绕本地 Python/Tauri 档案与数据同步，README 针对 WorkBuddy AI 的独立 auth 文件，当前加密 v2 格式兼容性未验证；整体移植成本高，不直接移植。
- [Faide-cyber/dsh-workbuddy v1.0.23](https://github.com/Faide-cyber/dsh-workbuddy)，MIT。使用 OneID 插件授权并保存插件私有凭据，明确把桌面 auth 文件作为只读输入；支持插件请求账号切换，不切换桌面客户端。Node 22 / DSH 插件运行环境与本项目不兼容，不解决快照桥接，不复用。

推荐不引入外部库，复用本项目已有的 capture、SecretVault 和切换/回滚流程；候选仓库均未提供可验证的 OneID token 到 WorkBuddy v2 桌面 envelope 转换实现。候选只读检查，未在本机运行或验证。

## 接口与数据约束
沿用 GET /api/managed-accounts 增加逐行安全能力投影；扩展现有 POST /api/managed-accounts/:app/capture-current，A 可传 target_account_id。shared PublicManagedAccount 只新增 switch_available 与 switch_reason_code，不返回 snapshot_ref、credential_ref、文件路径或 token。优先原 managed_account 行原子更新，不加列、不换 ID；vault 新引用先暂存，提交成功后清理旧引用。

## 验收
A：临时 DB + fake vault 覆盖身份不符、vault 失败、唯一冲突与事务失败；所有失败保留原行/原引用；成功保留 account ID、名称、启用态及签到/操作历史，并可按 native scope 解密；用户手动登录目标后由 Terra 在测试页验证逐账号提示、捕获原记录、切换到目标及切回原账号，登录身份逐项一致。无目标登录样本时 A 不能标记为已验。

B：无 snapshot/实例不符行不显示可点切换按钮，原因与补齐方式清楚；已有 native WorkBuddy 切换回归通过。

## 范围
只覆盖 WorkBuddy 协议账号与原生快照关联；不改其他 provider，不新增登录协议，不写未验证 envelope，不自动合并账号或清理历史数据。A/B 由用户在任务卡待决中选择；选择后再拆跨端实现任务与验收。

## 实现落点（ACC-SW-VALID-A1，2026-11-09，服务端已落地）
- 列表投影：`apps/server/src/api/accountRoutes.ts` 的 GET /managed-accounts 逐行计算 `switch_available` / `switch_reason_code`；WorkBuddy 判定顺序 `PROVIDER_UNAVAILABLE` → `TARGET_INSTANCE_MISMATCH`（client_instance_id 非当前安装实例）→ `SNAPSHOT_MISSING`（无 client_snapshot_ref）。`publicManagedAccount` 仍不返回任何 ref。
- 补齐入口：同文件 capture-current 的 strict body 增加 `target_account_id`（UUID）；非 WorkBuddy 传该字段 400，目标不存在 404。
- 身份比对：`apps/server/src/services/accounts/workbuddyDesktopProvider.ts` 新增 `requireV2Credentials()`，只在内存返回原生 uid；协议行匹配用 `sha256(app_id + NUL + uid)` 对比原行 `identity_hash`，不一致 409 `TARGET_IDENTITY_MISMATCH`，本次快照密文立即删除、原行不动。
- 就地补齐：匹配后在 `db.transaction` 内 UPDATE 原行（client_instance_id / identity_hash / identity_hint / client_snapshot_ref / checkin_credential_ref / updated_at），保留 id、display_name、enabled 与签到历史；同 app+实例+原生身份已有别的行 → `ACCOUNT_EXISTS` 拒绝合并。
- 签到凭据：优先本次捕获 token；本机取不到时按原 scope（protocol 实例 + 协议 identity_hash）解密旧凭据，按 native scope 重封装；仍不可得 → `CHECKIN_CREDENTIAL_UNAVAILABLE`。
- 失败语义：vault 或事务任一步失败删除本次新密文并保留原行/原引用；单测覆盖匹配成功、身份不符、唯一冲突、vault 失败回滚、token 缺失回退重封装、列表三种原因码。
- 未验项：仍未实测 OneID `oneidAccountId` 与客户端 `.info` `account.uid` 是否相等；协议行实际补齐/切换需用户手动登录目标后由 Terra 在测试页验证，服务端单测不能替代。前端按钮可见性由子卡 A2 落地。

## 实现落点（ACC-SW-VALID-A2，2026-11-09，前端已落地）
- 切换按钮条件：`apps/web/src/components/settings/AccountCard.tsx` 除平台能力 `capability.switch` 与 `is_current` 外，新增 `account.switch_available !== false`；`switch_available=false` 时直接不渲染可点按钮，避免“点了才吃 409”。
- 原因行：`switch_available=false` 且非当前账号时渲染 `accounts-switch-unavailable-<id>`，文案走 `accountCapabilities.reasonLabel(switch_reason_code)`；`TARGET_INSTANCE_MISMATCH` 额外附「先在 WorkBuddy 客户端手动登录该账号，再点补齐」的指引。
- 补齐入口：同文件 `adoptMutation` → `POST /api/managed-accounts/:app/capture-current`，body `{ target_account_id: account.id }`；成功后失效重拉列表，失败按 `reasonCodeOf` 渲染 `accounts-adopt-error-<id>`（`data-code` 保留裸码，主文案中文）。
- 前端原先没有 capture-current 入口（AccountsPanel 的捕获按钮已按 ACC-UI-PRUNE 移除），因此补齐能力必须由账号行的新按钮承接，否则服务端 target_account_id 能力在 UI 不可达。
- 测试：`apps/web/src/test/accountCardSwitchAvailability.test.tsx` 覆盖三条——不可切换行无切换按钮且有原因/补齐按钮、可切换行按钮不变、点补齐发对 body 且 409 `TARGET_IDENTITY_MISMATCH` 显示中文并带 data-code。
- 未验项：真机「手动登录目标账号 → 点补齐 → 切换 → 切回」仍需由用户在测试页验证；组件测试不能替代。
