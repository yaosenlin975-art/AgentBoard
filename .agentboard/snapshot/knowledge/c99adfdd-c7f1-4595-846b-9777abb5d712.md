# routes.ts 按域拆分：纯搬迁模式与验证套路（CR-10）

## 搬迁模式
- 域文件放 `apps/server/src/api/routes/<域>Routes.ts`，导出 `create<域>Router(deps)` 工厂，沿用 api/ 下既有域文件惯例（deps 接口 + 工厂，先例：accountRoutes / issuePayloadRoutes）。
- STORE-1/4a 解析闭包（workspaceResolverDeps / requireWorkspaceRow / dbForWorkspace / locateIssueRouted / requireIssueRouted / locateSessionRouted / resolveRequestDb / effectiveWorkspace / mutation / currentDbPath / attachmentsDirOf）是 routes.ts `createRouter` 装配期闭包、多域共用：留在 routes.ts，经 deps 接口注入域工厂，不在域内重建。
- 单域专属闭包随域迁入：settings 的 resolveDbPathSource/triggerRestart（deps 注入 dbPathSource/restart）、systemMisc 的 pick-folder 模块级并发守卫。
- parseBody / requireWorkspaceParam / requireExistingWorkspace 等小 helper 随域本地复制（api/ 既有先例：accountRoutes 自带 parseBody）；提取公共 helper 受本轮卡面文件白名单限制（只许改 routes.ts + 新建 routes/<域>Routes.ts），留作可选收敛项。
- 仅类型位置引用的 repo 函数（`ReturnType<typeof getIssue>` / `typeof getSession` 作 locate* 闭包的载荷类型）在 routes.ts 保留 value import，即使域端点已全部迁出。

## 顺序约束（语义保持的关键）
- CR-10a（issues）：DEC-WIRE——决策路由必须在 /issues/:id 中间件之前注册。整域单点挂载时，`router.use(createIssueRouter(...))` 放在 `createDecisionRouter` 之后；决策路由无 2 段 `/issues/*` 路径，draft 从决策路由前挪到后无路径冲突。域内相对顺序保持：draft 先于 /issues/:id 中间件（'draft' 不被当成卡 id）；/issues/counts 先于 GET /issues/:id。
- CR-10b（workspaces）：整域挂载点取原 per-workspace changelog 子挂载处（per-workspace changelog/statuses 子挂载随域搬入域工厂）；该位置此前无任何路由含 /workspaces/* 业务路径，决策路由的 /workspaces/:workspaceId/decisions/* 在其后注册且本域无 'decisions' 字面路径，前后无冲突。express.raw（附件上传）随域搬迁。
- CR-10c（sessions）：整域挂载点取原 sessions 群起点（clis 之后），域内端点原本连续，单点挂载零顺序影响；fileAttachmentPromptBlock（导出函数）随域搬迁并保持导出。
- CR-10d（settings + system 杂域）：settings 挂载在原 settings 群位置；systemMisc 挂载在原 /version 端点位置（此前无路由含 /version、/skills、/clis、/system/* 业务路径；/system/restart 属 ../systemRoutes.ts 且挂载更晚，两文件无同路径）。statuses 聚合 / archived changelog / voice / knowledge 挂载留在 routes.ts（knowledge 挂载选项闭包依赖装配上下文）。
- 无前缀 `router.use(子路由)` 下 req.baseUrl/req.path 与原注册同形：幂等 resource（baseUrl+path）与 /issues/:id 中间件内的 req.path 相对化（挂载前缀 '/issues/:id' 剥离出 '/claim' 等）均不受影响。

## 验证套路（每域同款）
- tsc：src 零错误。test/ 基线报错不扩大的证明法：`git stash push -- apps/server/src/api/routes.ts` 前后各跑一次 tsc，报错清单 diff 逐字一致（CR-10a/10b/10c/10d 实测 118=118）。
- vitest 全量：`cd apps/server && npx vitest run --maxWorkers=4`（四卡均取绿证：167 文件 / 1616 用例全过）。
- 端点对比（不起 live 实例）：一次性探针测试（createApp + supertest + git init 的临时空间目录），stash 前后各跑一遍，输出归一化 JSON 后 diff 逐字一致（CR-10a：issues 域 16 探针点；CR-10b：workspaces 域 14 探针点；CR-10c：sessions 域 14 探针点；CR-10d：version+杂域 12 探针点）。
- 归一化清单（防伪 diff）：uuid 与内嵌 uuid、13 位毫秒时间戳（数字与字符串两种形态）、ISO 时间戳（exported_at）、pid / db_path / db_scope / git_commit / comment / claimed_at / created_at / updated_at / 临时目录随机后缀。
- 探针副作用警告：PATCH /api/settings 会持久化写真实 config.json（configDir 不随测试 db 隔离）——探针发 PATCH 必须读-改同值或避开，否则污染后续基线对比与真实配置（CR-10d 实测踩中并已恢复 maxConcurrentTurns=3）。

## 已知潜伏 flake（既有，非本链引入）
- test/sessionPause.test.ts「暂停期消息入队不丢」：listMessagesBySession 按 `ORDER BY ts, id`（message.ts:99，id 随机 UUID 决胜），用例不 mock Date.now，两条紧邻 sendToSession（直接 service 调用）同毫秒时 userTexts 断言约 50% 反转。
- 触发概率随机器负载波动；A/B 交错实验（同机同负载交替跑基线/当前树）证实基线同样失败，两侧失败率无差异。全量并行负载下 sessionTurnMigration 也出现过一次同类抖动，单文件复跑稳定。
