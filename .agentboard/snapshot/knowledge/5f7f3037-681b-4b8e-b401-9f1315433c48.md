# AgentBoard 框架优化第二批：状态语义、前端口径、观测与回归

状态：proposed · 2026-11-09 · 落地卡组 ARCH-01..ARCH-08（父卡 `e0dfee83`）

前一批设计见知识页 `8a770fa7-96af-47e2-9321-f9c76700a743`（agent 效率与 token 优化）。本页只收框架级问题，两份设计不重叠。

## 1. 动机与一处自我更正

对框架做了一轮盘点，八条问题里两条最初的判断是错的，先纠正：

- **MCP 覆盖度不低**。任务 CRUD、claim/complete/fail/release/close/reopen、dep、status、knowledge 全套、changelog、decisions、accept 都有 MCP 版。真正缺的只有本地系统类命令（`workspace-db`、`accounts`、`grep`）与尚未存在的 `next`/`stats`。方向因此从「补齐 MCP」改成「不许新命令再出现双实现漂移」。
- **测试基线不薄**。348 个测试文件，`claimRace`、`pagination`、`taskContracts`、`dbMigration` 等关键路径均已覆盖。真缺口是 CLI 契约层的黑盒——单测测函数，测不出「命令输出长什么样」。

## 2. 已定决策

### 2.1 MCP 能力对照（ARCH-01）

`next` / `stats` 同时提供 MCP 版，复用 `packages/shared` 契约类型，不重复实现查询。`workspace-db` / `accounts` / `grep` 明确不提供 MCP 版：MCP 是远程语义，操作本机数据迁移与本地文件检索在远程语义下没有意义。配套在 `Docs/api.md` 落一张逐命令对照表，标注 有 / 无 / 永不提供及原因。

改完的判据不是「表里有」，而是同一查询两路各跑一次、返回字段逐项一致。

### 2.2 状态语义加 `kind=blocked`（ARCH-02）

只把 `blocked` 加进 `kind` 枚举，内置五状态不动。用户在工作区字典里自建「阻塞中」并标 `kind=blocked`，`swing-dev` 的排除规则从标签关键词匹配改为按 kind 判定。

否掉的方案：加第六个内置状态——要改 DDL CHECK、迁移、前端多一列，拖拽落点、列宽、关闭判定全跟，代价远超收益；不动状态改用标签——标签没有语义，正是当前脆弱点的成因。

### 2.3 前端关闭判定统一走 kind（ARCH-03）

现状是混合口径：新增组件已按 `kind` 判（`workspaceStatuses.ts:102-104` 并保留按名字兜底），老组件仍按状态名硬编码（`dnd.ts:11` 的 `BOARD_COLUMNS`、`DetailPanel.tsx:261`、`MetaRow.tsx:70`、`DependencySection.tsx:29`、`BlockedDownstream.tsx:25`）。

先只统一「关闭类」判定，列集合保持固定四列。关闭判定影响正确性（自定义完成类状态现在被当成未关闭），列集合影响布局与视觉验收，改对正确性优先，动态列另立。

### 2.4 知识页 landed 回改进收尾检查（ARCH-04）

不新增 DB 字段。`kb done`（与 `--close-record` 合并）时，若卡关联了 `landed=proposed` 的知识页，强制二选一：改 landed（landed / partial）或显式声明「本卡不推进设计」并写进 notes。

否掉的方案：知识页加 `from_issue` 字段——要迁移且全部写入口跟着改；靠 sources 里塞 `issue:<uuid>` 已可定位，保留为事实标准。

### 2.5 派发模板移出硬编码（ARCH-05）

模板从 `dispatch.ts` 常量改为服务端配置文件读取，保留内置默认值。启动时校验必需占位符，缺失即拒绝启动并点名——坏模板静默失败比启动失败贵得多。

不做工作区级模板覆盖，等真的出现多工作区不同模板再加。

### 2.6 上下文消耗可观测（ARCH-06）

CLI 输出层统一埋点，`KB_METRICS=1` 时在 stderr 打 `[kb] cmd=<命令> out=<字节数>B lines=<行数>`，覆盖 `list-tasks` / `show` / `claim` / `knowledge search` 四条高频命令。默认关，stdout 与退出码零变化。

要衡量的是「agent 读到了多少」，这是客户端事实；服务端记响应体积要引入日志轮转，成本更高且不直接对应 agent 的上下文。

### 2.7 CLI 黑盒 e2e，只覆盖变更面（ARCH-07）

起真实 `createApp` + 临时 DB + 跑真实 `kb` 子进程，覆盖五条：`list-tasks` 默认口径与 `--all-status` 兼容、`show` 评论限量与 `--comments all`、`claim`/`done` 输出含 status、`next` 可派卡字段、`stats` 与逐状态计数一致。

不做全命令 e2e。用例必须能证明「把实现改回旧行为就会失败」，否则只算新增测试不算回归。

### 2.8 数据下沉主干回归（ARCH-08）

在临时工作区目录跑 `enable → status → revert`，断言 `issue` / `issue_comment` / `knowledge_page` / `changelog` 四表在回迁后与下沉前一致。不测中断恢复（依赖 job 状态机，成本高且当前无该类事故）；不测附件二进制；不改实现只加回归。

## 3. 风险

| 风险 | 处置 |
|---|---|
| `kind=blocked` 改动 DDL CHECK，存量库升级可能卡住 | 迁移前备份；用例覆盖「旧库升级后 kind 不变 + 约束生效」；给迁移前后 `kb status ls` 对照 |
| 前端关判改口径导致既有视觉回归 | 保留按名字兜底；既有三份测试全绿作为门槛 |
| 模板移出硬编码后坏配置静默失效 | 启动期占位符校验，缺即拒启 |
| e2e 变慢拖累日常测试 | 限缩到五条用例，接入项目测试命令并记录单次耗时 |
| 下沉回归误伤真实库 | 用例使用临时目录与临时 DB，跑前后对真实库做行数快照对照 |
