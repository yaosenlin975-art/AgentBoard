# 桌面壳自绘窗口标题栏（Tauri v2）

## 定位

「顶栏」在桌面端有两种，别混：页面内看板工具条（TopBar，`apps/web/src/components/shell/TopBar.tsx`）与**窗口标题栏**（`- □ ×` 那一行）。本页只讲后者。用户说「顶栏」时先确认指哪一个，两者改动文件完全不同。

## 结论：无边框 + 三层自绘

- **窗口**：`desktop/src-tauri/src/main.rs` 用 `WebviewWindowBuilder` 代码建窗（`tauri.conf.json` 的 `app.windows` 为空，故没有 `decorations` / `titleBarStyle` 配置项可改），在 builder 上写 `.decorations(false)` 即可去掉原生标题栏。macOS 同样全自绘三键（不保留原生红绿灯），要原生红绿灯再按平台加 `title_bar_style(Overlay)` + `hidden_title`。
- **正式页**：`apps/web/src/components/shell/WindowTitleBar.tsx` 只在 Tauri 运行时渲染（`window.__TAURI_INTERNALS__` 存在），浏览器里返回 `null`，所以测试页/单测零影响。
- **启动页**：`desktop/src-tauri/ui/index.html` 自带同一套 32px 自绘条（`body` 用 `grid-template-rows: 32px 1fr`）。必须做——窗口先加载本地页再 `location.replace` 到服务页，启动失败时没有它就无法移动/关闭窗口。

## 布局口径

- 标题栏是**流式**布局（`App.tsx` 根节点 `flex h-screen flex-col`，标题栏 `shrink-0` 打头），不是 `fixed` 覆盖层：内容自然下移 32px，不会被遮，最大化/还原/窄屏都不会跳变。
- 高度集中在 `WINDOW_TITLE_BAR_HEIGHT = 32` 一个常量；改高度要同步启动页 `grid-template-rows`。
- 窄屏只隐藏应用名（`max-[560px]:hidden`），三键宽度固定 `w-11`（44px），不随视口收缩。

## 拖拽与双击：交给 Tauri 内置 drag.js

`tauri 2.12.5` 的 `src/window/scripts/drag.js` 已经实现，**不要自己写 dblclick 处理器**（会二次切换最大化）：

- `data-tauri-drag-region` 取值：裸写/`true` 只命中自身；`"deep"` 命中整个子树（推荐，空档也能拖）；`false` 禁用。
- mousedown `detail === 1` → `start_dragging`；`detail === 2` → `internal_toggle_maximize`。
- `BUTTON` / `A` / `INPUT` 等 clickable 元素上会自动跳过拖拽，所以三键天然不参与拖动，不需要额外 `pointer-events` 技巧；反过来，**给按钮外侧包一层 drag region 也不会传染**。

## 窗口命令调用（不引 @tauri-apps/api）

```ts
const label = window.__TAURI_INTERNALS__.metadata?.currentWindow?.label ?? 'main';
window.__TAURI_INTERNALS__.invoke(`plugin:window|${command}`, { label });
```

- 走 IPC 命令名 `plugin:window|<cmd>`，避免为 5 个窗口操作引入 `@tauri-apps/api` 依赖（lockfile 与网络变更）。
- **最大化图标同步**：mount 时 `is_maximized`，再监听 `window.resize` 重新取（最大化/还原必然改变视口尺寸）。不要高频轮询。
- 关闭沿用壳语义：Rust 侧拦截 `CloseRequested` → `hide()` 到托盘，进程与服务继续跑（`WindowTitleBar` 只管 `close`，不处理退出确认）。

## ACL 权限（漏一个就是静默失败）

`desktop/src-tauri/capabilities/*.json` 的 `permissions` 需要：

```
core:window:allow-minimize
core:window:allow-toggle-maximize
core:window:allow-is-maximized
core:window:allow-close
core:window:allow-start-dragging
```

`core:window:allow-internal-toggle-maximize`（双击最大化用）已在 `core:window` 默认集内，不用重复声明。远程 URL（127.0.0.1:8787）页面同样要命中这个 capability 的 `windows` + `remote.urls` 才生效。

## 验证套路与坑

- **WebView2 第一次点击只用来激活窗口**，不会派发给页面：自动化里第一次点「最大化」看起来没反应，第二次才生效。脚本每个动作前先点一下标题栏空白处预热。
- **合成鼠标驱动不了 Windows 模态拖拽循环**：`SetCursorPos` + `mouse_event`（即便窗口已是前台、`GetForegroundWindow` 命中）拖动位移恒为 `(0,0)`。可行的替代证据是 CDP 派发真实 DOM 事件：`page.mouse.dblclick()` 能触发 drag.js 的 `detail===2` → 窗口真最大化/还原，说明 drag region 与命令通路都通；`start_dragging` 权限可用 `invoke('plugin:window|start_dragging')` 是否 resolve 来确认。
- **抓标题栏截图用 CDP `page.screenshot()`**：自绘条就是页面的一部分，整页截图能带上；Win32 截屏（CopyFromScreen）容易被前台锁挡住，`SetForegroundWindow` 可能被拒。
- **窄屏取证别依赖 Win32 改窗口大小**：MoveWindow 后 WebView2 视口可能不跟（实测窗口 900x620 但 `innerWidth` 仍 1661）。用 `Emulation.setDeviceMetricsOverride({width:900,height:620})` 复现布局更稳，断言 `barHeight=32 / mainTop=32 / overlap=false / overflowX=false`。
- 打包后带的是 web `dist`：改 `apps/web` 必须重建 dist（`pnpm publish:web`）才有得验；只起 `tauri dev` 时也一样。
