落地范围与实现差异注记（以实现为准）：

1. 迁移：migrateCredentialExpiry（apps/server/src/db/migrations/credentialExpiry.ts）注册在 schema.ts 的 migrateDeviceIdentity 之后，幂等纯加列；老数据不回填保持 unknown，真机存量 5 行已按预期显示 unknown。
2. 到期归一化：parseCredentialExpiry 统一秒级（JWT exp / trae expiredAt，<1e10 ×1000）/毫秒（workbuddy auth.expiresAt 明文，本机实测确认 1796606419025）/ISO 字符串三种来源；trae 信封无 expiredAt 时兜底解 JWT exp。
3. §2 矩阵 trae 行的缺口已按设计修复：captureCurrent 落 JSON {token, refresh_token, expires_at}；httpCheckinProviders 新增 parseTraeCredential 供签到侧兼容旧裸串（行为保持的加法，traeCapture.test.ts 契约已同步更新）。
4. §3 写入点 2：minimax 加号线已改落 JSON 载荷 + expires_at=expires_in*1000+now；zcode/qoder/workbuddy/trae 加号线 expires_at 从 token 响应透传，取不到 null。
5. §4 refresh-credential：refreshMinimaxCredential 既有行为不变（签到侧任何失败仍收敛 null），仅提取 attemptMinimaxRefresh 区分 invalid_grant / failed / no_refresh_token——这是错误表（409 CREDENTIAL_RELOGIN_REQUIRED vs 409 CREDENTIAL_REFRESH_FAILED）所必需的行为保持重构；两码已登记 SAFE_ERROR_CODES。
6. §2 矩阵未覆盖 codebuddy_desktop：refresh_method=null，端点按 relogin 口径 409 引导（不伪造刷新能力）。
7. §3 判定规则 3 实现：无 expires_at 且无 invalid_at 时回落落库基准值（写入点按到期推导，未知即 unknown），与「其余 → unknown」等价。
8. recapture 分派复用 capture-current 的 CLIENT_NOT_RUNNING→backfill 分支（结构化最小接口 CredentialCaptureProvider，避免 routes↔service 循环依赖）；捕获 provider 自身即到期列写入点，刷新成功后行已带新到期。
