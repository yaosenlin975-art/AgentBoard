## WorkBuddy 签到状态

- `POST /billing/meter/checkin-activity-status` 携带 `{}`；仅 HTTP 成功、顶层 `code === 0`、`data.today_checked_in` 为布尔值时，状态才是 `already_done` 或 `not_done`。其它响应为 `unknown`。
- `POST /billing/meter/daily-checkin` 的 `code === 0` 不单独证明签到完成；随后回查 activity status，只有确认 `today_checked_in === true` 才返回 `succeeded`。回查仍为 false、字段缺失、业务码失败或读取异常均不报成功。
- 仓库参考脚本把 claim `code === 10001` 解释为今日已签到，但这是仓库脚本口径，不是上游官方契约；应用仍回查来源状态，只有确认已签到才返回 `already_done`。
- 401/403 标记凭据失效；429 标记限流。签到结果未知时不自动重试。

## 后台批次与额度缓存

- 批次启动 API 仍立即返回 202；后台启动器返回已经启动的批次 Promise。成功或失败结束后，路由调用额度服务 `reset()`，清除账号 scope 与聚合 scope 缓存。
- `reset()` 清缓存并推进代次。请求只在开始时的代次仍有效时写缓存；`finally` 只有在 in-flight map 仍指向同一个 Promise 时才删除该键。
- reset 之前发起的读取仍把自己的上游结果返回给原调用者，但不能覆盖 reset 后的新缓存，也不能移除新一代的并发 Promise。
