# macOS 应用菜单中文化（Tauri v2 自定义菜单换文案）

## 坑：换文案时丢了官方 submenu id，系统默认项失效

Tauri v2（实测 2.12.5）`App::set_menu` 在 macOS 上走 `init_app_menu`：先把菜单 `init_for_nsapp()`，再按固定 id `__tauri_window_menu__` / `__tauri_help_menu__`（导出为 `tauri::menu::{WINDOW_SUBMENU_ID, HELP_SUBMENU_ID}`）找子菜单，命中才调 `set_as_windows_menu_for_nsapp` / `set_as_help_menu_for_nsapp`。

自定义菜单如果全用 `Submenu::with_items`（自动生成 id），两个 `menu.get(...)` 落空：「窗口」菜单失去系统自动窗口列表（打开的窗口不再自动列出），「帮助」失去 NSApp help 关联。肉眼看菜单还在、文案也对，属于静默功能丢失。

## 解法

- 「窗口」「帮助」两个子菜单必须用 `Submenu::with_id_and_items(app, WINDOW_SUBMENU_ID, "窗口", true, &[…])` / `HELP_SUBMENU_ID`，与官方 `Menu::default` 同款 id；其余子菜单（App/文件/编辑/显示）无特殊 id，`with_items` 即可。
- 换文案只用 `PredefinedMenuItem::xxx(app, Some("中文"))`：保留系统默认行为与快捷键，不改运行语义；文本传 `None` 即回落官方默认文案。
- 结构对照官方 `Menu::default` 的 mac 段：App 子菜单（about/服务/隐藏/隐藏其他/退出）+ 文件(关闭窗口) + 编辑(撤销/重做/剪切/复制/粘贴/全选) + 显示(全屏) + 窗口(最小化/缩放/关闭窗口) + 帮助(mac 上为空占位)。App 子菜单比 Tauri 默认多带 `show_all`（全部显示），这是原生 NSApp 标准菜单本就有的项。
- 菜单函数在所有平台构造（Windows `cargo check` 即编译期校验），仅 macOS `app.set_menu` 挂载；Windows 无菜单栏，构造后 `drop`，行为不变。macOS-only 分支在 Windows 上不编译，`app.set_menu` 的存在性靠核对 tauri 源码 `shared_app_impl!`（app.rs，App/AppHandle 共用，`#[cfg(desktop)]`）静态验证。

## 验证方式（Windows 无 mac 环境时）

- `cargo check` + `cargo test`（desktop/src-tauri）：构造函数全平台编译、既有 11 项测试不回归。
- mac 真机目视（菜单五项中文截图、窗口菜单自动列窗口、关于/退出可用）只能人工验收，Windows 上标「未验证：需 macOS 环境」。
