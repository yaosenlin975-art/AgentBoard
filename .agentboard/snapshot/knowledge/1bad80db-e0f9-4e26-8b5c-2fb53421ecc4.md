# Windows 托盘的可观测性：tooltip 即 UIA Name、菜单项与锁屏限制

适用：Tauri v2 桌面壳在 Windows 上的托盘图标（`TrayIconBuilder`），以及「读屏 / 自动化怎么确认托盘真的可读、可点」。

## tooltip 就是 UIA 的 Name

- 托盘图标对 UIA 暴露的 `Name` 来自 `NOTIFYICONDATA.szTip`，Tauri 侧对应 `TrayIconBuilder::tooltip(..)`。**不给 tooltip 时该 Name 为空**：读屏念不出、自动化也定位不到这个图标（只能按「无名按钮」的顺序去猜），用户体感就是「溢出区里有个认不出的图标」。
- 修法一行：`.tooltip("AgentBoard 任务看板")`（见 `desktop/src-tauri/src/main.rs:1033`）。macOS 同 API 落到 status item 的 tooltip。
- 验收只能看**溢出区**：Win11 的隐藏图标挂在 `TopLevelWindowForOverflowXamlIsland` 里，必须先点任务栏的「显示隐藏的图标」把面板打开，UIA 才能枚举到按钮并读到 Name；图标被用户「固定到任务栏」时才会出现在可见区。

## 菜单项与「按归属置灰」

- 托盘菜单是 Win32 弹出菜单（窗口类 `#32768`）。Tauri 的 `TrayIcon` 有 id（`TrayIconBuilder::with_id`，本仓 `TRAY_ID = "main-tray"`），启动结果落地后可用 `app.tray_by_id(..)` + `tray.set_menu(Some(menu))` 整菜单重建，实现「停止服务」的文案与可用性随服务归属变化。
- 归属三分：壳自拉 → 「停止服务」可用；附着外部实例 → 置灰 + 文案「（当前连接外部服务）」；服务没起来 → 置灰 + 「（服务未启动）」。判定一律读 `ServerHandle::is_self_launched()`（`child.is_some()`），不要另存一份布尔状态——`stop()` 取走 child 后它自然变 false，不会漂移。
- 菜单文案是纯函数 `service_menu_label(Option<bool>) -> (&'static str, bool)`，单测直接断言三分支（`desktop/src-tauri/src/main.rs:541`）。
- 「打开看板」不新造唤窗逻辑：先调唯一入口 `wake_main_window`，再 eval 一段只改 navStore 持久化键（`agentboard.nav`，`{state:{view},version}`）的脚本、仅当视图不是 `board` 时改键并 `location.reload()`（`main.rs:532`）。不碰 `apps/web` 源码，也不新增前后端契约；本地启动页没有该键，脚本直接 return。
- 「停止服务」属于「停服但壳不退」：停完设 `boot_ok=false` + `boot_error=文案`，`destroy()` 旧窗口后重建（`destroy` 绕过「关窗=隐藏到托盘」的 `CloseRequested`），落回本地状态页 —— 不能白屏，也不能点了没反应。重建失败重试 5 次、每次 120ms。
- 开机自启**不进托盘菜单**：系统级自启项由设置页（`autostart_status` / `autostart_set`）管，托盘只留用户即时操作。

## 锁屏会打断一切合成交互（实测坑）

- 工作站锁屏时，任务栏整片被 `LockScreenBackstopFrame` 覆盖（`WindowFromPoint` 在任务栏坐标返回该类，或顶层出现「Windows 默认锁屏界面」）。此时：
  - 合成鼠标/键盘事件落到安全桌面，点「显示隐藏的图标」不会展开溢出面板，`{END}{ENTER}` 也选不中菜单项；
  - 直接 `PostMessage(hwnd, WM_RBUTTONDOWN/UP)` 或 `WM_CONTEXTMENU` 发给托盘隐藏窗口（类名 `com.agentboard.desktop-*`）也弹不出 `#32768` 菜单（menu 拿不到输入）。
- 但 UIA **仍能枚举**用户桌面上的窗口（托盘隐藏窗口、应用窗口都在），所以「窗口存在」类断言可跑，「面板/菜单能否打开」类断言不可跑。
- 判断当前能不能做托盘交互，先跑一次 `WindowFromPoint(<任务栏坐标>)`：返回 `LockScreenBackstopFrame` / 锁屏窗口就说明锁着，改期再测，别把「点了没反应」误判成功能坏了。

## 已有可复用的检测脚本（`logs/tray-audit/`，不进产品）

- `measure-exit.ps1`：UIA 找溢出区无名按钮 → 物理右键 → 点菜单末项 → 250ms 轮询进程消失；`-Attach` 切附着态。
- `attach-test.ps1`：先起外部 8899 服务再启壳，验证附着态退出不停外部实例。
- `tray-menu-uia.ps1`：按类名找托盘隐藏窗口、尝试 PostMessage 弹菜单并 dump `#32768` 子项（锁屏下必然失败，未锁屏时可用作菜单文案取证）。
