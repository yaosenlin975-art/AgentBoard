# swing-dev 续派判定：worker inactive 后按看板状态决定下一步

## 口径

worker 回合结束或宿主报 inactive **不等于卡完成**；唯一事实源是 `kb show <卡 UUID> --json` 的 `status`（叠加 `claimed_by`）。父代理在 worker 一停后先回读它手上最后一张卡，再按固定顺序判定：

1. 仍「进行中」→ 同一实例续做同一张：不 release、不重派、不重复 claim（占用仍在，claim 会 409）。
2. 「进行中」但 `claimed_by` 为空（worker 异常退出/租约清扫后的掉线遗留卡）→ 不是他人占用，`kb claim` 可直接续做（claim 接受「进行中且无人占用」）。第 3 节排除规则 4 的「占用者非空」只看 `claimed_by`，不看 status，否则这类卡会被永久跳过。
3. 已「待验收」/「已关闭」→ 依次取：父卡后继（同父、排序在后）→ 同父兄弟 → `kb dep ls` 中被本卡阻塞且已解除的后继 → 同 labels/同目录的未完成无主卡。
4. 都没有 → 回第 2–4 节重扫池子，确认无可做卡再释放绑定。

排序只在「回到池子」时生效；续派优先走上述固定顺序，不先按优先级重排。判定结果（回读 status + 命中分支 + 依据卡 id）要写进绑定账本与班次报告。

## 取数命令与坑

- `kb list-tasks --json` 条目字段：`parent_issue_id`、`status`、`claimed_by`、`sort_order`、`labels`、`resolved`。父卡后继/兄弟靠 `parent_issue_id` 过滤，不靠标题。
- `kb dep ls <卡>` 输出「前置 / 被阻塞者」两段，带「解除」列；完成卡变待验收即解除其出边，但被阻塞者若本身已待验收/已关闭，不能再派。
- 不能用首次派发的队列快照：班次中他人 claim/done/新卡入池都会改变候选集。
- `kb list-tasks` 缺省只回「未完成 + 无主」；要包含他人占用的进行中卡需显式 `--all-status`，否则「进行中且被自己占用」的续做判定会看不到卡。

## 实测（2026-11-09，本区真实两卡场景）

- 分支 1：`kb show 2c9adcef --json` → `进行中 | kb-cli` → 续做同一张。
- 分支 2：`kb show da93be56 --json` → `待验收 | - | b8490f1a-…`；父卡后继过滤（父 b8490f1a，排除待验收/已关闭/已废弃）→ `(空)`；`kb dep ls da93be56` → 被阻塞者 9bc8b831「待验收 / 已解除」→ 不可再派 → 落到分支 3。
- 分支 3：`kb list-tasks --workspace e41eb0fb… --status 待规划` → 有候选，回池子重扫。

## 边界

不改 executing-task 的单卡执行流程；不新增 CLI 命令；不放开他人占用的强制释放。
