# 派发 prompt 模板外置与占位符校验（ARCH-05）

## 结论

- 默认模板逐字迁移到 `dispatchTemplate.ts` 的 `DEFAULT_DISPATCH_PROMPT_TEMPLATE`，运行期模板在服务启动时解析并缓存：`AGENTBOARD_DISPATCH_PROMPT` 指向的文件 → 数据目录 `dispatch-prompt.md` → 内置默认。
- 文件存在但缺必需占位符 → 启动失败、退出码 1，错误里点名缺失的占位符与文件路径；文件不存在 → 静默回落内置默认（与改造前逐字一致）。
- 运行期不再读盘：模板经 `createApp → createRouter → dispatch` 逐层注入（`DispatchDeps.promptTemplate`）。

## 必需占位符

`{{issue_id}}`、`{{title}}`、`{{description}}`、`{{workspace_path}}`、`{{workspace_id}}`。知识块（OPT-14）不占位，作为渲染结果的精确后缀追加。

## 坑

- 文件要按 UTF-8 读并剥 BOM，否则首行会带不可见字符。
- 模板校验只在启动期做；改文件必须重启，热更新不做。
- env 指向的路径不存在时回落内置默认并在启动日志记 warning（不拒绝启动），避免环境变量残留导致服务起不来。

## 验证

- 真机演练（临时 APPDATA/DB/端口 18787）：改文案模板重启后派发首行变化且变量正确渲染；删掉 `{{issue_id}}` 后启动退出 1 并输出「缺少必需占位符：{{issue_id}}（文件：…）」；无文件时 prompt 与改造前逐字一致。
- `dispatch.test.ts` + `dispatchTemplate.test.ts` 28 例全通过；server build 通过。
