# kb list-tasks 缺省收敛（OPT-01）

## 口径

- `kb list-tasks` 不带 `--status` / `--tree` 时缺省只返回「未完成 + 无主」：`kind ∈ open/started/review` 且 `claimed_by IS NULL`；stderr 首行提示 `默认已收敛为未完成无主卡，全量用 --all-status`。
- `--all-status` 恢复改造前口径（整区全状态、含他人占用）；`--status` 显式覆盖（不带 kinds/unclaimed）；`--tree` 不收敛，保留整树上下文（祖先路径不能被过滤掉）。
- 提示顺序：收敛提示在前、`--full` 只对 `--json` 生效的忽略提示在后。

## 服务端契约（REST 增量，不破坏旧调用）

- `GET /api/issues` 新增 query：`kinds`（逗号分隔 kind 白名单，比对 `workspace_status.kind`，自定义状态同样生效）、`unclaimed=1|0`；两个参数都不带时行为与旧版完全一致。
- 非法值一律 400 并点名可用 kind / 只接受 `1|0`，不静默忽略。
- 分页与非分页两条路径共用同一个过滤构造函数 `appendIssueListFilters`，避免只改一条。
- 过滤必须落在 SQL（`EXISTS workspace_status` + `claimed_by IS NULL`），不在 CLI 拉全量后本地筛：否则性能目标失效，分页口径也会与列表不一致。

## 坑

- 状态名与 kind 是两个维度：自定义状态（如「待复测」kind=review）必须能命中，所以按 kind 比对状态字典，不能写死内置状态名列表。
- 参数顺序：CLI 拼 query 时 kinds/unclaimed 必须在 fields 之前；既有测试按 URL 前缀断言，顺序变化会连带改断言。
- 旧服务端不认识 kinds/unclaimed 会忽略参数（HTTP 200），输出退化为全量——这是兼容策略的一部分；只有 `fields` 不可识别才触发 400/404 回落。
- 只改列表还不够：`listIssuesPage` 的 limit/offset 分支必须同步传 filters，否则分页客户端拿到的仍是全量。

## 验证

- CLI：`pnpm --filter @agentboard/cli exec vitest run` → 30 文件 / 400 用例全过（含新增的收敛、`--all-status`、`--status` 覆盖、`--tree`、旧服务端回落用例）。
- 服务端接线：临时用 `createApp` + 临时库验证 `GET /api/issues?kinds=open,started,review&unclaimed=1` 只返回无主未完成（含自定义 review 状态），无参返回全量，`kinds=nope` / `unclaimed=2` 均 400（临时用例已删）。
