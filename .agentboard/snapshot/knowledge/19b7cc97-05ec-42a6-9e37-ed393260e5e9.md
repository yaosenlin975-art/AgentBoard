# CLI 工作区参数缺省解析（OPT-02）

## 口径

`kb create-issue`、`kb status ls/add/rm`、`kb workspace-db enable`、`kb workspace-db snapshot export` 的工作区参数可省略：

| 场景 | 行为 |
| --- | --- |
| 显式位置参数 / `--workspace` | 与 `matchWorkspace` 同口径，可跨区；`--workspace` 优先于位置参数 |
| 缺省，cwd 命中工作区 | 用命中的工作区，无 stderr 提示 |
| 缺省，cwd 不属于任何工作区且全库只有 1 个 | 回退到该区并在 stderr 提示 |
| 缺省，cwd 不属于任何工作区且存在多个 | 非 0 退出并列出候选，不猜 |
| `create-issue` 只给一个位置参数且不匹配任何工作区 | 按「当前工作区 + 该参数为标题」处理，stderr 提示 |

## 实现要点

- 新增 `findCurrentWorkspace`（找不到返回 `undefined`，多命中仍抛错），`matchCurrentWorkspace` 与其共用同一段匹配逻辑，对外行为/报错契约不变。
- `resolveWorkspaceRef` 负责「显式 / cwd / 单工作区回退 / 多区报错」；`resolveWorkspaceWithHint` 只额外把 hint 写到 stderr。二者独立于 `resolveWorkspaceId`，不改动其它命令的既有匹配规则。
- `create-issue` 的歧义判定需要先 `GET /api/workspaces` 再 `matchWorkspace`；请求失败时不把它当标题（保持原「缺少标题」报错），避免服务不可达时误导。
- `status add/rm` 的位置参数只能做成「全可选 + 入口内判空」：commander 不支持「可选在前、必填在后」；只给一个位置参数时按状态名处理。
- `snapshot export` 的 `--workspace` 选项此前只写在注释里、未注册，本次一并补上。

## 坑

- 一次性补上 `--workspace` 后要注意「位置参数 + 选项同时给」的组合：以选项为准，位置参数按标题/状态名处理。
- cwd 解析依赖真实路径（junction/软链接按 target 解析）；`realPath` 失败视为「不在任何工作区」，单工作区时走回退。

## 验证

- 临时 server（独立 APPDATA / DB / 端口）端到端：四个入口不带工作区均成功；单位置 `create-issue title-only-02` 落当前区且带提示；`status add/rm` 单参数成功；cwd 在工作区外、单区时回退并提示，建第二个区后同命令非 0 并列出两个候选。
- CLI 全量单测 30 文件 / 400 用例全过；CLI `tsc --noEmit` 本卡文件 0 错误。
