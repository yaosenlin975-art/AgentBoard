# MCP 任务生命周期收口工具（MCP-C1：close / reopen / accept）

覆盖卡 `f504f61d-aacb-4e6c-96e3-846cf30a4184`。截至 C1，MCP 主名 35、`tools/list` 总数 70（35 主名 + 35 alias）。

## 1. 工具与端点

| 工具 | 端点 | 入参 | 结果 |
| --- | --- | --- | --- |
| `close_task` | `POST /api/issues/:id/close` | `workspace_id`（或绑定）、`task_id`、`request_id`、`fence?` | 更新后的 `Issue`，status=已关闭 |
| `reopen_task` | `POST /api/issues/:id/reopen` | 同上 + `status?`（默认待规划） | 更新后的 `Issue`，status=目标状态 |
| `accept_task` | `GET /api/issues/:id` + `POST /api/issues/:id/comments` | `workspace_id`、`task_id`、`verdict`(pass/fail，默认 pass)、`note?`、`reviewer?`、`request_id` | `{ task_id, verdict, reviewer, comment }` |

- 三者都注册 `agentboard_*` alias。
- `fence` 走 `x-claim-fence` 头（与 done/fail/release 一致）。

## 2. 关键语义

- `close_task`：仅「待验收」→「已关闭」；已关闭再调幂等返回；占用中拒绝（`ISSUE_CLAIMED`，先 release）；有未关闭后代由服务端 409。
- `reopen_task`：仅关闭类（kind `done`/`deprecated`）可重开；目标状态必须命中本工作区状态字典（含自定义状态），非法目标 400 并列出可用状态；占用中拒绝。
- `accept_task`：与 `kb accept` 同语义，**只写固定格式评论、不改状态**：`【验收记录】verdict=<pass|fail>; reviewer=<name>; at=<ISO8601>`，`note` 从第二行起；`reviewer` 缺省 `AGENTBOARD_AGENT_ID`。
- `accept_task` 先 GET 校验：工作区不一致 → `WORKSPACE_BOUND`；status 不是「待验收」→ `ACCEPT_STATUS_NOT_ACCEPTABLE`，且**不发写请求**（本地拒绝）。

## 3. 坑：生命周期写工具必须显式或绑定 workspace

`close_task` / `reopen_task` / `accept_task` 沿用任务写工具的 `resolveWorkspaceId`：只设 `AGENTBOARD_AGENT_ID`、不设 `AGENTBOARD_WORKSPACE_ID` 时，工具调用返回 `WORKSPACE_REQUIRED`，请求不会发出。真机验收时要么在客户端 env 里设 `AGENTBOARD_WORKSPACE_ID`，要么在参数里显式传 `workspace_id`。

## 4. 错误码映射

409 `ISSUE_CLAIMED`（占用中，先 release）/ `INVALID_TRANSITION`（状态不允许，如非待验收卡 close）；400 `VALIDATION_ERROR`（重开目标状态非法）；404 `TASK_NOT_FOUND`；本地新增 `ACCEPT_STATUS_NOT_ACCEPTABLE`。文本一律回安全文案，不回服务端原文。

## 5. 真机验收步骤（可复用）

1. 建临时卡 → claim → `kb done` 到「待验收」。
2. `close_task` 断言 `data.status=已关闭`。
3. `reopen_task` 断言 `data.status=待规划`。
4. 再 claim + `kb done` 回到「待验收」→ `accept_task` 断言返回 `【验收记录】...reviewer=<agent>` 评论。
5. `kb delete-issue <临时卡> --yes` 清理（未占用即可删）。
