# kb next：可派卡组合视图（OPT-10）

## 一句话

`kb next [--workspace <id>] [--limit n] [--json]` 一次返回「当前工作区 · 待规划 · 无占用 · 前置全部解除」的卡，并带派活所需字段：`parent_issue_id`、`blockers`（全部已解除，含状态）、`blocked`（后继）、`siblings_by_label`（同标签未关闭卡，最多 5 张）。

## 取数实现（无新表、无缓存）

1. `resolveWorkspaceWithHint`：`--workspace` 传 id/名称/≥8 位唯一前缀；缺省按 cwd 解析（单工作区回退时 stderr 提示）。
2. `GET /api/issues?workspace=<id>` 取整区，本地过滤 `status === '待规划' && !claimed_by`。
3. 对**每个候选**并行 `GET /api/issues/<id>/dependencies?workspace_id=<ws>`；`blockers.some(!resolved)` 的卡直接剔除（不进入可派列表）。
4. 前缀 `--limit`（缺省 5，正整数、非法 exit 1）只截断输出，不截断上面的取数——总数行仍报真实可派数。

服务端没有依赖批量端点，因此依赖请求数 = 候选卡数（已占用/非待规划/已关闭的卡不发请求）。这是本卡明确接受的成本：N 次并行请求换掉人的三轮查询。

## 输出契约

- 文本：首行 `可派卡 N 张（显示 M 张；条件：待规划 · 无占用 · 前置全部解除）` + 摘要表（id/优先级/父卡/前置/标题）+ 每卡明细（父卡/前置/后继/同标签）；无卡时输出 `（无可派卡）`，**退出码 0**。
- `--json`：`{ items: [...], next_offset: null }`；每项含 `id/title/status/priority/parent_issue_id/labels/blockers/blocks/siblings_by_label`。
- 退出码：0 成功（含空结果）；1 参数错误 / 工作区无法解析。

## 边界

- 不自动 claim（派发仍由调用方显式 `kb claim`）。
- 不改 `kb list-tasks` 语义；需要整区全状态盘点仍用 list-tasks。
- 不加缓存：每次调用都是实时视图，避免派发到已被 claim 的卡。

## 验证

- `pnpm --filter @agentboard/cli exec vitest run` → 34 文件全过（新增 5 例：过滤口径、父卡/前置字段、--limit 与 JSON 信封、空结果退出 0、--limit 非法零请求）。
- 真机对照（工作区 e41eb0fb，OPT-10 收尾时）：`kb next --limit 5` 返回 5 张，与「list-tasks --status 待规划 + 过滤 claimed_by + 逐卡 dep ls 校验 resolved」的手工三轮结果逐卡一致（problems=[]，consistent=true；该区当时手工可派 18 张）。
