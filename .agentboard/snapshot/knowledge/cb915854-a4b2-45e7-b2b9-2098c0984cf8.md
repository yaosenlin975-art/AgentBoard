# 语音输入：长按转写插入链路的静默丢失坑（VOICE-INSERT）

## 结论（可照做）
- **录音中不要把 `pointerleave` 当作取消信号**。长按说话时用户仍按着鼠标/手指，指针因手抖、浮层遮挡、移到窗口边缘而离开输入框很常见；以 document capture 监听 `pointerleave` 并 `cancel()` 会让转写静默白录。`pointerleave` 只用于 `pending` 阶段取消长按计时；录音结束只认 `pointerup` / `pointercancel` / `Escape` / 显式取消按钮。
- **插入失败面必须可见**：转写为空、目标输入框已被移除、`insertVoiceText` 返回 `ok:false` 三种情况都要弹 `voice-error` 并写 `__voiceDebug.lastError`，不能只做 `if (text !== '') insert()`。
- **受控输入框的插入依赖 input 事件**：execCommand/setter 之后必须让 React 的 `onChange` 跑到 store；仅改 DOM 会在下一次渲染被旧值覆盖。验证必须用「React 受控 textarea + 外部 store」用例，而非裸 DOM input。
- **execCommand 返回 true ≠ 插入成功**：少数宿主会返回 true 但值未变，需比较插入前后的 `value`，未变化就回落 setter + input 事件。

## 取证方法
- 用真实事件序列写 RED 用例：`pointerdown` → 等 400ms 出「正在听…」→ `pointerleave` → `pointerup`，断言浮层仍在、松手后文本插入。旧实现该用例稳定失败。
- 浏览器 `?voiceMock=1` 可在不下载模型时走完整手势 + 插入链路；控制台 `window.__voiceDebug`（lastText/lastCaret/lastError）用于区分「没识别到」「没插入」「取消了」。
- 桌面壳（Tauri）不是独立前端：本地启动页后 `location.replace` 到 8787，与浏览器共用同一构建产物，验证时要确认窗口已重载到新 dist。

## 取舍
- 不把「移出输入框」改成「结束录音」：用户可能只是把指针移开，仍按着继续说话；结束只认松手，语义最直观，也不会产生半截文本。
- 「语音已识别但插入失败」单独用一个错误码，不复用「浏览器不支持」，否则用户会被误导去换浏览器。
