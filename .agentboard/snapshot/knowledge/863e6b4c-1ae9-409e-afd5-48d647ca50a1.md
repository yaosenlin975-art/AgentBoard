# MCP 知识库浏览与反查（MCP-K1：list_knowledge / find_knowledge_sources）

覆盖卡 `4e009883-c385-41f2-999c-2c221cd700ee`。截至 K1，MCP 主名 40、`tools/list` 总数 80（40 主名 + 40 alias）；知识域共 9 个主名。

## 1. 工具与端点

| 工具 | 端点 | 入参 | 输出 |
| --- | --- | --- | --- |
| `list_knowledge` | `GET /api/knowledge/pages` | `scope` workspace/common/both（默认 workspace）、`workspace_id?`、`status` active/archived/deleted/all（默认 active）、`include_expired`（默认 false）、`offset`、`limit` 1–100（默认 20） | `{ scope, workspace_id, items[], next_offset }` |
| `find_knowledge_sources` | `GET /api/knowledge/find-source` | `path`（locator / content_hash / source_id 三选一精确匹配）、`scope` common/workspace/both（默认 both）、`workspace_id?` | `{ path, total, items[], truncated }` |

- 两者均只读、均注册 `agentboard_*` alias；只消费既有 REST，不新增服务端路由。
- 列表项只回元数据摘要：`id / scope / workspace_id / slug / title / status / revision / category / landed / domain / expires_at / updated_at / link`，**不带正文**，也丢弃服务端的 `link_info`（引用渲染串可由 `link` 自行拼）。

## 2. scope 语义（与既有工具一致）

- `common`：必须**省略** `workspace_id`，否则本地 `INVALID_ARGUMENT`。
- `workspace` / `both`：`workspace_id` 可显式传；服务端已绑定（`AGENTBOARD_WORKSPACE_ID`）时传别的值 → `WORKSPACE_BOUND`，未绑定又没传 → `WORKSPACE_REQUIRED`。
- `find-source` 默认 `both`：工作区页 + common 页一起反查。

## 3. 输出有界

- `list_knowledge` 上限 100（zod 拒绝 101），摘要字段精简后 100 条仍在 40k 工具结果上限内。
- `find_knowledge_sources` 的 REST 没有分页参数，工具层截断到 100 条，并用 `total` + `truncated` 明示被截断；需要精确定位时改用更具体的 `path`。

## 4. 错误码

404 → `KNOWLEDGE_UNAVAILABLE`（知识 API 不可用）；scope 越界 → `INVALID_ARGUMENT` / `WORKSPACE_REQUIRED` / `WORKSPACE_BOUND`；结果超限 → `KNOWLEDGE_RESULT_TOO_LARGE`。均走 `isError` + `structuredContent.error.code`，不回服务端原文。

## 5. 与 search_knowledge 的分工

- 知道关键词 → `search_knowledge`（相关度排序 + snippet）。
- 只想翻目录/按状态盘点 → `list_knowledge`（时间倒序、分页、无正文）。
- 已知文件路径、想知道哪些知识页引用了它（文件迁移/重构后的反查）→ `find_knowledge_sources`。
