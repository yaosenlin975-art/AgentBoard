# kb stats：一次拿全工作区计数（OPT-11）

## 命令

```
kb stats [--workspace <id|名|前缀>] [--json]
```

## 输出口径

- 五行内置状态计数：待规划 / 进行中 / 待验收 / 已关闭 / 已废弃（自定义状态不计入五行，但计入「覆盖卡总数」）。
- `无主（未完成）` = `status ∈ {待规划,进行中,待验收}` 且 `claimed_by` 为空（与服务端收敛参数 `kinds=open,started,review&unclaimed=1` 同口径）。
- `被阻塞（未完成，有未解除前置）` = 未完成且 `blocked_by_open_count > 0`（该字段由服务端依赖聚合直接带出，不需要逐卡查询）。
- 输出带 `工作区: <完整 uuid>` 与 `生成时间: YYYY-MM-DD HH:mm:ss±HH:mm`（本地时区），末尾附一条逐状态复算命令。
- `--json`：`{ workspace_id, generated_at, statuses: {…五状态}, unclaimed_open, blocked_open, total }`。

## 实现取舍

- **单请求**：`GET /api/issues?workspace=<id>&fields=status,claimed_by,blocked_by_open_count`，本地计数；老服务端不认 `fields`（400/404）时回落整对象请求，计数不变。不新增表、不落库、不加缓存、不改 list-tasks。
- 为什么不走五次 `list-tasks --status X`：每次都要重新解析工作区并回传整页数据，实测五次合计 1326ms，`kb stats` 单次 246.8ms（同机同区）。
- 技能同步：`skills/executing-task` 收尾纪律、`skills/using-agentboard` 收尾声明、`skills/writing-task` 卡面数字复算，统一改为「看板计数类优先 `kb stats`，逐状态复核再给 list-tasks 命令」——数字仍必须可复算，只是取材从 N 条 shell 变一条命令。

## 验证（真机，工作区 e41eb0fb）

| 项 | stats | 手工复算 |
| --- | --- | --- |
| 待规划 | 18 | 18 |
| 进行中 | 1 | 1 |
| 待验收 | 136 | 136 |
| 已关闭 | 664 | 664 |
| 已废弃 | 11 | 11 |
| 未完成无主 | 154 | 154 |
| 被阻塞 | 1 | 1 |
| 覆盖总数 | 830 | — |

耗时：`kb stats` 246.8ms，五条 `list-tasks --status` 合计 1326ms（stats 更快，`faster: true`，`problems: []`）。

测试：`pnpm --filter @agentboard/cli exec vitest run` → 35 文件全过（新增 4 例：计数口径、workspace id+时间+单次请求、--json、fields 400 回落）。
