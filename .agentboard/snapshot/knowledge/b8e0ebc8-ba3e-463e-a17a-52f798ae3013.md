# 技能文档单一权威定义（OPT-13）

## 结论

AgentBoard 技能族把「同一规则写三遍」改成「一处定义、其余引用」：

- **唯一权威定义处**：`skills/using-agentboard/SKILL.md`。
- `skills/executing-task/SKILL.md` 与 `skills/swing-dev/SKILL.md` 只保留本流程独有的内容（执行循环、并行准入、班次参数、拆卡判据等），通用口径一律写「按 `using-agentboard` 的〈节名〉执行」，不复制正文、不改写措辞。

## 锚点表（改规则时只改这些节）

| 口径 | 唯一定义锚点 | 引用方 |
| --- | --- | --- |
| 工作区绑定 / 跨区授权 / 越界三问 / 卡归属 | `using-agentboard`「工作区边界（强制）」 | executing-task「工作区边界与执行环境」、swing-dev「安全红线」 |
| 领取状态门禁与冲突文案 | `using-agentboard`「kb 命令速查」的「claim 状态门禁」 | executing-task Claim 第 1 步 |
| 收尾状态回读（OPT-08） | `using-agentboard`「收尾与提交（GIT-ON-DONE）」的「收尾状态回读」 | executing-task Finish、swing-dev §6/§8 |
| 提交纪律（GIT-ON-DONE / `--scope`） | `using-agentboard`「收尾与提交（GIT-ON-DONE）」+「--scope 与 ID 口径」 | executing-task 并行执行与 Finish、swing-dev §6 完成段 |
| done 前置 CLOSE-RECORD（知识页 / 变更日志） | `using-agentboard`「领任务 → 执行 → 汇报」第 4 步 +「知识页写什么（内容口径）」 | executing-task Finish、swing-dev §6 完成段 |
| 收尾声明四要素 | `using-agentboard`「工作区边界（强制）」的「收尾声明」 | executing-task 收尾回报 |

## 维护规则

1. 改通用规则：先改 `using-agentboard` 对应锚点，再 `grep` 其余技能里对该节名的引用是否仍指向存在的标题；节名是引用契约，不要只改标题不改引用。
2. 新增规则：先判断归属——跨流程通用 → 只进 `using-agentboard`；单流程独有 → 只进对应技能；禁止为了「看得方便」复制第二份。
3. 引用一律用「按 `using-agentboard` 的〈节名〉执行」或「见〈节名〉」，不写「同上」「见前文」这类位置相关措辞（文件被裁剪后即失效）。
4. 验证：三份文件行数、`node scripts/check-bom.mjs`、锚点 grep、`skills/*/test-prompts.json` 的期望行为关键词各查一遍。

## 为什么

重复定义必然漂移：OPT-07 改 `--full` 行为、OPT-08 改状态回读取材后，多处旧文案同时过期，读者无法判断哪份为准。收敛到一处后，改一处即全局生效，验收也只需核一个锚点。
