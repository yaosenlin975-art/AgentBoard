# kb show 多 id 摘要视图（OPT-06）

## 口径

- `kb show <id...>`：**≥2 个 id** 走摘要视图，每个块固定 6 行：`【n/N】<请求 id>`、`id`、`标题`、`状态`、`占用者`（未占用显示 `（未占用）`）、`评论数`（服务端 `comment_count`）。块间空行分隔。
- 单个 id 完全走原详细视图（描述 + 评论 + 子卡进度 + 决策锁），逐字不变；`--comments` / `--description-*` / `--mark-read` 在多 id 模式下忽略（帮助文案已标注）。
- 摘要模式每个 id 只发 1 个 `GET /api/issues/:id`，**不请求评论、不拿描述窗口参数**，20 个 id 实测 260ms（并行 Promise.all）。
- `--json`：多 id 返回 `{ items: [...] }` 信封；成功项 `{ id: <请求 ref>, issue: {...} }`，失败项 `{ id, error: <message> }`。
- 部分失败不影响其余块：文本逐块标 `错误: <message>`，命令返回退出码 1；**不抛错**，避免 `--json` 的 items 流后面再被 `{"error":...}` 污染。

## 实现要点（坑）

- commander `.argument('<issue-id...>')` 即使只给一个 id 也传数组，所以 `show` 的入参类型是 `string | string[]`；数组首元素要给非空断言 `ids[0]!`，否则 `string | string[]` 会漏进 `resolveIssueByRef` 触发 TS2345。
- 退出码通过 `main()` 内的局部变量 `commandExitCode` 传递：show 返回 0/1，action 赋值，`parseAsync` 之后 `return commandExitCode`。不要用「打印完再 throw」实现部分失败——`toExit` 会额外写错误体，破坏 JSON 输出。
- 多 id 下每个 id 各自走 `resolveIssueByRef`：完整 UUID 是 1 次 GET；**前缀会各触发一次 listAllIssues 全量扫描**，批量查询尽量用完整 UUID，避免 N 次全表扫描。
