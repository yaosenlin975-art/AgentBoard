# 详情首屏：描述默认展开（2026-11-07 口径翻转，已替代 D3 clamp）

## 现行口径（2026-11-07，卡 9a140121【DETAIL-DESC-EXPAND】）

用户当轮明确要求「介绍默认展开」，因此现行行为已从 D3 的「默认 3 行 clamp」翻转为「默认展开全文」：

- `DetailPanel.tsx`：`descCollapsed` 初值 `true → false`；切换 issue 的重置 effect 里 `setDescCollapsed(true) → false`。
- `desc-preview` 仍用 `descCollapsed ? 'line-clamp-3' : ''`，只是默认值反过来了；`desc-expand` 的 `aria-expanded={!descCollapsed}` 与文案（`descCollapsed ? '展开全文' : '收起'`）不变。
- `descLong` 判据不变（>140 字或 >3 行才给入口），短描述默认展开且不渲染切换按钮。
- 无折叠状态持久化、无草稿/编辑态耦合（`descEditing` 独立），所以翻转默认值不会留下跨卡串态或脏草稿。
- 测试契约同步翻转：`detail.test.tsx` 的 D3 两条用例改为「长描述默认展开 + 收起回路」「短描述默认展开且无入口」；只改实现留旧断言＝既没测新契约又留下矛盾用例。

**取舍记录**：D3 当初折叠的理由是长描述会把「依赖摘要 + 评论」挤出首屏（真实卡 b95530da 描述块约 2300px）。本次按用户偏好把可读性放在首屏密度之前；若后续要折中，应先立项成决策，不要私自把默认值改回去。

## 历史背景：D3 为什么默认 clamp（已被上面的口径替代）

详情首屏原本「描述默认全文」。长描述（真实卡 b95530da 的描述块约 2300px）会把「依赖摘要 + 评论」推到 y=2528 / y=2965，首屏只剩标题、meta、描述、吸底条——board-accept 在 5174 用 Playwright 量出来的就是这个。

当时的修法（最小改动，三处）：`descCollapsed` 初值 `false → true`；切换 issue 的重置 effect 同步改 `true`；`desc-preview` 的 `line-clamp-3` 沿用原开关。现在这三处已按现行口径反向改回 `false`。

## 环境噪声的识别（同机多 agent 高负载）

同一份代码在不同负载下结论会反：0 条 `AssertionError`、失败全部是 `Test timed out in 5000ms / 15000ms`，且同文件里与本次改动无关的用例（吸底条、状态只读）一起红——这时是负载不是回归。判别三件套：

1. 失败原因里有没有 `AssertionError`（有才是断言失败）。
2. `findBy*` 默认只等 1s，高负载下极易假红。
3. `vitest run` 的位置参数是**子串匹配**：`-- detail.test` 会一起匹配 `accountsMasterDetail.test.tsx` 等，跑成一大堆无关用例；要精确就到 `src/test/detail.test.tsx`。

## 两个操作坑

- PowerShell 5.1 用 `>` 重定向写文件是 **UTF-16LE**，会直接让 esbuild `Transform failed`。要落 UTF-8 无 BOM 用 `[System.IO.File]::WriteAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))` 或 write 工具。
- 不要用 `>` 做「换回 HEAD 版本跑基线」这种对照实验；需要基线就先 `git show <ref>:<path>` 取文本再用无 BOM 写入，跑完立刻还原并核对 `git diff --stat`。
