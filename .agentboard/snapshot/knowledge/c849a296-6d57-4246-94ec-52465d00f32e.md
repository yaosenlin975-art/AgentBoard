# 壳侧轻量取数：Dock 角标与系统通知（E1/E2）

## 取数口径（壳侧集成复用）

壳（Rust）直接对本地服务做只读 GET，无需鉴权（本地态接口与 kb CLI 同源）：

- `GET /api/workspaces` → 工作区数组（`id`/`name`）。
- `GET /api/issues?workspace=<id>&fields=status`（或 `fields=id,title,status`）→ **裸数组**（非 `{items}` 包装）`[{id,title,status}, …]`；「待验收」在壳侧数（与 `kb stats` 的 readIssues 同一路径）。
- `GET /api/decisions?workspace_id=<id>&state=open|grace&limit=1` → `{decisions, counts:{grace,open,stale_open,answered_recent}}`；**计数直接读 `counts.*`**，拉条目时（宽限差分）不带 limit 取 `decisions[].{id,question}`。
- 角标（E1）= 全部工作区的 Σ待验收 + Σcounts.open；通知（E2）差分「新进入待验收的卡」与「新进入宽限的决策」。

## HTTP 工具（server_process.rs `http_get_json`）

std TcpStream 最小 HTTP GET + `Connection: close` 读到 EOF + 按 `\r\n\r\n` 切体 + serde_json 解析；非 200/解析失败返回 None。express `res.json` 恒带 Content-Length（无 chunked），简单解析安全。

## 轮询与平台门控（main.rs，E1/E2 同模式）

- mac-only 线程：成功 30s 一轮；失败（服务未就绪/瞬时错误）5s 退避；每秒检查 quitting 即时收线。
- 取数/差分/解析逻辑**全平台编译**并配单测（fixture + `#[ignore]` 对 8787 实测对账，`cargo test -- --ignored` 显式跑）；仅「产生平台副作用」的调用点（set_badge_count / 通知线程启动）`#[cfg(target_os="macos")]` 门控；被 mac-only 调用链引用的函数在非 mac 加 `#[cfg_attr(not(target_os="macos"), allow(dead_code))]` 消除死代码告警。

## E2 系统通知语义

- 事件：卡进入「待验收」（issues 差分）+ 待决策进入「宽限」（decisions state=grace 差分）。**首轮只建基线不弹**（避免启动把存量全部重弹）；同一 id 会话内只弹一次（NotifiedSet 去重集合）。
- 前台去重口径：主窗口聚焦时跳过系统通知（web 内提醒已覆盖），但事件仍并入去重集合——失焦后不补弹。
- 发送：`tauri-plugin-notification` Rust API `app.notification().builder().title().body().show()`（插件已在 builder 注册，DEC-7）；失败（权限被拒）eprintln 不静默，降级 = Dock 角标 + web 内提醒。
- 限制：点击通知仅激活应用/看板，**不支持深链定位到具体卡/决策**（插件桌面端未暴露点击回调），口径已写卡 062f2bbb 评论。
