# Trae CN 签到状态响应契约（部分核实）

## 已确认

- 签到状态端点：`POST https://api.trae.cn/trae/api/v2/ug/checkin_credits/status`。
- 请求身份头使用 `Cloud-IDE-JWT <token>`。相同账号凭据使用 `Bearer` 时虽返回 HTTP 200，但业务响应为 `code=1001`、`enable=false`、`checked_in=false`，不能按 HTTP 状态判断请求成功。
- 成功状态响应使用顶层数值 `code=0` 和顶层布尔 `checked_in`。`checked_in=true` 表示已签到；`false` 表示未签到。非零业务码、缺少字段或无法解析的响应均不构成可信状态。
- 当前实现只有在 claim 返回 HTTP 2xx 且顶层数值 `code=0`，并且随后状态查询确认 `checked_in=true` 时才返回 `succeeded`。claim 的真实成功响应契约未验证，因此 `code=0` 是当前必要条件，不代表已验证的充分条件。
- Trae 的同日本地 `succeeded` 记录不能代替来源状态查询。

## 未确认

- 本次账号来源状态已为 `checked_in=true`，未重复提交签到；claim 成功响应结构未做真实请求验证。
- 来源响应包含 `credits` 与 `extra_credits` 字段；本次未记录奖励数值及前后变化。
