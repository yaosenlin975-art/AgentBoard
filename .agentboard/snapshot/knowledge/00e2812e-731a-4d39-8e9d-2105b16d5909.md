# 全仓代码审查（2026-11-07）沉淀的可复用事实

配合 Docs/audit-2026-11-07-code-review.md（15 条结论、13 张卡）使用。本页只留可复用的事实与判断口径，不复述逐条清单。

## 1. issue 列表不缺 workspace_id 索引（推翻常见假设）

只读打开中心库（40MB）执行 EXPLAIN QUERY PLAN：`SELECT * FROM issue WHERE workspace_id = ? ORDER BY sort_order, created_at, id` 命中 `issue_parent_order`（(workspace_id, parent_id, sort_order)）。因此「列表全表扫」不成立，不要再为此立项。
真实成本在附加列：comment_count（PERF-5 已修索引）、4 个决策投影子查询、dependency_violation 的 recursive CTE（每行一次，成本随阻塞子树大小增长）。

## 2. 启动期单例锁的正确顺序

不变量：acquireServerLock 必须先于 openDb / initSchema / sweepExpiredLeases / recoverOnBoot。
现状违反：apps/server/src/index.ts 里上述四件事都在加锁之前执行，而该文件注释自己写着「必须先于 openDb」。
失效形态：并发启动时两个进程同时走「PRAGMA table_info 判断列是否存在 → ALTER TABLE」，后到者抛 duplicate column name 并在加锁前崩溃。
推论：任何新增的启动期迁移/清扫，都必须放在加锁之后，不能放进 openDb 或模块顶层。

## 3. 三端 HTTP 超时不一致

apps/mcp/src/apiClient.ts 有 10s 超时；apps/web/src/api/client.ts 与 packages/cli/src/api.ts 没有任何超时/AbortSignal。
判断口径：服务进程存活但不回包时，MCP 正常报错，Web 永久 loading、CLI 永久挂起。三端任一新增请求入口，都应先对齐超时语义再谈其它。

## 4. 错误码映射的现状边界

apps/server/src/api/routes.ts 的 errorHandler 已映射 ApiError / INVALID_JSON / entity.too.large / SQLITE_BUSY；未映射 SQLITE_CONSTRAINT* 与 SQLITE_READONLY，二者落 500 INTERNAL。
推论：仓储层新增约束时，必须同时确认路由层是否需要新映射，否则参数错误会被报成服务故障。

## 5. 已核查、判定「非缺陷」的怀疑点（避免重复排查）

- SQL 全参数化，无模板串拼值；
- attachments 以 UUID 作存储键，无用户可控路径拼接；
- pick-folder / credentialImport 用 spawn + 数组参数，无 shell；
- 两处 dangerouslySetInnerHTML 均为模块常量样式，非用户内容；
- voiceRoutes 的 250ms ticker 在 close/finish 双路径清理；
- decodeTreeCursor 对非法游标抛 ValidationError（400），不是 500；
- 账号凭据不进日志与界面。
