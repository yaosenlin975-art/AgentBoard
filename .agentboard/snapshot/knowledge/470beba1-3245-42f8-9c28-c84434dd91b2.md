# 桌面壳退出语义：附着/自拉两态与 LaunchAgent 托管（B11）

## 口径

托盘「退出」只停「壳自己拉起的 server」（`ServerHandle.child: Some`）。启动时端口已健康（LaunchAgent 开机拉起、手动先起的服务）是附着态（`child: None`），退出只断开不停服、服务 pid 不变、不碰它的 `server.lock`。自拉场景退出停服后，若外部 LaunchAgent 设 `KeepAlive=true`（仓库 `kb autostart` 写的 plist 默认 `KeepAlive=false`），launchd 会按自启语义再拉起——这是配置行为不是拉锯；彻底停服用 `kb autostart uninstall`。

## 两处防拉锯实现

1. **启动宽限（server_process.rs `launchagent_custody` + `ensure_server`）**：`~/Library/LaunchAgents/com.agentboard.server.plist` 存在且端口未健康时，先给 launchd 15s 宽限（KeepAlive 重启有 ~10s 节流）再回落自拉，避免壳抢跑 spawn 与 launchd 争端口/单例锁。plist 检测是纯 fs 判断，`#[cfg(target_os = "macos")]` 分支，Windows 恒 false（行为不变、可编译验证）。
2. **退出等启动收口（main.rs `wait_boot_settled`）**：退出早于 server 健康是真实竞态——`shutdown` 从状态槽里拿不到句柄（还在 `ensure_server` 健康等待里），若直接 `exit(0)`，后台启动线程随进程死亡，刚 spawn 的 node 成孤儿：端口/锁不释放，KeepAlive 场景还会与 launchd 再拉起的实例持续争端口（真正的拉锯种子）。修法：三个退出线程（托盘退出、`--quit-after-ms`、tray 探针）在 `shutdown` 后 `wait_boot_settled`——等 `boot.outcome` 置位（此时 start_server 的 quitting 竞态分支已把刚拉起的 server 停掉）再 exit；上限 70s 覆盖 `ensure_server` 的 60s 健康超时。该等待**不能**放进 `RunEvent::Exit` 处理器（事件线程不可阻塞）。

## Windows 侧验证法

隔离 `APPDATA` + 独立端口跑 dev 二进制：`--quit-after-ms 3000`（退出早于健康，覆盖竞态分支）与 `--quit-after-ms 15000`（健康后退出，覆盖常规停服）都应 exit 0、端口无监听、`server.lock` 不存在。修复前 3000ms 场景会留下孤儿 node（父进程已退、端口仍监听、锁残留）。
