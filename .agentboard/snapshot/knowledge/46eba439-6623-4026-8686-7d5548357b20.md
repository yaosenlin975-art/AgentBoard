# kb show 描述窗口（OPT-05）

## 口径

- 文本模式默认按 **12000 码位** 窗口读描述（`DESCRIPTION_WINDOW_CHARS`，与 MCP `get_task` 的 `description_max_chars` 默认值一致），请求带 `description_offset_chars=<offset>&description_max_chars=<max>`。
- `--description-max-chars <n>` / `--description-offset <n>` 覆盖窗口与续读偏移；`--description-max-chars` 必须 ≥1、offset ≥0，非法值 exit 1。服务端上限 40000 仍以服务端校验为准。
- 服务端 `description_truncated=true` 时，正文后单独一行：`描述已截断，续读：kb show <完整 id> --description-offset <next_description_offset_chars>`；短描述卡不出现该行，输出与改造前逐字一致。
- `--json` 路径保持全量（不带窗口参数），仅当显式给 `--description-max-chars/--description-offset` 才透传，便于脚本分页又不破坏旧消费者。
- 不新增服务端字段：续读完全复用 `GET /api/issues/:id` 已有的 `description_offset_chars` / `description_max_chars` / `description_truncated` / `next_description_offset_chars`。

## 坑

- `resolveIssueByRef(ctx, ref, query?)` 新增可选查询串，show 文本模式恒带窗口参数；**既有测试的 fetch 桩按精确 URL 匹配会全部失败**，须改为按 `url.split('?')[0]` 匹配（本次已同步 cli / taskHierarchy / decision / commentWindow 四套桩）。
- 描述内容可能含换行，`issueLines` 只加一行 `描述: ` 前缀、正文换行原样保留；从输出取描述做拼接校验时要用 `描述: ([\s\S]*?)\n状态: ` 这类跨行匹配，别按单行截。
- 截断偏移由服务端按码位给出，客户端不要自行用 `string.length` 累加。

## 验证

- `pnpm --filter @agentboard/cli exec vitest run` → 32 文件 / 416 例全过；`test/showDescriptionWindow.test.ts` 覆盖默认窗口、显式窗口、短描述逐字一致、分页拼接与 `--json` 全量、CLI 入口与非法值。
- 真机分页（32ee91eb，描述 6119 码位，max=2000）：4 页拼回与 `kb show --json` 描述 `equal=true`；`--description-max-chars 100` 输出续读 `--description-offset 100`；短描述卡（6549eb8d）无截断提示。
