# 技能族结构优化（darwin-skill 适配）：在禁子代理 / 禁分支的项目里怎么落地

## 背景与结论

darwin-skill 的标准流程依赖三件本项目拿不到的东西：独立分支（ratchet/blob 快照）、独立评委 subagent（成对比较、抗自评偏差）、人工 CHECKPOINT 停等。本项目（AgentBoard）的硬约束是 GIT-ON-DONE（在当前分支按 `--scope` 提交、提交信息带卡号）且不派子代理。硬套原流程会产生「分支与看板卡脱钩」「自评冒充评委」两类伪证据。

可行替代（本轮实测）：

1. **ratchet 点 = 卡提交**：每张卡一次 `kb done --scope` 提交，回滚用 `git revert <hash>`；卡评论里记录基线表与复算命令，替代 `results.tsv`。
2. **评委 → 可复算结构指标**：把 rubric 里能机器判定的维度（frontmatter 完整性、CHECKPOINT 标记数、失败分支段数、description 是否有「不适用」、含糊词计数）写成 PowerShell 扫描，基线/结果各跑一次；不能机器判定的维度（dim8 实测表现）**不打分、不据此改动**，`eval_mode=dry_run` 并下调置信度。
3. **人工 CHECKPOINT → 收尾一次性回报**：用户明确「给结论时再报」时不停等，但必须在卡评论里写清偏离项与理由，避免「没说就没做」。

## 本轮扫描出的真实缺口（不是凭感觉）

- `ask-user`：全文 0 个 `🔴 CHECKPOINT · 🛑 STOP`，且无失败分支。它是无人值守唯一提问通道，服务不可达 / 宽限中断 / 回答后 claim 409 / 决策撤回四种情况都没有处置口径 —— 这是最危险的缺口，因为默认行为会变成「自己拍板」或「一直占着卡」。
- `brainstorming`：有 `<HARD-GATE>` 但无失败分支；用户沉默、方案被连续否掉、设计文档写不进知识页时没有下一步。
- `swing-dev` / `using-agentboard`：description 缺「不适用」，路由边界靠正文猜。
- `executing-task` / `handoff` / `writing-task`：三维达标，**不动**。优化不是「每份都改」，没有失败证据的改动就是 churn。

## 可复用的判定口径

- 失败分支必须写「一线 → 兜底」，且兜底要指明**不许做什么**（不 fail、不抢占用、不谎称已保存）。只写「重试」等于没写。
- 停手标记只在「真会写文件/提交/流转状态」的位置加；给纯阅读段加标记会稀释信号。
- 与 `ask-user` 同源的提问口径：任何技能里出现「问用户」都必须显式写成 `kb ask`，否则模型会退回内置提问工具，破坏唯一通道约束。

## 复算命令

- `Select-String -Path skills\ask-user\SKILL.md -Pattern 'CHECKPOINT' | Measure-Object | % Count`
- `(Select-String -Path skills\brainstorming\SKILL.md -Pattern 'HARD-GATE' | Measure-Object).Count`
- `Get-Content skills\swing-dev\SKILL.md -TotalCount 4 | Select-String '不适用'`
- `git diff --stat -- skills`

## 边界

外部 darwin-skill 只读引用（`D:\WorkSpaces\skills\agent-workflow\darwin-skill\SKILL.md`），不复制其 rubric 全文；本页只记录适配结论与可复算判定，不记录「今天改了几行」这类进度。
