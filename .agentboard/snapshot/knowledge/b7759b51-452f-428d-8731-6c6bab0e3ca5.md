# 智能体人设/工具注入管控、聊天窗全 CLI 控制、专家团：调研与设计

- 本页涵盖 P1、P2、P3 三阶段；P1 的人设与工具注入设计已落地，P2 通用 CLI / 技能物化与 P3 专家团仍是后续方案。
- date: 2026-11-09
- card: f02e622a-0a8c-4e70-b07c-c0e563d516f3（RESEARCH-X）
- 调研对象: multica-ai/multica、anywhere-labs/Agents-Anywhere、WorkBuddy 专家团（本机逆向）

## 1. 需求

1. 智能体人设提示词注入 + 工具（含技能）注入管控。
2. 用 AgentBoard 聊天窗控制本地所有 CLI。
3. 专家团功能（对标 WorkBuddy）。
4. 验收导向：给会话选择人设与策略后，turn 按当前 CLI 能力执行；新增 CLI 可按 profile 接入；专家团成员会话可编排、观测与停止。

## 2. 证据基础

- multica：三层人设 brief；CLAUDE.md、AGENTS.md、CODEBUDDY.md 标记块幂等注入与回滚；provider 级技能策略；MCP 三态；统一 Backend/Session/Message；应用层 squad 编排。
- Agents-Anywhere：无 SDK system prompt 注入，依赖 CLI 配置文件；提供权限档位与会话覆盖链、审批事件流、RuntimeProvider 抽象。
- WorkBuddy 专家团：专家包包含 plugin.json、agents/*.md、teamInfo 与 settings；专家提示词经模板装入 system prompt；成员通过主理人编排并中转消息。
- 启动前基线：四个内置 CLI 适配器没有 persona / tool policy 的 RunTurnOptions；会话没有 persona 与策略列；工作区 skills 仅供宿主列举。

## 3. 候选库对比与选型裁定

| 候选 | 许可证类型 | 功能匹配 | 兼容性 | 移植范围与成本 | 验证状态 | 裁定 |
| --- | --- | --- | --- | --- | --- | --- |
| multica-ai/multica | Apache-2.0 | 人设注入、工具管控、团队编排 | Go+Postgres，与 Node/SQLite 栈不符 | 不移植整库；借鉴设计 | 静态读码 | 自研实现 |
| Agents-Anywhere | MIT | 权限与审批、Runtime 抽象；无 system prompt 注入 | Python 云多租户架构不符 | 只借鉴权限与事件语义 | 关键文件已读 | 参考权限档位与审批事件 |
| WorkBuddy 专家团 | 未明确/待确认 | 专家包格式与编排语义 | Electron 端内，无开放 API | 不移植代码；兼容包格式 | 本机 asar 取证 | 只读格式与交互语义 |

采用 Node/TypeScript 自研。multica 源码不移植；Agents-Anywhere 提供权限与审批语义参考；WorkBuddy 只做格式兼容。

## 4. 总体架构

三阶段复用现有 session、turn 与 adapter 骨架：

- P1 注入层：personas 存储、session 级 persona 与 tool policy、CodeBuddy flag 注入、显式 file 模式的工作区标记块、会话设置 UI。
- P2 控制层：声明式 cli_profiles、GenericAdapter、CLI 发现与配置；技能策略按 provider 落地。
- P3 编排层：lead session + member sessions、应用层消息路由与状态事件、专家包导入。

## 5. 能力①：人设注入 + 工具/技能管控

### 5.1 数据结构

- personas 表：id、name、description、body_md、source（builtin|user|import）、package_path、created_at。
- sessions 增加 persona_id、tool_policy、skill_policy、persona_injection 四列；策略字段以 JSON 字符串存储。persona_injection 为 auto|flag|file|off，NULL 按 auto 处理。
- RunTurnOptions 包含 persona、toolPolicy、personaInjection。P1 不向 adapter 传递 skillPolicy；skill_policy 暂存在 session，provider 级物化属于 P2。
- persona 正文上限 100 KB。builtin persona 可读取，不可经 API 修改或删除。

### 5.2 注入链与支持边界

P1 的 persona/tool flag 装配只在 CodeBuddy adapter 实现：

- persona 正文用单个 argv 参数 --append-system-prompt 传入。
- allow / deny 分别用 --allowedTools / --disallowedTools 传入。
- approval_mode=inherit 不传权限参数；plan、acceptEdits、bypass 分别映射到 --permission-mode 对应值。仅当能力探测确认该 flag 时传入。
- personaInjection=auto 或 flag 时，CodeBuddy 使用 persona flag；personaInjection=off 时关闭 persona、tool 与权限注入。
- personaInjection=file 时，persona 不传 CLI flag，改为写工作区标记块；tool policy 仍按 CodeBuddy 能力传入。
- CodeBuddy 以外的内置 adapters 在 P1 没有 persona/tool 参数到 CLI argv 的映射。能力接口返回 CLI help 探测结果供设置 UI 展示，不代表每个 adapter 都有完整的 runTurn 装配。

显式 file 模式使用工作区根目录标记块：

- codebuddy → CODEBUDDY.md；claude 前缀适配器 → CLAUDE.md；其余适配器 → AGENTS.md。
- 块以 AGENTBOARD-SESSION:<session_id> 边界标记包裹；相同 session 更新时原位替换，删除会话时精确移除本会话块。
- persona 正文经过 sanitizer，标记块外的用户内容与其他会话块保留。写入失败记录错误，不阻断起轮。
- auto 不会自动写入工作区文件；只有用户选择 file 时才写标记块。

能力探测通过 CLI --help 识别 personaFlag、toolFlags 与 permissionFlags，按命令缓存 60 秒。该探测用于支持提示与 CodeBuddy 权限参数确认；P1 不提供跨 adapter 的自动 fallback。

### 5.3 工具与技能策略

- tool_policy = { approval_mode: inherit|plan|acceptEdits|bypass, allow: string[], deny: string[] }。P1 的 CLI 参数映射仅由 CodeBuddy adapter 消费；bypass 默认关闭，只有会话显式选择才应用。
- skill_policy = { allow: string[], deny: string[] }。P1 将其保存到 session JSON 列并由会话设置自动保存；不物化到 provider 技能目录、不改变 CLI 的 skill 发现。provider 级 hydrate / deny 与 MCP 托管属于 P2。
- 会话设置提供人设、工具、技能三节。persona_id、persona_injection、tool_policy、skill_policy 在字段变更后 500 ms 防抖自动 PATCH，仅发送变更字段；同一 session 请求串行，组件卸载或切换 session 时用旧 session id flush。全局 persona 正文仍通过 persona API 显式保存，builtin 正文只读。详细交互契约见 knowledge:77c9ba40-f255-4b0e-8aa9-01dde990b84a。

### 5.4 API

- GET/POST/PATCH/DELETE /api/personas；builtin persona 的 PATCH / DELETE 返回 409。
- GET /api/cli-capabilities?adapter=<id> 返回内置 CLI 的 help 探测结果；当前入口识别 codebuddy、codex、opencode、dsh。
- PATCH /api/sessions/:id 接受 persona_id、tool_policy、skill_policy、persona_injection。策略对象以 JSON 字符串写入 session；null 清除字段。persona_id 指向不存在的 persona 时拒绝请求。
- sessionManager 在每轮开始时读取 session 字段和 persona 行，装配当前 RunTurnOptions；file 模式应用工作区 marker。

### 5.5 关键流程

会话设置更新 → 500 ms 防抖 PATCH → session 四字段持久化 → 下一轮装配 persona/tool policy。CodeBuddy 使用受支持的 flag；显式 file 模式在对应工作区配置文件应用 persona marker；off 模式关闭注入。删除会话时回滚该 session 的 marker。skill_policy 目前只保存，等待 P2 的 provider 实现。

## 6. 能力②：聊天窗控制本地所有 CLI（P2 方案）

### 6.1 数据结构

cli_profiles：id、display_name、command、run_args_json、resume_args_json、output_format（jsonl|text）、model_flag、persona_flag、tool_flags_json、env_json、enabled、discovered、created_at。内置适配器保留；profile 面向标准 headless stdout CLI。

### 6.2 GenericAdapter

由 profile 参数化 spawn、resume 与事件解析。JSONL 映射为 UnifiedEvent；text 按行产生 text delta。能力探测生成 profile 级 persona/tool 支持矩阵。

### 6.3 放宽约束

AgentAdapter.id 放宽为 string，注册层校验内置适配器与 enabled profiles。

### 6.4 发现与 UI

PATH 探测已知 CLI并提供手动登记；NewSessionDialog 显示已发现 CLI 与 profile 配置。非目标：交互式 TUI 与 GUI 程序。

## 7. 能力③：专家团（P3 方案）

### 7.1 裁定

应用层自编排，不调用 WorkBuddy 原生专家中心。成员互聊在 v1 禁用，所有成员消息经 lead session 中转。

### 7.2 数据结构

teams：id、name、lead_session_id、status、max_turns_per_member、budget_tokens。team_members：team_id、session_id、role、agent_name、status、usage_json。成员使用普通 session，并绑定 persona 与 CLI。

### 7.3 编排协议

- 创建成员会话；lead 每轮接收成员名册与状态。
- lead 指派成员时，服务端使用成员 session 发起 turn；成员结果返回 lead 处理。
- 状态、用量经 WS team_update 广播。
- 禁用 CLI 内生子代理，避免绕过 AgentBoard 的会话生命周期与状态管理。

### 7.4 专家包导入

兼容 WorkBuddy 专家包的 plugin.json、teamInfo、agents/*.md frontmatter 与 settings.json；解析并导入本地 personas 和团队模板。v1 使用本地目录，marketplace 后置。不复制 WorkBuddy 代码。

### 7.5 UI 与成本护栏

团队视图显示成员状态、tokenUsage 与 toolCallCount；composer 恒指 lead，成员会话可只读展开。以 max_turns_per_member 和团队 token 预算限制成本。

## 8. 分阶段范围

- P1：personas、session 四字段、CodeBuddy persona/tool flag、显式 file marker、三节会话设置 UI。
- P2：通用 cli_profiles、GenericAdapter、CLI 发现、provider 技能策略物化。
- P3：专家团编排、专家包导入与团队视图；依赖 CR2-5 turnStore 细粒度订阅。

## 9. 取舍与风险

- multica 只借鉴设计；Agents-Anywhere 只参考权限与审批语义；WorkBuddy 只兼容格式，不移植代码。
- persona 进入 system prompt 是信任边界；保留来源标记、正文 sanitizer、session 级选择与 bypass 默认关闭。
- CLI flag 随版本变化；探测结果只代表 help 声明的能力。未实现对应 argv 映射的 adapter 不视为已支持 flag 注入。
- file 模式会修改用户工作区根目录文件；仅显式选择时写入，使用 session 边界块，可按 session 精确回滚。
- skill_policy 在 P1 不改变 CLI 行为；未物化前不应将 allow/deny 描述为已执行策略。
- 专家团成员调用可能放大 token 成本；以轮数与预算上限约束。
- 不读取工作区配置文件的 CLI 无法使用 L2 persona marker。

## 10. 已确认的方案决策

1. file marker 为会话级 opt-in；CodeBuddy 默认 auto 走已支持的 persona flag。
2. 专家团 v1 禁成员互聊，成员消息一律经 lead 中转。
3. persona marketplace 后置；v1 仅使用本地 personas 与导入目录。
