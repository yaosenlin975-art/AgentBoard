# 智能体人设/工具注入管控、聊天窗全 CLI 控制、专家团：调研与设计

- status: proposed（第 10 节三项已于 2026-11-09 经用户确认按建议拍板；P1 实施启动）
- date: 2026-11-09
- card: f02e622a-0a8c-4e70-b07c-c0e563d516f3（RESEARCH-X）
- 调研对象: multica-ai/multica、anywhere-labs/Agents-Anywhere、WorkBuddy 专家团（本机逆向）

## 1. 需求（用户，2026-11-08）
1. 智能体人设提示词注入 + 工具（含技能）注入管控；
2. 用 AgentBoard 聊天窗控制本地所有 CLI；
3. 专家团功能（对标 WorkBuddy）。
允许克隆移植。验收导向：①给任一会话选人设与工具/技能策略后，该会话 turn 实际按策略驱动对应 CLI；②新增一个本地 CLI 只需登记 profile 即可入聊天窗；③建团后成员会话自动编排、状态与用量实时可见、可硬停。

## 2. 证据基础
- **multica**（55k star，Apache-2.0+附加条款，Go）：三层人设 brief（agent Instructions + 内置 SystemInstructions + workspace Context）；标记块（BEGIN MULTICA-RUNTIME）幂等注入/回滚 CLAUDE.md/AGENTS.md/CODEBUDDY.md，per-turn 变量上下文走 user message 保 prompt cache；per-provider 技能禁用表（claude settings / codex config.toml）；MCP 三态托管；Backend/Session/Message 统一抽象 + Supplement 运行中插话 + 分级 watchdog；squad 编排全在应用层（leader=普通任务，IsSquadLeader 由 claim 派生防文本嗅探），CLI 内生子代理默认禁用。
- **Agents-Anywhere**（3161 star，MIT，Python/TS）：**无人设注入**（SDK options 不设 system_prompt，人设依赖 CLI 原生读 AGENTS.md）——反证①需自研；权限档位 catalog（claude 六档/codex 三档）+ selections 会话覆盖链 + SessionNotice 审批事件流；RuntimeProvider 统一抽象与会话/turn/流式/中断协议——②的现成蓝本；无编排。
- **WorkBuddy 专家团**（本机 asar 逆向，证据充分）：专家=目录包（plugin.json expertType:agent|team + teamInfo.leadAgent/memberAgents + agents/*.md frontmatter 人设 + settings.json）；内置 60 候选含 10 团队；注入链 expertId → ExpertPromptSlotCollector.resolveExpertPrompt → `<expert_prompt>` 模板并入系统提示词；团队开关 env CODEBUDDY_CODE_EXPERIMENTAL_AGENT_TEAMS；编排=主理人 TeamCreate → 按 Agent ID spawn 成员 → 消息一律经主理人中转（铁律）+ Phase 串并行 SOP；运行时 teammate-message / teamUpdate(member_status_change, tokenUsage, toolCallCount) 事件。
- **我方现状**：四家 CLI spawn 均未传任何人设/工具 flag（types.ts:27 RunTurnOptions 无 persona；全仓 grep persona 零命中）；codebuddy CLI 实测存在 --system-prompt/--append-system-prompt/--allowed-tools/--disallowed-tools（WorkBuddy 系 CLI）；仓库 skills/ 只进宿主 agent 不进被控 CLI（skills.ts:15 只读列举）；adapter.id 四家联合硬编码（types.ts:54）；sessions 表无人设/策略列（schema.ts:90-97）；patchSessionSchema 仅 model/title/archived/paused（schemas.ts:318）。

## 3. 候选库对比与选型裁定

| 候选 | 许可证类型 | 功能匹配 | 兼容性 | 移植范围与成本 | 验证状态 | 裁定 |
| --- | --- | --- | --- | --- | --- | --- |
| multica-ai/multica | Apache-2.0+附加条款（禁托管服务/禁嵌入商业分发） | ①②③全部命中（注入/管控/编排） | Go+Postgres，与 Node/SQLite 栈不符 | 整库不可行；设计级借鉴 | 静态读码（未运行） | 只借鉴设计，实现全自研 |
| Agents-Anywhere | MIT | ②强（权限/审批/Runtime 协议）；①半（工具管控）；③无 | Python 云多租户架构不符 | 模块摘抄（权限目录/审批 schema/抽象）小-中 | 关键文件已读 | 摘其权限档位与审批事件语义 |
| WorkBuddy 专家团 | 专有（逆向取证） | ③全套（包格式/编排协议/注入模板）；①的人设包形态 | Electron 端内，无开放 API | 不移植代码；做包格式兼容导入 | asar 证据充分 | 采用其专家包格式与编排语义，不依赖其端 |

裁定：**全部自研（Node/TS），设计级借鉴三者的机制**。multica 许可附加条款使源码级移植到可分发便携包有风险，且栈不符——不搬代码。

## 4. 总体架构

三层，全部复用现有 session/turn/adapters 骨架：

- **注入层**（能力①）：personas 存储 + tool/skill policy → 按 CLI 能力协商装配（flag 优先、标记块兜底）。
- **控制层**（能力②）：cli_profiles 声明式 profile + GenericAdapter + 发现/能力探测；聊天窗零改动（session 语义不变）。
- **编排层**（能力③）：team=lead session + member sessions（成员即普通会话），应用层路由与事件，专家包导入兼容 WorkBuddy 格式。

## 5. 能力①：人设注入 + 工具/技能管控

### 5.1 数据结构

- 新表 `personas(id TEXT PK, name, description, body_md TEXT, source builtin|user|import, package_path TEXT NULL, created_at INTEGER)`。
- `sessions` 幂等迁移加列：`persona_id TEXT NULL`、`tool_policy TEXT NULL`（JSON）、`skill_policy TEXT NULL`（JSON）。
- `RunTurnOptions` 加：`persona?: { id, body, source }`、`toolPolicy?`、`skillPolicy?`、`injection: { mode: 'flag'|'file', flags?: string[], fileBlock?: { path, block } }`（装配结果由 adapter 能力决定）。

### 5.2 注入链（两级，能力协商）

- **L1 flag**（探测通过才用）：codebuddy 用 `--append-system-prompt <body>`（实测可用）与 `--allowed-tools/--disallowed-tools` 承载 toolPolicy。
- **L2 标记块文件**（兜底 + 不支持 flag 的 CLI）：向会话 workdir 的 `CLAUDE.md`/`AGENTS.md`/`CODEBUDDY.md`（按 provider 映射）写 `<!-- BEGIN AGENTBOARD-SESSION:<session_id> -->` 边界块（multica 幂等注入/精确回滚模式）；用户可控字段过 sanitizer 防提示词注入；**per-turn 变量上下文并入 user message，不进缓存前缀**（multica 教训）。
- 能力探测：`--help` 扫描 flag 支持（启动与会话创建时，结果缓存 60s）；探测失败自动降级 L2。

### 5.3 工具/技能管控

- `tool_policy = { approval_mode: 'inherit'|'plan'|'acceptEdits'|'bypass', allow: string[], deny: string[] }`（档位语义借 Agents-Anywhere catalog；按 CLI 映射到原生 flag/env；bypass 默认关）。
- `skill_policy = { allow: string[], deny: string[], mcp: 'inherit' | { servers: object } }`；技能物化按 multica hydrate 模式落到 provider 原生技能目录，deny 按 provider 落地（multica runtime_skill_policy 模式）；MCP 三态托管（inherit/managed/managed-strict）复用本仓 MCP 面（与 f78d7465 alias 移除节奏协同）。
- UI：会话设置抽屉新增「人设 / 工具 / 技能」三节；能力协商不支持的项置灰并给原因（与账号域 reason_code 惯例一致）。

### 5.4 API

- `GET/POST/PATCH/DELETE /api/personas`（builtin 不可删改）；`GET /api/cli-capabilities?adapter=<id>`（探测缓存）。
- `PATCH /api/sessions/:id` 扩 `persona_id/tool_policy/skill_policy`（patchSessionSchema 同步）；sessionManager 组装 runTurn opts 时解析并注入。

### 5.5 关键流程

建会话（选人设+策略）→ runTurn 组装（解析 persona/policy → 能力协商 → flags 或标记块）→ 流式回投（不变）→ 会话删除/归档时回滚标记块。验收：给会话设人设后，codebuddy turn 的实际命令行含 --append-system-prompt（进程审计）；L2 会话的 workdir 配置文件含边界块且删除会话后块消失。

## 6. 能力②：聊天窗控制本地所有 CLI

### 6.1 数据结构

新表 `cli_profiles(id TEXT PK, display_name, command, run_args_json, resume_args_json, output_format 'jsonl'|'text', model_flag TEXT NULL, persona_flag TEXT NULL, tool_flags_json NULL, env_json NULL, enabled INTEGER, discovered INTEGER, created_at)`。内置四家适配器保留（行为复杂不宜 profile 化），profile 面向「标准 headless stdout 流」形状的新 CLI（claude/qwen/gemini/grok 类）。

### 6.2 GenericAdapter

一个参数化适配器消费 profile：spawn（shell:false）→ 按 output_format 解析（jsonl 事件映射到 UnifiedEvent；text 退化为整行 text delta）→ resume 按 resume_args_json；能力探测产出该 profile 的 persona/tool 支持矩阵（与 5.2 同一套协商）。

### 6.3 放宽约束

`AgentAdapter.id` 从四家联合类型放宽为 string，白名单校验移到注册层（builtin 4 + enabled profiles）。

### 6.4 发现与 UI

发现：PATH 探测已知命令清单（multica agents_probe 模式）+ 手工登记表单；web 的 NewSessionDialog 加 CLI 选择器（发现列表 + 添加 profile），ChatPanel/消息流零改动。非目标：pty 交互式 TUI、GUI 程序；仅 headless stdout 流。

## 7. 能力③：专家团（应用层编排）

### 7.1 裁定

**我方自编排**，不走 WorkBuddy 原生专家中心：accounts 对 WorkBuddy 仅有快照/切换/签到能力（无会话/编排 API）；CLI 原生 teams 耦合实验 env 且仅 codebuddy 系可用；multica 证明应用层编排可覆盖全部 CLI。

### 7.2 数据结构

`teams(id, name, lead_session_id, status, max_turns_per_member INTEGER, budget_tokens INTEGER NULL)`；`team_members(team_id, session_id, role 'lead'|'member', agent_name, status, usage_json)`。成员=普通 session（各绑 persona+CLI），lead=团队会话。

### 7.3 编排协议（WorkBuddy 语义 + multica 防嗅探教训）

- 建团：选专家包模板或手动组员 → 创建成员 session → lead 人设由模板装配，**团队 SOP 以常量标记块并入 lead 人设**（「成员消息一律经主理人中转」为 v1 铁律，同 WorkBuddy team-spec）。
- 运行：lead 每轮由服务端把成员名册/状态注入 per-turn 块；指派成员 = 服务端以成员 session 发起 turn（成员就是普通会话，天然复用流式/持久化/占用语义）。
- 事件：成员状态/用量变化广播 WS `team_update`（形状对标 WorkBuddy `member_status_change{members[tokenUsage,toolCallCount]}`）。
- 禁用 CLI 内生子代理（multica 教训：生命周期未建模会丢产出）——codebuddy 会话不透传其 TeamCreate。

### 7.4 专家包导入

导入器兼容 WorkBuddy 专家包：`plugin.json(expertType/agentName/teamInfo)` + `agents/*.md(frontmatter 人设+maxTurns)` → 落 personas 与团队模板；其内置 curated-experts.json（60 候选含 10 团队）可整包导入。不复制其任何代码，只读格式。

### 7.5 UI 与成本护栏

团队会话视图：成员状态卡（状态/tokenUsage/toolCallCount，事件驱动）；composer 恒指 lead；成员会话只读展开。护栏：`max_turns_per_member` + 团队总 token 预算，超限 fail 并广播（防多成员 token 放大）。

## 8. 迁移路径（三阶段，各自独立可验收）

- **P1 = 能力①最小闭环**：personas 表 + sessions 三列幂等迁移（schema.ts 注册点单卡串行）+ codebuddy flag 注入 + 标记块兜底 + 会话设置 UI 三节。
- **P2 = 能力②**：cli_profiles + GenericAdapter + 发现/能力探测 + 会话创建 CLI 选择器。
- **P3 = 能力③**：teams 编排 + 专家包导入器 + 团队视图；**依赖 CR2-5（turnStore 细粒度订阅）先行落地**，否则团队事件风暴会放大既有全量重渲税。

## 9. 取舍与风险

- 许可：multica 附加条款→只借鉴设计；Agents-Anywhere MIT→可摘数据结构；WorkBuddy 专有→只做格式兼容不碰代码。便携包分发（app/rules）不受影响。
- 安全：用户人设进 system 层=提示词注入面→sanitizer + persona 来源标注 + bypass 默认关；标记块写用户仓库→仅限会话 workdir、幂等、带边界元数据、可回滚。
- 漂移：CLI flag 随版本变化→能力探测每次会话校验，失败降级，不硬编码。
- 成本：专家团 token 放大→7.5 护栏。
- 已知边界：L2 标记块对不读 workdir 配置文件的 CLI 无效（该类 CLI 只能走 L1 或不支持，能力协商会如实置灰）。
