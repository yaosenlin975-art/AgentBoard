## 结论

知识星图的两处热点都在「布局收敛期」：

1. **坐标出 React state（CR2-7）**：`ForceLayoutClient` 的 `onPositions` 不再 `setState`，改为写入 `positionsRef` 并调用 `handleRef.current.updatePositions(next)`。`updatePositions` 只刷新已有节点的 `x`/`y`（尊重拖拽 pin）并 `changed()` / `centerOnContent()`，同时把新 `positions` 记进渲染层 `data`——渲染循环据此创建尚未落位的节点，`snapshot()` 也能拿到最新坐标。收敛期由「每 4 tick 一次整组件重渲」降为 0 次 React 提交。
2. **边清理去 O(E²)**：`update()` 删除消失连线时，原实现对每个现存边 `next.edges.some(...)`，即 O(E²)；改为先建 `nextEdgeKeys` 的 Set 再 `has(key)`，O(E)。

## 坑

- **首帧坐标可能为空**：pixi 句柄异步创建，`start()` 里的首个 `update(renderData)` 可能早于布局 effect 写入 ref。必须在 start 时用 `{ ...initial, positions: positionsRef.current }` 合并最新坐标，否则 `createPendingNodes` 看不到坐标，节点不创建。
- **测试 mock 的句柄没有新方法**：`knowledgeGraphPixi.test.tsx` 用工厂 mock 了 `./pixiGraph` 的返回对象；调用处写成 `handleRef.current?.updatePositions?.(next)`，mock 未实现时静默跳过，不必为了新方法改 mock 约定。
- **effect 顺序**：布局 effect 声明在 pixi 挂载 effect 之前，挂载时 ref 已有初始坐标；后续结构变化时若句柄已存在，直接把新 positions 合并进当前数据推一次 `update()`，新节点立刻上屏。
- **结构变化仍走全量 `update()`**：只有纯坐标变化走 `updatePositions`；增删节点/边、切换筛选、换配色仍要重建差量，别把两条路径混用。

## 实测（2026-11-09）

- 600 条边的清理循环：旧 `.some` 1.81ms / 新 Set 0.41ms（单次 update 内的删除判断；节点边数越多差距越大）。
- 回归：`pnpm --filter @agentboard/web exec vitest run src/test/knowledgeGraphPixi.test.tsx src/test/knowledgeGraph.test.tsx` 23 passed。
