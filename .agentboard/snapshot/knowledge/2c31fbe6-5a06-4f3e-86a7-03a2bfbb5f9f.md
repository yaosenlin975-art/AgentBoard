# 技能族路由与便携包规则清单：新增技能要同步的四处

## 现象

DEC-5 新增的 `ask-user` 技能（提交 `2e7c9c5`）曾在 `AGENTS.md` 索引里列为第 6 项，但 `skills/using-agentboard/SKILL.md` 的族入口、The Rule 动作路由、Skill Priority 表与「与其它技能的关系」表都没有它。后果不是「少列一个名字」，而是按看板工作流作业的 agent 永远不会在卡住/需拍板时被路由到 `ask-user`，而是按旧口径「先 `kb comment` 说明问题后保持占用继续等」——与 `ask-user` 的 `LOCKED` 语义（释放占用 + bump fence + 停手）直接冲突。

同一类问题在 `brainstorming` 上重演了一次（SKILL-PKG，提交见卡 `ebf65000`）：技能已存在于 `skills/brainstorming/` 且被 Skill Priority 表当成「需求未澄清」的唯一落点，但 `AGENTS.md` 索引与两处 `REQUIRED_SKILLS` 仍按 6 个算，导致便携包里没有它。

## 结论（口径）

- 技能要在 `using-agentboard` 的四处登记才算「接入」：frontmatter description、正文族说明与权威来源解析、The Rule 第 1 条动作路由、两张表（Skill Priority / 与其它技能的关系）。只写进 `AGENTS.md` 索引不够——索引只说明「存在」，不构成执行路由。
- 待决策统一口径：`kb ask` 落决策 → 默认 180 秒宽限（0–600）→ 返回 `LOCKED` 即停手（不改文件、不提交、不 `done`）；无人值守用 `--grace 0` 立即落锁。
- `executing-task` / `handoff` 不得再写「保持占用等回复」，必须指向 `ask-user`；`swing-dev` 属无人值守场景：已有决策用 `kb decisions --state open --stale` 只读核对后跳过，卡面外的设计决策用 `kb ask <id> --grace 0` 立项落锁（不建宽限期），再把原因写进卡面。

## 便携包清单是四处同源维护（坑）

当前必需技能（7 个）：`using-agentboard` / `writing-task` / `executing-task` / `handoff` / `swing-dev` / `ask-user` / `brainstorming`。

- 打包生效清单在 `scripts/package-portable.mjs` 的 `REQUIRED_SKILLS`；包内自检脚本 `scripts/portable/verify-rules.mjs` 另有一份同名常量。两份曾经不同步（前者有 `ask-user`、后者只有 5 个），导致「包内规则自检通过」并不能证明新技能真的进了包。
- 新增/删除技能时要同时改四处：两份 `REQUIRED_SKILLS`、`scripts/portable/README.txt` 的携带清单与自检输出示例、`AGENTS.md` 技能索引 +「对外打包约束」的份数与名字；根 `README.md` 打包小节是同一口径的第五处同源文案。
- **已同步（2026-11-07 收口）**：根 `README.md` 第 129/131 行已改为「7 个技能」并列出 `brainstorming`（卡 `9a2a81af-c10f-4a6e-b59d-bdcd5d0442be`）；两份 `REQUIRED_SKILLS` 同由卡 `ebf65000-c352-4070-8694-9fa6c85c6389`（SKILL-PKG）改为 7 项。此前按少一个技能计数的表述全部过期。
- 校验方法（快）：正则提取两份 `REQUIRED_SKILLS` 做字符串比对，再逐个断言 `skills/<name>/SKILL.md` 存在，并核对 `(Get-ChildItem skills -Directory).Count` 与清单长度相等。
- 校验方法（权威）：`node scripts/package-portable.mjs --skip-build --no-zip --out <临时目录>`，看末行 `[rules] OK：… N 个技能`、`rules-manifest.json` 的 `skills` 数组长度、以及 `runtime\node.exe app\verify-rules.mjs` 的退出码。`--skip-build` 复用已有 dist，步骤 4–5 与全量一致。

## 验证

- `node scripts/check-bom.mjs`：新增 BOM 0。
- `node --check scripts/portable/verify-rules.mjs` 通过。
- 两份 `REQUIRED_SKILLS` 逐项一致，7 个技能目录均有 `SKILL.md`；打包产物 `app/rules/skills` 实有 7 个目录，manifest `skills` 长度 7，包内自检 exit 0。
