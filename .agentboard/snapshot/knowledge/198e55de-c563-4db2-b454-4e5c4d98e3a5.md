# 批量导入不落每页快照：显式跳过信号（KB-SNAP-IMPORT 方案 3）

## 裁决与理由

卡 6892d200 给了三个方案，选 **方案 3（保持不接线 + 响应显式信号）**：
- 方案 1（逐页提交）：每页 4-5 次 git 子进程，100 页 ≈ 500 次进程调用，导入端点毫秒级 → 分钟级；卡面自认需「耗时上限/批处理折中」，折中即退化成方案 2。
- 方案 2（单次汇总提交）：打破已定稿 BORROW-5.1「一次提交只含该页路径」（决策 c0cb9509），实质改已确认设计，不在实施卡授权内。
- 方案 3：不动 BORROW-5.1、不给导入端点加 git 开销，消除「响应零信号」；后续真接线另立卡。

## 契约

- `POST /api/knowledge/pages/import` 响应为 `{ pages, warnings, page_commit }`；`page_commit` 恒为 `IMPORT_BATCH_COMMIT_SKIPPED = { path: '', relative_path: '', committed: false, commit: null, reason: '批量导入不落每页快照（…）', skipped: true }`（`services/knowledgePageCommit.ts` 导出的常量，PageCommitResult 形状）。
- 语义沿用 KB-SNAP-SILENT：`committed=false && skipped=true` = 既定决策的跳过，**不是失败**；调用方据此可区分「已接线但显式跳过」与「端点根本不落快照」（后者表现为无 page_commit 字段）。
- 端点保持**无** `commitKnowledgePageRevision` 调用（复算口径：grep 该端点仍无调用即为符合方案 3）。
- CLI `kb knowledge import`：文本模式在 stderr 打印一行 `提示：<reason>`（`committed===false && skipped===true` 时，数据驱动——未来接线后提示自动消失）；`--json` 不加 stderr，信号在 stdout JSON 的 `page_commit` 里。
- 文档同步：`Docs/api.md` §11 BORROW-5.1 段与 §18 导入响应、知识页 `0726f260`（rev 5）状态规则表与已知缺口段已改。

## 验证

- server：`npx vitest run test/knowledgeImport.test.ts` 25 passed（新增 1 条：page_commit 形状 + 快照文件不存在断言）；`test/knowledgePageCommit.test.ts` 15 passed（回归）。
- CLI：`npx vitest run test/knowledgeImport.test.ts` 11 passed（新增 2 条：文本 stderr 一行、--json 机器可读）；`test/knowledge.test.ts` 45 passed（回归）。
- tsc：两侧 src 均无错误（apps/server 与 packages/cli 的既有报错全在本工作树他人 WIP 的 test/ 文件，与本卡无关，未扩大）。

## 边界

- 导入页在 git 审计链里**仍然没有**提交——这是显式决策不是缺陷；「导入页 archive/delete 后走 removeKnowledgePageSnapshot 的 skipped=true 分支」与本信号口径一致。
