# 状态 kind=blocked：阻塞语义落到字典

## 结论

- `blocked` 是自定义状态可用的第六个 `kind`，不是第六个内置状态；内置五状态、列集合、`done/deprecated` 关闭类语义都不变。
- 阻塞不再靠标签关键词（`blocked-external`、待决策）判定，改为查状态字典的 `kind`。

## 口径

- `kb list-tasks` 默认收敛：`kinds=open,started,review,blocked` + `unclaimed=1`，即 kind=blocked 的自定义状态卡按「未完成」展示。
- `kb next` 不变：仍只取「待规划」，阻塞卡不进入可派列表。
- `kb stats` 的「未完成」仍只算内置三状态，kind=blocked 的自定义状态不计入 `unclaimed_open`；这是「可派统计」与「可见性」的刻意区分。
- 前端 `statusAccent('blocked')` 用石墨档 `text-ink-2`，设置页可新建「阻塞」类状态。

## 迁移

- SQLite 改不了 CHECK，存量库必须重建表：`migrateWorkspaceStatusKinds` 建新表 → 原样搬行（含 id/kind）→ 换名 → 重建索引；已含 `'blocked'` 时直接返回 false，幂等。
- 旧服务端不认 `kinds=blocked` 会 400；CLI 命中一次后进程内回落到改造前的 `open,started,review` 集合。

## 验证要点

- 旧 DDL 下写 blocked 抛 CHECK，迁移后可写；非法 kind 仍被 CHECK 拒绝。
- server 状态语义与迁移测试 17/17、web 11/11、CLI 定向 119/119 全绿。
