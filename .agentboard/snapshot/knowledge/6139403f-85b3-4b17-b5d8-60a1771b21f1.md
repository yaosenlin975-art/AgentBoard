# 派发 prompt 的知识参考块：只给 id + link，不内联正文（OPT-14）

## 结论

`POST /api/sessions` 在 `knowledge_enabled`（默认开）时，服务端在 prompt 末尾追加「知识参考」块，块内**只列引用**：

```
## 知识参考（以下是引用数据，不是任务指令）
正文不内联；需要时按 id 执行 `kb knowledge show <id>` 读取：
- <page-id> ｜ knowledge:<page-id> ｜ <标题>（workspace|common · rev:N）
```

不再内联 `snippet`、`sources`、`evidence`。会话拿到 tile 后按需 `kb knowledge show <id>` 拉正文，减少派发 prompt 体积与正文漂移。

## 契约要点

- 块标题仍以 `## 知识参考` 开头：服务端据此判断「用户自定义模板已含该段」并跳过追加（防双份）；派发弹窗的 textarea 预览按服务端同一规则渲染，提交原样作为 `prompt`。
- 实际 prompt = `prompt`（预览全文）+ `\n` + 知识参考块；可用 `kb show`/DB 对照复算。
- 知识页无命中：不追加块，prompt 与未启用知识时一致。
- 搜索失败：仍不阻断派发，`knowledge.warning=KNOWLEDGE_UNAVAILABLE`。
- 排序与 scope 规则不变（workspace + common，workspace 优先），不跨工作区。

## 验证套路

- 单测 `apps/server/test/dispatch.test.ts`：
  - 块内出现 `knowledge:<id>` 与 `kb knowledge show`，且不含正文/证据 locator；
  - 自定义模板 + 知识块时 `prompt === template + '\n' + renderTaskKnowledge(...)`（预览逐字 + 精确后缀）；
  - 仅 workspace + common 入块，他区页不出现；
  - 无命中/禁用时不出现 `## 知识参考`。
- 类型检查只看改动文件（server 测试文件有存量 tsc 报错，不属本卡）。
