## 0. 一句话

把知识页的**唯一事实源**从 SQLite 换成实体 markdown 文件（工作区 `Docs/`、公共 `~/.agentboard/Docs/`），主键改成 Obsidian `[[wikilink]]`；同时把已经存在的"每工作区一个 db"从按需开启变成默认形态，并移除设置界面的数据存储配置。应用内自研星图同步改为直接扫 `Docs/*.md` 画边。

**方向以用户拍板为准**：现状只作为可复用地基与约束清单，不构成方向依据。

## 1. Intent & Why

【已定·用户原话】方向 B：md 是唯一事实源；知识页正文与元数据全部落在 `<工作区>/.agentboard/Docs/*.md`，公共知识落在 `~/.agentboard/Docs/*.md`；kb／web／server 直接读写文件；SQLite 不再持有知识页权威数据，只留任务／日志／看板数据。Obsidian 打开该目录＝打开知识库，改文件＝改数据。

【已定·追加】「我们自己的知识库星图绘制也要支持 obsidian 的语法」＝应用内自研 pixi.js 星图（`apps/web/src/components/knowledge/`），不是 Obsidian 客户端。

【事实·为何是重写而非改造】`apps/server/src/services/knowledgePageCommit.ts:17` 写明「该快照是派生物：库仍是唯一事实源，删掉文件不影响数据」；`:317` common 页完全不落盘；权威数据在 `knowledge_page` / `knowledge_revision` / `knowledge_fts`（`db/migrations/knowledge.ts:6-40`）。现有 99 个 `.agentboard/snapshot/knowledge/<uuid>.md` 是 UUID 命名、7 字段 front matter 的派生物。方向 B 因此是**替换仓储层**，不是补落盘。

【事实·为何星图必须换数据源】现有边来自 `knowledge_link` 表（`db/migrations/knowledgeLinks.ts:22-38`，按 `source_page_id + revision` 绑定），由 `services/knowledgeLinks.ts:119-157` 写页时同事务写入，`api/knowledgeRoutes.ts:196-206` 用 `listResolvedLinks` 喂给 `buildKnowledgeGraph`（`services/knowledgeGraph.ts:157-271`）。md 成唯一事实源后该表不再有权威地位。

【事实·有利地基】
- `services/knowledgeLinks.ts:35-41` 的 `normalizeLinkTarget()`（NFKC→trim→空白折叠为 `-`→小写）归一到 slug，与新方案「文件名＝slug」同源，`:82-105` 解析器可复用而非重写。
- 前端 `KnowledgeGraph.tsx:103-109` 已默认 `edge_kinds: 'link,source,keyword'`，`pixiGraph.ts` 只消费 `nodes/edges`，`pixiGraph.ts:248` 已接 `fillUnresolved`，`index.css:356-420` 有 11 个 Obsidian `.graph-view.color-*` 语义色，`localGraph.ts:116-164` 有 forelinks／backlinks／interlinks／hideOrphans 四开关与 1–5 跳。**前端契约可基本不动**。
- `<工作区>/.agentboard/agentboard.db` 的下沉能力已完整实现并接线（`api/routes.ts:118` 生产 `openWorkspaceDbs: true`；`packages/cli/src/commands/workspaceDb.ts` 的 `enable/status/cleanup/revert/snapshot` 全族），只是默认 `db_mode=center`、本工作区未 `enable`。
- `[[a]]`／`[[a|b]]`／`[[a#h]]`／`[[a#h|b]]` 的解析、反链端点、unresolved 统计、跨库解析（workspace→中心库 common 页）均已存在（`knowledgeLinks.ts:1-16, 82-105, 110-118, 196-223`）。

## 2. Goals / Non-goals / Anti-goals

**Goals【已定 + 必要推论】**
- G1 知识页唯一事实源是 `Docs/*.md`；Obsidian 打开即可浏览，直接编辑文件即改数据。
- G2 工作区知识落 `<工作区>/.agentboard/Docs`，公共知识落 `~/.agentboard/Docs`，公共知识不随工作区仓库进 git。
- G3 引用主键改 `[[wikilink]]`（文件名＝语义化 slug）；uuid 退到 front matter 作稳定 id；`knowledge:<uuid>` 保留兼容解析而非强删。
- G4 每工作区一个 db 成为默认形态；移除设置界面数据存储配置与 `db_path` 可配；保留只读 `AGENTBOARD_DB` env 与 `revert` 回退通道。
- G5【已按 §8 #1 定稿】应用内 pixi 星图**较完整支持 Obsidian 语法**：现有 `[[a]]`／`[[a|b]]`／`[[a#h]]`／`[[a#h|b]]` 四形态、反链、unresolved、语义色在换数据源后不回退，并补齐 `![[embed]]` 独立边 + 嵌入渲染、`[[a#^block]]` 块引用、`#tag` 标签节点、`![[image.png]]` 附件节点。
- G6 存量数据一次性迁移，旧库只读保留可回退。
- G7 一份设计覆盖两点，拆卡分两期：一期 db 下沉默认化，二期知识子系统重写。

**Non-goals【裁决／可否决】** 不做与 Obsidian 客户端的双向实时同步或插件；不做 vault 级 `.obsidian/` 配置管理；不做跨设备／网络同步、云存储；不重写任务／日志／会话／账号／签到数据模型；不改动 `kb` 非知识族命令语义。

**Anti-goals【事实推导】**
- AG1 不得保留与文件并行的「权威 DB 知识表」——否则退回方向 C。旧库表只能只读保留。
- AG2 不得让 `knowledge_link` 表继续当星图权威边源。
- AG3 不得静默覆盖 Obsidian 外部编辑（沿用 `knowledgePageCommit.ts:211-224` 的逐字节回读校验口径）。
- AG4 HARD-GATE 批准前不实施／不建卡／不落库（`AGENTS.md:5-7` RULE-1）。

| | **A 扶正快照** | **B md 唯一事实源（用户选）** | **C 双写镜像** |

### 7.3 一致性与并发（最关键，逐项等价承载）

| 现有能力（DB） | 承载方式 | 放弃与后果 |
|---|---|---|
| revision CAS（`db/repos/knowledge.ts:174-192` 事务级原子） | 写协议：读文件→比对 `expected_revision`→写 tmp→`fsync`→`renameSync` 原子替换（沿用 `config.ts:215-236`）→更新索引→返回新 revision；进程内 per-path 串行队列 | 放弃 SQLite 事务级原子性；崩溃可能留 `.tmp-*`（reconcile 清理）；不同进程同时写只能靠检测把「静默丢」变成「显式报错」 |
| slug 唯一索引（`db/migrations/knowledge.ts:14-15`） | 文件系统同目录不能重名，天然唯一；跨 scope 同名按 M2 报歧义 | 无 |
| 不可变历史 `knowledge_revision`（`:20-29` 禁 UPDATE/DELETE 触发器） | 工作区 `Docs/` 可借 git history（不保证每页单提交）；公共 `~/.agentboard/Docs` 无 git | **放弃自动历史落盘** → `GET /pages/:id/revisions` 无数据、410 `KNOWLEDGE_DELETED` 的「可查看历史版本」失效 → §8【待拍板 1】 |
| FTS5 trigram（`:30-39`；`:608` ≥3 字符 bm25、1-2 字符 LIKE、`snippet≤1200`） | **不降级（§8 #2 已定）**：落盘可重建索引文件承载 bm25 排序 + trigram／1–2 字符子串 + `snippet`，索引可全量重建、非事实源 | 无能力下降；代价是新增索引构建／失效维护与首次构建耗时；大库（>5000 页，`knowledgeGraph.ts:16`）需评估索引体积；`score` 语义变化处写进 `Docs/api.md` 并前端回归 |
| 跨工作区聚合（`knowledgeSearch.ts:76,159`、`resolver.ts:433-466` fan-out） | 知识侧扫「当前工作区 Docs + 用户级 Docs」两目录合并，`scope` 由目录过滤 | **明确放弃旧 fan-out（§8 #4 已点头）**：共享一律走 `~/.agentboard/Docs`，不再遍历中心库注册表做跨所有工作区聚合；`kb list-tasks --all` 是任务数据、仍在 db，**不受影响** |

**三层并发策略**【裁决 + §8【待拍板 2】默认】：
- L1 进程内：per-path 串行队列 + tmp/rename 原子写。
- L2 跨进程锁：`<Docs>/.locks/<slug>.lock`（`O_EXCL`，写 `pid + instanceId + ts`，stale 超时接管，复用 `services/serverLock.ts` 口径）；锁只覆盖 API/CLI 写，**不锁 Obsidian**。
- L3 外部编辑检测：写前比对 `stat.mtimeMs` + `content_hash` 与索引基线，不一致 → 不覆盖，抛 409 `KNOWLEDGE_FILE_CONFLICT`，提示先 `reconcile`。
- 正文读路径直接读文件（不缓存正文）→ 「改文件即改数据」无需重启／无需命令；索引按 mtime/hash 增量刷新。
- 不引入文件监听库（C12）；启动 reconcile 默认只读报告（校验 front matter 必填/类型、文件名 vs slug、`id` 重复、revision 倒退、content_hash 不符、`[[...]]` 目标缺失、残留 tmp/lock），`--fix` 只修可判定项。

## 11. 风险

- R1 中心库位置与「移除数据存储配置」的张力 → 已由 M13 依用户已确认边界定掉；若用户否决需重画 P1。
- R2 公共知识不进 git × 不可变历史 × 回退三者拉扯 → §8【待拍板 1】；`revert` 不是完整回退（§7.7）。
- R3 混合态迁移：知识页分散在中心库与多个工作区库，导出必须 fan-out，漏一个区就丢页。
- R4 外部编辑与并发：跨进程无原子 CAS、无实时监听，冲突只能事后报错（§8【待拍板 2】）。
- R5 检索／图谱性能：FTS→内存扫描，`GRAPH_MAX_PAGES=5000`（`knowledgeGraph.ts:16`）可能成为新瓶颈。
- R6 文件名即主键：改名／中文／大小写不敏感文件系统／NFC 归一／跨 scope 同名（§7.1 N1-N5、M2、M10）。
- R7 双轨引用：`[[wikilink]]` 与 `knowledge:<uuid>` 的服务端解析、web 渲染、CLI 产出、4 个存量引用页（§7.5）。
- R8 附件与图片：旧 `/api/knowledge/images/:id` DB 存储与 vault 相对路径的兼容（M8）。
- R9 文档滞后：`SKILL.md:105` 速查未登记 `enable`/`snapshot`，`:227-236` KCLINK 与主键变更直接冲突；`Docs/api.md` 知识页整章需重写。
- R10 Docker／便携包：网络盘预检、`~/.agentboard/Docs` 可写性（M15）。
- R11 RULE-3：新增 CLI 命令／REST 端点／wikilink 扫描都必须证明外部可触达（`AGENTS.md:13-15`）。
