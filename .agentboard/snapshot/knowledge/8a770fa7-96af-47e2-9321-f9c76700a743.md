# AgentBoard agent 效率与 token 优化设计

状态：proposed · 2026-11-09 · 落地卡组见文末「落地拆分」

## 1. 动机

本设计的来源是一次针对「agent 用 AgentBoard 干活有多贵」的实测复盘。三条真实成本：

1. **单次输出过大**：`kb show <id>` 与 `kb claim <id>` 全量打印该卡所有评论正文（`show.ts:74-84`、`claim.ts:43-53`、`render.ts:57-62`）。一张 17 条评论的卡，一次读取就是几千到上万 token，而 agent 实际只需要最近几条。
2. **往返次数偏多**：父代理解一次派活要 `list-tasks` → 逐卡 `show` → 逐卡 `dep ls` 三轮；每卡收尾要写知识页、写 changelog、再回读 `kb show`；每个统计数字还要各跑一条复算命令。
3. **默认语义不贴用法**：`kb list-tasks` 不带参数会刷出整区全部卡（含数百张已关闭卡），真正要用的「本区未完成无主卡」反而要自己拼参数；CLI 里一部分命令按 cwd 解析工作区、另一部分强制必填，口径不一致。

## 2. 目标与非目标

**目标**

- 让 agent 每一轮都会付的成本（看卡、领卡、收尾、统计）直接下降。
- CLI 的工作区语义统一：缺省即当前工作区，显式参数才跨区。
- 消除技能文档中同一口径的三处重复，降低加载成本与口径漂移。

**非目标**

- 不改数据库 schema、不新增表、不引入外部依赖或第三方库。
- 不改已发布 REST 字段语义；不为性能引入缓存层。
- 不把技能拆成「核心 + 附录按需加载」：规则不完整比多花 token 更贵。
- 不做看板前端与知识图谱的改造（另立项）。

## 3. 已定决策

### 3.1 工作区缺省语义（三档，不是一刀切）

| 档 | 范围 | 决策 |
|---|---|---|
| 读与改 | `list-tasks`、`knowledge *`、`changelog` 活动命令、`decisions`、`workspace-db status`、`status ls/add/rm`、`create-issue`、`workspace-db enable`、`snapshot export` | 不传即按 cwd 解析，全部走 `resolveWorkspaceId` |
| 销毁与迁移 | `delete-space`、`workspace-db cleanup`、`workspace-db revert`、`changelog import preview/apply` | 保留显式必填。`delete-space` 另需 `--yes` |
| 位置参数错位 | `create-issue <workspace> [title]` | 第一个位置参数先用 `matchWorkspace` 试解析：命中当工作区，不命中当标题并使用 cwd，stderr 提示 |

cwd 不属于任何工作区的兜底：全库只有一个工作区时用它并提示；多个工作区时报错并列候选，不默认取第一个。

### 3.2 `kb list-tasks` 默认口径

- 无参 = 当前工作区 ∩ 未完成 ∩ 无主。
- 「未完成」按状态字典 `kind` 判定（`kind ∉ {done, deprecated}`），复用服务端已有的 STATUS-3 口径（`issue.ts:586-600`），不硬编码状态名，自定义状态自动归类。
- 「无主」= `claimed_by` 为空。
- `--all-status` 保留改造前的「全区全状态」旧口径；`--status <名>` 仍显式覆盖。
- 过滤在服务端做。CLI 现在拉全量再本地渲染（`listTasks.ts:215-222`），阈值上调后分页与性能都会失真。
- 切默认时 stderr 打一行说明，不静默。

用途定位：这是**派活池**（能领的卡），不是欠账清单。待验收与「进行中且无主」的脏卡走 `--status` 显式查。

### 3.3 调度续派判定

worker 回到 `inactive` 时，判据是看板状态而不是宿主状态（`inactive` 不等于完成）：

1. 占用卡仍「进行中」→ 同一实例续做同一张，不重派、不清占用。
2. 占用卡已「待验收」→ 按 父卡后继 → 同父兄弟 → 被本卡 `blocks` 已解除的后继 → 同 labels/同目录 的顺序派下一张。
3. 都没有 → 重扫池子，释放绑定、换区。

「上游」在本设计里取「任务树上层与依赖图下游」，不取「前置补做」：前置卡按定义必须先完成，轮不到此时派。

### 3.4 token 优化清单（按 ROI 排序）

| 序 | 改造 | 省什么 |
|---|---|---|
| 1 | `show`/`claim` 评论默认最近 5 条 + 窗口截断，`--comments all` 兜底 | 单次读取体积 |
| 2 | `show` 描述窗口（`--description-max-chars` + 续读偏移） | 单次读取体积 |
| 3 | `claim`/`done` 返回体自带最新 status 与 claimed_by | 每卡 2 次往返 |
| 4 | `kb done --close-record` 一次完成 done + changelog +（可选）知识页引用 | 每卡 2–4 次往返 |
| 5 | `kb next` 一次给出可派卡 + 依赖/占用/相邻卡字段 | 派活 3 轮 → 1 轮 |
| 6 | `kb stats` 汇总计数替代逐数字复算 | N 次 shell → 1 次 |
| 7 | `show` 多 id 一次读取 | 验收批量核对 |
| 8 | 表格默认 5 列，全列走 `--full` | 单次输出体积 |
| 9 | `decisions --issue` 走服务端精确过滤 | 200 条前缀扫描 |
| 10 | 技能口径去重（CLOSE-RECORD / 回读 / 提交纪律集中到 `using-agentboard`） | 每次加载的上下文 |
| 11 | 派发 prompt 的知识块改为给 id/link，正文按需读 | 每次派发的 prompt 体积 |

第 5、6 条是新增命令，契约单独定；其余是既有命令的接线与合并。

### 3.5 知识库写入技能（kb-curator）

- 取数：抓链接内容复用 `web-scout`，不重写抓取。
- 粒度：**一个主题一页**。新链接作为该主题页的新证据追加（`revise` 追加 sources + 正文增量），只有判定为新领域才 `create`。
- 判定重复主题必须先查：`kb knowledge list --status all --include-expired`。
- 入库前必须征询用户；`--category` 显式给出，`sources`/`evidence` 各 ≥1。
- 快速查找复用既有 FTS5 检索（`kb knowledge search`，trigram 分词，中文子串可命中），不新增检索设施。
- 新增技能必须同步四处清单：`AGENTS.md` 技能索引与份数、`scripts/package-portable.mjs` 的 `REQUIRED_SKILLS`、`scripts/verify-rules.mjs` 同名常量、`scripts/portable/README.txt`。

## 4. 接口与命令变更

新增：`kb next`、`kb stats`、`kb show <id...>`、`--all-status`、`--comments <n|all>`、`--description-max-chars`、`--close-record`、`decisions --issue`。

语义变更：`list-tasks` 无参口径、`done`/`claim` 输出含状态、`list-tasks --full` 对表格生效、上述命令的工作区参数可省略。

不变：状态字典与五状态、REST 已发布字段、`--json` 信封 `{items, next_offset}`、8 位短码只用于命令引用。

## 5. 风险与回滚

| 风险 | 处置 |
|---|---|
| 默认口径变更让现有脚本数字悄悄变小 | 保留 `--all-status`；stderr 明示；文档与复算示例同步改；CLI-LIST-GUARD 段更新 |
| 评论限量掩盖关键上下文 | `--comments all` 兜底；「另有 N 条」计数行；回读校验不放宽，只改取材位置 |
| `create-issue` 位置参数错位 | 命中判定确定性（走 `matchWorkspace`），不命中才当标题，stderr 提示 |
| 技能去重丢规则 | 三处逐条比对表作为验收物；先去重后跑技能自检 |

回滚：全部改动是 CLI 与文档层，回滚按 git revert 单卡提交，无数据迁移、无 schema 变更。

## 6. 验收口径

- 每张子卡自带可执行验收命令，不以「看代码像对的」结案。
- 涉及 CLI 输出体积的卡，验收必须给出改造前后同一命令的输出行数或字符数对比。
- 涉及统计数字的卡，必须能用于该卡给出的复算命令重算一致。
- 全组完成后跑一次项目既有检查（构建、类型、CLI 单测）并记录结果。
