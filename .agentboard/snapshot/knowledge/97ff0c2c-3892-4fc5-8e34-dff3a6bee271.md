# WorkBuddy 猫猫旅行状态与请求契约

- 每个请求路径用 `workbuddyBillingUrl(region, path)` 生成完整 URL；路径不从含尾斜杠的 base 手工拼接。
- 对 status、config、claim、depart 同时检查 HTTP 状态和顶层 `code === 0`。业务失败或缺少 code 时返回安全错误码。
- status 状态按来源字段处理：`arrived`/`ready` 才领取；`traveling`/`on_the_way` 表示已派出；明确 `idle` 才读取 `data.locations` 并考虑派出；未知状态不派出。
- `daily_limit_reached === true` 表示今日已达到派出上限；已实测来源响应含该布尔字段。未知值不允许派出。
- claim 与 depart 成功后都回查 status，并按来源状态确认结果。不得只凭 HTTP 2xx 报成功。
- runner 对本地已有同日成功记录的 WorkBuddy 继续查询来源和执行 `afterCheckin`，来源已签到时不重复提交签到；没有附加活动 hook 的平台保留本地早退。
