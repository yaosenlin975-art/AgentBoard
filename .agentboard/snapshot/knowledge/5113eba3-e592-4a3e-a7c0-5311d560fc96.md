## 缺陷：下沉漏搬决策/轮次表，锁判定读到空库

`localizeWorkspace` 的 scoped 表清单原本只覆盖 issue/session/message/attachment/knowledge 等，
漏掉了 `issue_decision` / `issue_decision_option` / `issue_decision_answer` / `session_turn` /
`session_step_ledger` / `approval_rule`。下沉完成、中心库删行时，`issue` 的 `ON DELETE CASCADE`
把决策三表一并带走；而 `getDbForWorkspace` 此时 `decision.target='workspace'`，
claim / PATCH 的锁判定只读工作区库——库里没有决策行，于是「有待决策锁」永远判不出来（DEC-2 锁失效）。
轮次账本与审批规则同样在中心被级联删掉后凭空消失。

## 修复口径

1. **拷贝顺序与查询同源**：`LOCALIZE_COPY_ORDER` 与 `WORKSPACE_TABLE_QUERIES` 同步增补六张表。
   子表没有 `workspace_id` 列，按父表 JOIN 过滤：
   - `issue_decision_option` / `issue_decision_answer` → `JOIN issue_decision d ON d.id = 子表.decision_id WHERE d.workspace_id = ?`
   - `session_turn` / `session_step_ledger` → `JOIN session s ON s.id = 子表.session_id WHERE s.workspace_id = ?`
   - `approval_rule` 自带 `workspace_id`，直接过滤。
2. **中心删除按 workspace 而非 issue**：`approval_rule` 的 `workspace` 档 `issue_id` 恒 NULL，
   原来按 `issue_id IN (该区卡)` 删会整行漏删，改为 `DELETE FROM approval_rule WHERE workspace_id = ?`。
3. **计数键集统一**：`LocalizeCounts` 与 `countWorkspacePayload` 增加同名键，dry-run 与真实迁移同键集；
   `UNIFIED_COUNT_KEYS` 测试常量同步，避免「dry-run 少键、真实多键」的假一致。
4. **路由按库解析**：`DecisionRouterDeps` 增 `dbForWorkspace` / `locateIssueDb` / `locateDecisionDb`。
   ask 用任务所在库；answer / withdraw / undo / extend 用「决策所在库」；`GET /decisions` 逐区读各自库后
   合并、再按 `created_at` 全局截断（否则 limit 会按单区误截）。
   **权限（workspace_member / 角色）始终读中心库**，不随业务库漂移。

## 一致性测试套路（可复用）

- 中心库只留 `workspace` 行；工作区库 raw insert 同 id 的 `workspace`，再在同库建 issue + claim。
- 注入三个解析器：`dbForWorkspace → 工作区库`、`locateIssueDb → 命中 id 才返回工作区库`、
  `locateDecisionDb → 先在工作区库 SELECT 探针`。
- 断言：ask 201 且决策只落工作区库（中心 0 行）；`GET /decisions/:id` 与 `GET /decisions?workspace_id=`
  都能读到；answer 后答案行也只在工作区库。

## 坑

- **迁移门禁拦运行中会话**：`createSession` 默认 `status='运行中'`，localize 会报
  「该工作区有运行中的会话，请先结束后再迁移」。测试里建会话必须显式 `status: '已结束'`。
- `session_turn.state` 有 CHECK，合法值仅 `running/awaiting_input/awaiting_approval/failed/done/stopped`；
  测试造数写 `'completed'` 会直接约束失败。
- 本地全量并行跑 `workspaceLocalize*` 用例会因 5s 默认超时假红（FS + SQLite 争用），
  单独跑同样用例 2–5 秒全过。判断回归前先单跑该文件，别把超时当逻辑失败。
