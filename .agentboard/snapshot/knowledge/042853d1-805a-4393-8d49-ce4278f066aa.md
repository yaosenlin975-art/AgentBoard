## 2. 问题清单

### A. 功能缺失
- A1 CLI 无通用改状态命令：`kb update` 不含 status，`reopen --to` 只对已关闭/已废弃生效 → 自定义状态与「已废弃」无法从待规划直接置入。服务端 `updateIssueSchema` 已有 `status` 字段（apps/server/src/api/schemas.ts:201），CLI 未暴露。
- A2 MCP 缺 close / reopen / accept / changelog / 待决策 / 账号 / 工作区治理 / grep / 评论图片。

### B. 文档与实际不一致（均在 2026-11-07 实测复现）
- B1 任务 id 前缀：4 份技能写「只认完整 UUID」，实际支持 ≥8 位唯一前缀（`kb show 0f6ba9ab` 成功）。
- B2 `kb show` 已读游标：技能写「会推进」，实际默认只读，需 `--mark-read`。
- B3 `--json` 失败形态：技能写「纯文本 stderr」，实际 stdout 输出 `{"error":{"code","message"}}`。
- B4 claim 门禁：技能写「只对『待规划』」，实际接受「待规划 或 进行中且无人占用」。
- B5 close 释放：技能写「占用中 409」，实际 ACTOR 等于占用者时自动释放自有占用。
- B6 退出码：技能写「3 参数非法」，实际 3 仅 `dep` 专用，全局参数错误是 1。
- B7 `create-issue` 无 `--description-stdin`（writing-task 建议使用该参数）。
- B8 技能速查表漏收 15 个已注册命令组。
- B9 AGENTS.md / 打包脚本统一按 6 个技能，skills/ 实为 7（brainstorming 未纳入便携包）。
- B10 README 无 MCP 入口，MCP 客户端配置只存在于设计稿。

### C. 参数 / 退出码问题
- C1 `kb list-spaces` 表格输出 8 位短 id，`--workspace` 不认前缀 → 照抄即失败（任务 id 认前缀，工作区 id 不认，规则不一致）。
- C2 工作区不存在时无候选列表、不提示可用形式。
- C3 无子命令的父命令（`kb shortcut` 等）打印帮助到 stderr 并 exit 1，与 `--help` exit 0 不一致。

### D. MCP 未覆盖
- D1 MCP 25 工具（任务 13 / 依赖 3 / 状态 3 / 知识 6），缺 A2 所列能力。
- D2 alias 使工具清单翻倍（50 条），MCP-NAMING 已决定保留至下个大版本，需明确移除卡号。
- D3 无 README/CLI 入口暴露 MCP 工具清单。
