# kb done --close-record 一次完成收尾（OPT-09）

## 用法

```
kb done <id> --close-record --changelog-title '<标题>' --type 新增|修复|调整 \
  [--changelog-body '<正文>'] [--knowledge-page <已有页 id>] \
  [--notes-stdin] [--scope <路径>]...
```

## 变更日志门禁（SK-05，R4-01 起三条任一放行）

带 `client: 'cli'|'mcp'` 的 done 才校验；不满足任一条 → 400 `CHANGELOG_ACK_REQUIRED`，done 不执行、状态不变：

1. 库中已有本卡日志：`workspace_change_log.issue_id = 本卡 id` 且 `created_at >= issue.claimed_at`（claim 之前写的旧日志不算）。对应 `kb changelog create --issue <卡 id>` 后普通 `kb done`。
2. 请求显式 ack：`changelog_ack: true`（`--close-record` / `--no-changelog` 都会置 true）。`--close-record` 现在写入本卡 `issue_id`。
3. 请求带 `changelog_id`（MCP `complete_task` 传入）：校验该日志存在且属于本工作区，不存在 → 400 `CHANGELOG_NOT_FOUND`。

要点：门禁查**中心库**（changelog 路由挂 `deps.db`），issue 行查请求解析后的工作区库 `rdb`；`issue_id` 列可空、不建外键（issue 可能已下沉工作区库）。REST 直调不带 `client` 仍不受门禁影响。

## 执行顺序（关键取舍）

1. **参数前置校验**（零请求）：`--close-record` 必须带 `--changelog-title` 与 `--type`（新增/修复/调整）；配套参数在缺少 `--close-record` 时直接报错，避免「看起来写了、其实没写」。
2. **知识页只读校验**：给 `--knowledge-page` 时先 `GET /api/knowledge/resolve?scope=both&workspace_id=…&ref=…`，确认页存在；失败则中止，done 不执行。**只挂引用不新建页**，页正文仍由执行者自己先创建。
3. **先写 changelog**（`POST /api/workspaces/<ws>/changelog`），再发 done。这样保证「卡进入待验收时 changelog 已经存在」，不会出现「卡 done 了但 changelog 没写」。
4. **done**：notes 自动追加一行 `close-record: changelog=<id> knowledge=<id|（未提供）>`；正文默认复用 notes（`--changelog-body` 可覆盖），notes 为空时写「本轮无用户可见变更」。

## 失败语义

- changelog / 知识页失败 → 退出码原样（多为 1），stderr 明示「changelog 未创建 / 知识页不可解析，done 未执行」，**卡状态不变**。
- changelog 成功但 done 失败（如 409）→ stderr 明示「close-record 部分完成：changelog 已创建（<id>）；done 未执行」，按 done 原有处置重试。
- 幂等：同一 `--request-id` 重试时，changelog 使用由该 id 派生的稳定 UUID（sha256 派生的 v5 形态）作 Idempotency-Key，done 仍用原 id——两者不共用 key（服务端幂等键按 request_id + workspace_id 存，共用会串结果），重试不会产生重复 changelog。

## 未做（边界）

- 不改变 CLOSE-RECORD 的必填要求：知识页仍需执行者先建，`--knowledge-page` 只是引用。
- 不自动生成知识页正文；不合并验收类评论；`--close-record` 与 `--close` 可叠加，行为各自独立。
- 门禁只认「本卡归属 + claim 之后」，不校验日志正文与卡改动是否相关（语义关联靠人审）。
