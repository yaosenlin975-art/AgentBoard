# AgentBoard 前端使用教程 设计稿

## 1. 意图与为什么

AgentBoard 能力已经铺开（看板、待决策、任务树、知识库、日志、聊天、专家组、账号签到、设置、CLI/MCP），但终端用户没有一份「照着做」的入口：不知道按钮在哪、点完会发生什么、状态什么时候会变。

本设计要交付的是一套**前端内、随时可打开、按步骤教学**的教程，教「具体怎么操作」，不是功能罗列。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 左栏常驻入口「教程」，任何时候一键打开，不依赖后端数据。
2. 覆盖 11 个主题：快速上手、任务看板、卡片详情与依赖、待决策、任务树、知识库、日志、聊天、专家组、账号与签到、设置、进阶 CLI/MCP。
3. 每章结构统一：一句话目标 → 编号步骤（引用**真实**按钮/菜单/字段名）→ 预期看到什么 → 「去该视图」跳转按钮。
4. 内容数据驱动：一章一个文件，新增/修改章节不需要改渲染组件。
5. 只复用现有设计令牌 `--ab-*`（`bg-surface-*` / `border-hairline` / `text-ink*` / `text-accent`），浅色深色都可读。
6. 可测试：vitest + @testing-library/react，断言章节齐全、步骤非空、跳转真实生效。

**非目标**

- 不做分步高亮 / spotlight 遮罩（需要跨组件埋锚点，元素缺失即断，只能覆盖一条路径）。
- 不做首次进入强制弹窗（打断用户）。
- 不做视频、截图素材、i18n、按用户持久化阅读进度。
- 不改任何后端契约、不加 REST/WS/DB。

**反目标（做到也算失败）**

- 教程里出现界面上不存在的按钮名（编造）。
- 只列功能名词、没有可执行步骤。
- 引入新的视觉体系（新主色、新字体、新圆角、新阴影语言）。

## 3. 约束

- 前端栈：React 18 + Vite + TypeScript + TanStack Query；导航状态在 `apps/web/src/state/navStore.ts`（zustand + localStorage）。
- `NavView` 是单值枚举，以下四处是 `Record<NavView, …>` 或精确断言，必须同步改：`navStore.ts` 的 `NAV_VIEWS`、`SideBar.tsx` 的 `ENTRY_ICON` / `ENTRIES`、`App.tsx` 的 `CHAT_EXIT_LABEL`、`test/navStore.test.ts` 对 `NAV_VIEWS` 的精确数组断言。
- 仓库 UTF-8 无 BOM；`apps/web` 的 `pretest` 会跑 `scripts/check-bom.mjs`。
- 验收命令：`pnpm --filter @agentboard/web test`、`pnpm --filter @agentboard/web build`。
- 不重启 8787；界面验证走测试页 `pnpm dev:test-page` → `http://127.0.0.1:5174/`（只读走查）。

## 4. 方案对比

| 方案 | 形态 | 优点 | 代价 |
| --- | --- | --- | --- |
| A 独立「教程」视图 | 左栏主入口第 7 项，主区整屏；左侧章节目录 + 右侧正文 | 容量大、可深链（`view=guide`）、复用现有 lazy view 模式、易测试、不挤压现有界面 | 需离开当前视图（用「去该视图」一键跳回）；多一个导航项 |
| B 帮助抽屉 | `DrawerPanel` 增加 `guide` 抽屉，右侧滑出 | 随时打开不离开当前视图，复用抽屉三态 | 宽度受限，命令表/步骤拥挤；与账号/设置互斥；抽屉状态不持久化；内容一多就难读 |
| C 首次进入分步高亮 | spotlight 引导 | 就地教学、参与感强 | 需在十余个组件埋锚点 + 缺失降级；只能覆盖单条路径，覆盖不了 11 章；测试与维护成本最高 |
| D A + 首次轻提示 | 在 A 上加一次性「新来的？看 5 分钟上手」提示条 | 兼顾发现性 | 多一个 localStorage 键与置灰/关闭逻辑 |

**推荐：A**，把 D 留作后续可选卡；B、C 不做。

理由：本任务的核心矛盾是「覆盖全部能力 + 步骤要能照做」，内容体量决定了需要整屏与目录；A 的实现面最小，完全落在现有「导航视图 + 右栏」架构里，不新增交互模型。C 的维护成本与教程内容量成正比，但收益只覆盖一条路径，不划算。

## 5. 入口与信息架构

- `NavView` 增加 `'guide'`。
- 左栏主入口（`ENTRIES`）顺序：任务看板 / 待决策 / 任务树 / 知识库 / 日志 / 聊天 / **教程**。
- 视图标题「使用教程」，副标题「按章节照着做；每节末尾可直接跳到对应界面」。
- 布局：≥1024px 两栏，左 220px sticky 目录（章节列表 + 章号），右正文 `max-w-[72ch]`；<1024px 目录变顶部横向 chip 可滚动，正文单栏。
- 目录点击用锚点滚动（`scroll-margin-top` 留出顶栏高度）；首版不做滚动高亮（避免 IntersectionObserver 的额外状态与测试面）。
- 每章末尾 `goTo` 按钮调用 `setView(target)`，直接跳到真实视图。

## 6. 内容大纲（逐章；括号内为已核对过的真实界面元素）

**0 五分钟上手**：选择/新建工作空间（左栏）→ 看板列头「+」新建任务 → 卡片「派发任务」→ 聊天里看进度 → 会话头「标记待验收」→ 状态 chip 选「已关闭」或 `kb close`。

**1 任务看板**：顶栏「选择」进入两段式批量选择；选择模式下点列头复选框「选择本列全部任务（待规划）」；「移动到状态…」「应用」「退出选择」；「显示密度：舒适密度/紧凑密度」；「分组方式：不分组/按标签分组」（按标签分组时禁用拖拽）；搜索框「搜索标题/描述/标签」；标签筛选；拖拽换列（占用中/待决策锁定不可拖）；列头「+」与排序控件；进行中列「退回运行中任务到待规划」；退回结果条「仅看本次退回（N）」。

**2 卡片详情、派发与依赖**：点卡片打开右侧详情；状态 chip「点击修改状态」；「优先级 · 中」；「截止 · 未设置」；标签 chips；负责人「未领取/名称 · 时长」；「派发任务」→「派发设置」弹窗（知识参考、历史图片、CLI、模型、新建会话/续用最近会话、Prompt 模板）→「确认派发」；「释放任务」；⋯菜单（复制任务 ID/删除任务）；依赖区「前置 N · M 项未解除 · 阻塞 K」「添加前置（当前工作区内搜索）」；评论「追加评论（markdown）」+「发送」；「添加图片」。

**3 待决策**：顶部汇总条「有 N 条待决策」；筛选 tab 全部/宽限中/待回答/已超时/已回答；卡片倒计时「剩 X」「即将落锁」；选项 chip 直接点选，或「✎ 自定义」写一句；「＋1 分钟」；「改答案」「撤回决策」；「展开/收起」；跳转「打开任务卡 ↗」；落锁后显示「已锁 N」并冻结卡片拖拽。

**4 任务树**：筛选「全部状态」、勾选「隐藏无子任务」；+/− 展开收起；行内「+ 子任务」「移动」；锁图标「存在 N 项未解除的前置任务」；「后代进度 x/y 已关闭」；「关闭前需先关闭全部后代任务」。

**5 知识库**：「列表 / 星图」切换；范围「当前项目＋公共 / 当前项目 / 公共经验」；搜索；「添加」导入 .md/.txt/.json；无限滚动到底自动加载（「已到底 · 共 N 条」）；知识页「编辑正文（含图片）」「归档/恢复/软删除」「导出 Markdown / 导出 PDF」；版本历史抽屉「查看 diff」「恢复此版本」；星图「适应视图」「搜索节点」「只看未落地设计」「内容类型/作用域」着色，右键「打开详情/复制页链接/聚焦该节点的邻居」。

**6 日志**：「新增日志」；筛选（关键字、类型「全部类型/新增/修复/调整/历史」）；时间线点条目看正文；「编辑 / 删除」。

**7 聊天**：会话列表顶部「＋ 新建会话」（CLI、模型可留空、工作空间必填、智能体人设可选）→「创建」；行内悬停「✎」改名、「✕」删除（「确认删除」）、「归档/恢复」、「⎇」分叉；输入区「＋」加附件（单个 ≤10 MiB）、输入 `/` 选技能、`@` 选任务、Enter 发送 / Shift+Enter 换行；长按输入框 400ms 说话、松手插入、Esc 取消（需在设置开启语音）；会话头「停止」「标记待验收」；⋯→「会话设置」「审批规则…」；工具调用弹窗「工具调用需要确认」+ 三档「仅本次/本任务/本工作区」+「允许」「拒绝」；计划条。

**8 专家组**：「新建专家组」（团队名称、lead 会话）→「创建」；「添加成员」（成员名/角色/默认 CLI）；成员状态「空闲/进行中/已交付/失败」；lead 在聊天里写 `@成员名: 任务` 派活；「token 用量 x / y」；「停止团队」。

**9 账号与签到**：「添加账号」→ 选择供应商（WorkBuddy/MiniMax/Trae/Qoder CN/ZCode/DeepSeek/Codex）→「授权添加」或「读取本机」→「开始授权」→「检查授权结果」；顶栏「一键签到」；批次卡状态与条目「签到成功/今日已完成/签到失败/结果未知」；「猫猫旅行：已派出/已领取/今日已完成/失败」；账号卡「切换」「补齐本机登录态」「停用/删除」。

**10 设置**：「主题」浅色/深色/跟随系统；「智能体人设」→「＋ 新建人设」/「从专家包导入」，编辑抽屉内「智能创建」「一句话生成草稿」「生成草稿」；「配套技能同步」→「复制所选（N）」，冲突时「覆盖/跳过/备份后覆盖」；「MCP（模型上下文协议）」→「复制配置」；「语音输入」启用 + 400ms 说明；「数据存储」迁移；「服务重启」。

**11 进阶 CLI / MCP**：`kb list-spaces`、`kb create-issue`、`kb list-tasks`、`kb next`、`kb claim`、`kb show`、`kb comment`、`kb done`、`kb accept`、`kb close`、`kb stats`；MCP 定位：本机 stdio 服务，只经 `http://127.0.0.1:8787/api` 调现有 REST，给 Codex/DSH/WorkBuddy 等客户端接入。

## 7. 组件结构与数据模型

```ts
// apps/web/src/components/guide/types.ts
export type GuideBlock =
  | { kind: 'steps'; items: Array<{ do: string; result?: string }> }
  | { kind: 'note'; tone?: 'info' | 'warn'; text: string }
  | { kind: 'code'; lines: string[] };

export interface GuideChapter {
  id: string;          // 锚点 id，如 'board'
  order: number;       // 排序
  title: string;       // 章标题，如 '任务看板'
  intro: string;       // 一句话目标
  blocks: GuideBlock[];
  goTo?: { view: NavView; label: string };
}
```

- 内容文件：`apps/web/src/components/guide/chapters/*.ts`，每章一个文件导出 `chapter`。
- 聚合：`GuideView.tsx` 用 `import.meta.glob('./chapters/*.ts', { eager: true })` 收集并按 `order` 排序；**避免多张卡共改同一文件**（RULE-2）。
- 渲染：`GuideView.tsx`（目录 + 章节 + 跳转）与 `GuideChapter.tsx`（单章渲染，可选拆出）。文案中的界面元素名统一用「」包裹，不做富文本解析。
- 空态：章节数为 0 时显示「教程内容准备中」，不崩。
- 跳转：`useNavStore.getState().setView(view)`（按钮 onClick），不新增路由。

## 8. 测试与验收

- `apps/web/src/test/GuideView.test.tsx`
  1. 渲染后目录项数量与章节数一致，且按 order 排列；
  2. 每章都有 ≥1 个 `steps` 且每条 `do` 非空（防「占位章」）；
  3. 点击「去任务看板」后 `useNavStore.getState().view === 'board'`；
  4. 深/浅色不涉及逻辑，样式走令牌（不做断言）。
- `apps/web/src/test/navStore.test.ts`：`NAV_VIEWS` 期望值追加 `'guide'`；`isNavView('guide') === true`。
- 门禁：`pnpm --filter @agentboard/web test`、`pnpm --filter @agentboard/web build` 全绿。
- 界面验证：`pnpm dev:test-page` 后打开 `http://127.0.0.1:5174/`，左栏「教程」可进入，逐章滚动，跳转按钮生效，浅/深色各看一遍；不重启 8787。

## 9. 接线（RULE-3）

- 入口接线：`SideBar` 按钮 → `setView('guide')` → `App` 分支渲染 `GuideView`（真实可点，非死入口）。
- 章节跳转：`goTo` → `setView(<真实视图>)`。
- 无新增 REST / WS / ticker / CLI / 迁移，因此不需要额外外部触达证明；以构建 + 组件测试 + 测试页走查为证。

## 10. 需要用户拍板的点（现有实现与需求表述的差异）

1. **「子会话派遣」在现有前端没有独立入口**。真实存在的两种派活路径是：任务卡「派发任务」（新建/续用会话并占用任务），以及专家组 lead 在聊天里写 `@成员名: 任务`。教程按真实路径写，不编造按钮。
2. **「猫猫签到自动回收」没有前端开关/文案**。前端只在签到结果里展示 `猫猫旅行：已派出/已领取/今日已完成/失败`。教程只写「怎么看结果」，不写不存在的自动回收配置。
3. **入口位置**：推荐主入口第 7 项「教程」；备选为左栏底部「账号/专家组/设置」组之上，或设置抽屉内。
4. **是否要首次进入轻提示（方案 D）**：默认不做，需要再加卡。

## 11. 实施拆分（交 writing-task）

- 骨架卡：`types.ts` + `GuideView.tsx` + 1 章示例 + `navStore`/`SideBar`/`App`/测试接线。
- 内容卡（各占一个章节文件，互不冲突）：看板+详情+依赖 / 待决策+任务树 / 知识库+日志 / 聊天+专家组 / 账号签到+设置+CLI。
- 校对卡：逐条对照代码行号、浅深色走查、`pnpm --filter @agentboard/web test` + `build`，收尾声明「dist 未重建（测试页已验证）」。
