# 规则清单自检：包内自检脚本不可在仓库根直跑，改用最小等价自检

## 事实

- `scripts/portable/verify-rules.mjs` 用 `const APP = dirname(fileURLToPath(import.meta.url))` 定位自身目录，并只读 `join(APP, 'rules-manifest.json')`；清单不存在即 `exit 1`，无 `--help`、无路径参数、无环境变量覆盖。
- 因此在仓库根 `node scripts/portable/verify-rules.mjs` 必然失败：`[rules] 无法读取清单 <repo>\scripts\portable\rules-manifest.json: ENOENT`。它是**打包后包内自检**，由 `scripts/package-portable.mjs` 复制到包内 `app/` 并生成同名清单后才可跑。
- 该脚本还要求 `APP/cli/index.js` 能跑 `--help`，仓库态下没有这个布局，纯靠造目录也跑不通。

## 不可或缺的规则文件（打包侧唯一事实来源）

`scripts/package-portable.mjs` 与 `scripts/portable/verify-rules.mjs` 各有一份同名常量：

`REQUIRED_SKILLS = ['using-agentboard','writing-task','executing-task','handoff','swing-dev','ask-user','brainstorming']`，

加上 `AGENTS.md`、`README.md`、`Docs/api.md`，共 **10 个文件**。

注意：`brainstorming` 是第 7 个必需技能（SKILL-PKG，卡 `ebf65000`）；`ask-user` 是第 6 个（DEC-5）。任何「6 个技能 / 6 个必需技能 / 共 9 个文件」的表述都已过期（2026-11-07 收口，卡 `9a2a81af`）。两份常量必须逐字一致，只改一处等于没改。

## 仓库内的最小等价自检（改完 skills/** 或上述 3 个文档后跑这个）

```bash
node -e "const fs=require('fs');const S=['using-agentboard','writing-task','executing-task','handoff','swing-dev','ask-user','brainstorming'];const f=['AGENTS.md','README.md','Docs/api.md',...S.map(s=>'skills/'+s+'/SKILL.md')];let b=0;for(const x of f){const ok=fs.existsSync(x);if(!ok)b++;console.log((ok?'OK  ':'MISS')+'  '+x)};console.log('缺失 '+b+' 个');process.exit(b?1:0)"
```

退出码 0 且 10 行全 `OK` 才算规则集齐全；它不校验 sha256 与 `kb --help`，因此只支持「文件齐全」这一结论，不支持「包可发布」。

## 验证边界

- 要得到 sha256/`kb --help` 层面的结论，只能跑 `pnpm package:portable`（会写 `dist-package/`，属打包卡的范围）；仅改文档的卡不去动它。验证时可加 `--skip-build --no-zip --out <临时目录>` 缩短耗时，步骤 4–5（携带规则 + 包内自检）与全量一致。
- 改 md 后仍先跑 `node scripts/check-bom.mjs`（新增 BOM 即 exit 1，存量豁免见 `scripts/bom-baseline.txt`）。
- 新增/删除技能时同步四处清单：两份 `REQUIRED_SKILLS`、`scripts/portable/README.txt` 的携带清单与自检输出示例、`AGENTS.md` 技能索引与「对外打包约束」，以及根 `README.md` 的打包小节。
