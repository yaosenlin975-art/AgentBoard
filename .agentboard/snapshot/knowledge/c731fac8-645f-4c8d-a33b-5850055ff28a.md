# WPA 破解工具链：驱动能力边界、算力路径与 runtime 预算

## 结论速查

| 决策点 | 结论 |
|---|---|
| 网卡选型 | RTL8192FU / AX210 均不能注入，只能被动抓；要 deauth / WPS 必须换 MT7612U / AR9271 / RTL8812AU |
| 算力路径 | GPU 爆破只能在 Windows 原生或 WSL2 跑；VMware / VirtualBox 无 GPU 计算直通 |
| 抓包路径 | 必须 Kali 原生；VM 里 hcxdumptool 不可靠 |
| runtime 预算 | 必须含冷启动下限，`clamp(ceil(eta*1.2), 60, 14400)` |
| 自检 | 用自算 PMKID 造 hash 验证链路，不依赖任何无线硬件 |

## 一、驱动能力边界（决定能不能打，不是打多快）

### RTL8192FU（USB 0BDA:F192，水星 MERCURY Wireless N）

- 2.4GHz 单频。Windows `netsh wlan show drivers` 可能误报「2 个频段」，但 radio types 只有 b/g/n，以 radio types 为准
- Linux 内核 6.5 起内建 `rtl8xxxu` 支持，无需第三方驱动
- 监听模式可用；帧注入不可用（`rtl8xxxu` 无注入实现）
- 可做：被动抓四次握手、被动收 PMKID；不可做：deauth、WPS Pixie Dust、Evil Twin
- Debian 12 系（默认内核 6.1）识别不到，需 backports 内核或第三方 DKMS

### Intel AX210（PCIe 8086:2725，iwlwifi）

- 监听可收包；固件不支持帧注入，hcxdumptool 直接拒
- 通常同时是唯一联网出口，`airmon-ng check kill` 会杀掉 NetworkManager 直接断网

### 芯片识别口径

Windows 侧唯一可靠处：设备属性的硬件 Id（VID/PID），或 `netsh wlan show drivers` 的 INF 与 Provider。品牌名无用——同一型号不同硬件版本会换芯片，PID 才是判据。Linux 侧用 `lsusb -v` / `lspci -nn` 看 ID。

## 二、算力路径

- WPA 是 PBKDF2-HMAC-SHA1 4096 轮，纯 ALU 密集、几乎不吃带宽；eGPU 的 PCIe x4 通道损失 <2%，可忽略
- 带宽不是瓶颈，密钥空间才是
- hashcat 默认只枚举 GPU 后端：Linux 上要 `pocl-opencl-icd` 才有 CPU 后端，Intel 核显要 `intel-opencl-icd`，缺任一则该设备不参与计算
- RTX 50 系（Blackwell，`sm_120`）需 CUDA 12.8+ 与 hashcat ≥ 7.x；老版本报 `No devices found` 或 PTX 编译失败

实测量级（`-m 22000`）：

| 设备 | 速率 |
|---|---|
| Radeon 780M（RDNA3 12CU，`-w 3`） | 131.2 / 147.8 kH/s（实测） |
| Ryzen 7 8840U CPU（8C/16T） | 约 60–90 kH/s（估算） |
| Comet Lake-U 核显 + CPU 并联（NUC10） | 约 40–70 kH/s（估算） |
| RTX 5070 Ti | 约 0.9–1.3 MH/s（估算，未实测） |

## 三、runtime 预算必须含冷启动下限

`--runtime <sec>` 从进程启动即开始计时，而 hashcat 单次冷启动（OpenCL 后端初始化）需 3.5–4.1 秒。

按候选数算出的 runtime 低于冷启动时间时，该阶段会在初始化完成前被终止：

- `--runtime 1` 冷态 → rc=4，无命中
- 同一参数在内核缓存已热时偶发能出结果 → 表现为「偶发白扔」而非稳定失败，最难排查

校准公式：

```
runtime = clamp(ceil(预计耗时 * 1.2), 60, 14400)
```

- 下限 60s：覆盖 3.5s 冷启动 + 约 56s 计算窗口
- 上限 14400s：单段 4 小时封顶
- 预计耗时 ≥ 17.5s 时 1.2 系数本身已覆盖冷启动，无需另加常数

覆盖率统计必须区分两种失真：

- 下限抬升 = 估算不可靠（该段耗时以启动开销为主）
- 上限截断 = 算力不够（须给出实际覆盖百分比）

## 四、射频坑

USB 3.0 端口与线缆在 2.4GHz 附近有宽带噪声，可让低成本 2.4GHz 网卡灵敏度掉 5–10 dB，表现为「扫不到远处的 AP」。

对策：插 USB 2.0 口，或用 USB 2.0 延长线把网卡移到离机身 20cm 以外。不要用 USB 3.0 口。

## 五、零硬件自检（建议固化成脚本）

不依赖任何无线设备即可验证「hashcat 能正确破解 WPA」这条链：

```
PMK   = PBKDF2-HMAC-SHA1(password, essid, 4096, 32)
PMKID = HMAC-SHA1(PMK, "PMK Name" || AP_MAC || STA_MAC)[:16]
```

按 hashcat 22000 格式写出：

```
WPA*01*<pmkid>*<apmac>*<stamac>*<essid_hex>***
```

MAC 用小写十六进制无分隔符，ESSID 用十六进制编码。配只含正确口令的字典，解出后断言明文相等。

反向对照必做：同一 hash 配错误字典必须解不出（rc=1 且无 outfile）。否则是空跑通过，不能证明链路有效。

## 六、Windows 侧 hashcat 调用约束

- 必须从 hashcat 自身目录运行：OpenCL 内核目录是相对路径，否则报 `./OpenCL/: No such file or directory`
- 全局包装器只能 pushd 到该目录再执行；副作用是命令行里的相对路径参数全部失效，字典与 hash 文件必须传绝对路径
- `ADL2_Overdrive_Caps(): -8` 是 AMD APU 的 Overdrive 接口不支持，无害，可忽略
