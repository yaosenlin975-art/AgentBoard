# done 收尾的设计页 landed 回改门禁

## 结论

- `kb done` 在写 changelog / 改状态之前先做只读检查：本卡及其父链通过 `issue:<uuid>` 引用到的 `category=design` 知识页，若仍为 `landed=proposed` 且状态 `active`，则直接失败退出 1，done 与 changelog 都不执行。
- 两个合法出口：`kb knowledge revise <页 id> --landed landed|partial --expected-revision <rev>`，或 `kb done ... --design-not-advanced`（把「本卡不推进设计（页 id）」写进 notes，跳过门禁）。

## 实现要点

- 关联判定只看知识页当前 revision 的 sources / evidence：约定非文件证据用 `issue:<uuid>` 前缀（见 `kb knowledge create --help` 的说明）。
- 必须走父链：设计页常挂在父设计卡上，只看本卡会漏拦；父链有循环保护（上限 32 层）。
- 列表接口先筛 `category=design && landed=proposed && status=active`，再逐页取详情核对引用；列表与详情之间被归档/删除（404/410）直接跳过，不阻塞收尾。
- 只对 UUID 形态的卡启用门禁；8 位前缀在 done 入口已先 `normalizeIssueRef` 成完整 UUID，非 UUID 引用（如导入占位）保持旧行为。
- 不自动改 landed、不改 revise 的 CAS、不拦 pending / non-design 页。

## 验证

- `packages/cli/test/lifecycle.test.ts` 新增 6 例：proposed 拒绝并给两选项、revise 后 done 通过且 show 回读 landed、partial 放行、`--design-not-advanced` 写 notes、与 `--close-record` 共存、无关联页行为不变。
- `pnpm --filter @agentboard/cli test` 450/450 通过；`tsc -p tsconfig.build.json --noEmit` 通过。

## 注意

- 门禁只认 `issue:` 前缀的引用；用 `--knowledge-page` 仅把页挂进 notes，不会自动产生引用，也不会被门禁识别。
