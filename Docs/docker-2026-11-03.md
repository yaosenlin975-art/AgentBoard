# Docker 单容器部署（DOCKER-3）

镜像只依赖两个运行时约定：`AGENTBOARD_DB` 指向 `/data` 下的库文件，附件目录由它派生为 `/data/attachments`（DOCKER-2）；
监听地址由 `AGENTBOARD_HOST` 在镜像里放宽为 `0.0.0.0`（DOCKER-1，本机默认仍 `127.0.0.1`）。

## 1. 三条命令

```bash
docker build -t agentboard:local .
docker run -d --name agentboard --restart unless-stopped -p 8788:8787 -v agentboard-data:/data agentboard:local
curl -fsS http://127.0.0.1:8788/api/version
```

- `-p 8788:8787`：宿主 8788 映射容器 8787。**宿主 8787 常被本机服务占用**，容器冒烟请换端口。
- `-v agentboard-data:/data`：命名卷，DB 与附件都在里面。
- `--restart unless-stopped`：容器内没有 `kb autostart` 的桌面语义，用重启策略代替。

## 2. bind mount 变体

```bash
mkdir -p /srv/agentboard
docker run -d --name agentboard --restart unless-stopped \
  -p 8788:8787 \
  -v /srv/agentboard:/data \
  agentboard:local
```

- Linux 宿主注意目录归属：容器以 root 运行，`/srv/agentboard` 需要容器可写（`chown 0:0` 或交给 root）。
- Docker Desktop（Windows/macOS）走 virtiofs/gRPC-FUSE，SQLite WAL 在该挂载上的锁行为未实测（见 §5）。

## 3. 冒烟 6 步

```bash
docker build -t agentboard:local .
docker run -d --name agentboard -p 8788:8787 -v agentboard-data:/data agentboard:local
curl -fsS http://127.0.0.1:8788/api/version                 # 1) 宿主可访问
curl -fsS -X POST http://127.0.0.1:8788/api/workspaces \
  -H 'Content-Type: application/json' \
  -d '{"name":"smoke","path":"/tmp/smoke"}'                  # 2) 建工作区
curl -fsS -X POST http://127.0.0.1:8788/api/issues \
  -H 'Content-Type: application/json' \
  -d '{"workspace_id":"<上一步 id>","title":"smoke issue"}'   # 3) 建卡
docker restart agentboard                                    # 4) 重启
curl -fsS "http://127.0.0.1:8788/api/issues?workspace=<id>"  # 5) 数据仍在
docker inspect --format '{{.State.Health.Status}}' agentboard # 6) HEALTHCHECK=healthy
```

清理：

```bash
docker rm -f agentboard
docker volume rm agentboard-data
docker rmi agentboard:local
```

## 4. 回滚

镜像只是外层，数据在卷里，回滚不影响宿主本机安装：

1. 停掉并删除容器：`docker rm -f agentboard`（**不要**删卷，除非确认数据不再需要）。
2. 需要换回旧镜像：`docker run ... -v agentboard-data:/data <旧 tag>`；卷内容向后兼容（同一 DB schema）。
3. 要彻底回到非容器运行：宿主 `pnpm -r build && node apps/server/dist/index.js`，DB 仍用 `%APPDATA%\AgentBoard\agentboard.db`；
   若要把容器数据搬回来，`docker cp agentboard:/data/agentboard.db <宿主路径>/agentboard.db` 后把 `AGENTBOARD_DB` 指过去即可（附件目录会跟着派生）。
4. 卷备份：`docker run --rm -v agentboard-data:/data -v "$PWD":/backup alpine tar czf /backup/agentboard-data.tgz -C /data .`

## 5. 构建与环境注意

- **基础镜像拉取**：`FROM node:22-bookworm-slim` 需要能访问 `registry-1.docker.io`。直连被阻断时用 Docker Desktop 的 manual proxy，
  注意填**宿主回环**地址：`OverrideProxyHTTP/HTTPS = http://127.0.0.1:7897`（Docker Desktop 在**宿主侧**做转发，所以宿主 `127.0.0.1` 反而有效）。
  实测 `host.docker.internal:7897` 与宿主 LAN IP 都不通——本机代理进程（Clash Verge / verge-mihomo）只监听 `127.0.0.1:7897`，
  VM 侧解析到的 `192.168.137.221:7897` 与 LAN IP 均无监听。改完 `%APPDATA%\Docker\settings-store.json` 后必须重启 Docker Desktop 才生效。
- **构建上下文**：镜像里 `pnpm -r build` 依赖根 `tsconfig.base.json`（各包 `tsconfig.build.json` extends 它），Dockerfile 已显式复制。
- **better-sqlite3**：走 `prebuild-install` 预编译二进制，构建阶段**不需要** python/make/g++（Dockerfile 里那行 apt 已注释；
  网络无法下载预编译包时再放开，改用源码编译）。
- **镜像大小**：实测 `agentboard:local` = **615MB**（未做生产依赖裁剪，见 §6）。

## 6. 未做 / 未证实

- **生产依赖裁剪未做**：运行阶段整体复制 `/app`（含 devDependencies），实测镜像 615MB。pnpm workspace 的符号链接与 better-sqlite3 原生模块让裁剪需要额外验证；
  本轮优先保证镜像可跑；后续可用 `pnpm deploy` 或 `pnpm prune --prod` + 重建 symlink 收口。
- **WAL on bind mount**：Docker Desktop 的 virtiofs 下 SQLite 锁行为未实测（本机冒烟用命名卷，`/data` 下 db + db-wal + db-shm 正常）。
- **容器内桌面能力**：WorkBuddy/MiniMax 桌面快照、客户端进程启停、`kb autostart`/`kb shortcut`、agent 派发、GIT-ON-DONE 自动提交
  均不在镜像内（见 `Docs/research-2026-11-03-macos-docker-readiness.md` §6）。
- **跨平台数据库互换**：账号表含平台相关密文（Windows DPAPI），容器与 Windows 宿主的账号数据不可直接互换。
- **本机冒烟范围**：Windows 11 + Docker Desktop 29.9.2（linux/amd64）。macOS（Apple Silicon）与 linux/arm64 未实测。
