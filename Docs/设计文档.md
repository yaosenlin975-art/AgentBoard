# AgentBoard 设计文档（暂名）

日期：2026-10-31
状态：已确认（六节设计审阅通过；DeepSeek、聊天界面、UI 布局、任务详情与派发、评论区参考 multica 并入）

## 1. 需求分析

| # | 需求 | 来源约束 |
|---|---|---|
| 1 | 基于文件夹创建工作空间，各工作空间的 issue 分开管理 | 工作空间 = 任意本地文件夹，不强制 git 仓库 |
| 2 | 自动识别本机已安装的 Agent CLI | 首发适配：codebuddy、codex（OpenAI）、opencode、dsh（DeepSeek harness） |
| 3 | 配套供 Agent 调用的 CLI 和 skill | CLI + SKILL.md 首版；MCP server 二期 |
| 4 | issue 拖拽改变状态：待规划 → 进行中 → 待验收 → 已关闭 | 允许拖回（含已关闭重开） |
| 5 | 内置与 Agent CLI 聊天的界面，可选 agent CLI 及内部模型 | 模型列表动态探测，失败降级（见 §4.2） |
| 6 | 任务占用状态，防止多个 agent 领取同一任务 | 显式领取 + 手动释放（见 §5.4） |
| 7 | 任务详情内置评论区：agent 写总结、用户留言、人机互评（参考 multica） | 用户评论可唤醒占用 agent（见 §5.8） |

使用假设：单机单用户，Windows 优先；agent 执行任务时工作目录 = 工作空间文件夹；issue 含标题/描述/优先级/标签；验收由人工完成。

## 2. 方案选型

| 决策 | 结论 | 备选与取舍 |
|---|---|---|
| 底座 | 完全自研，借鉴开源设计不抄码 | vibe-kanban 功能最全但 Rust+官方退场；Backlog.md 缺聊天/锁；ai-agent-board 骨架窄。无候选覆盖全部 6 条需求 |
| issue 存储 | 中央 SQLite（better-sqlite3，WAL 模式） | markdown-in-workspace 模式锁实现复杂；混合模式需双份状态同步。SQLite 事务天然保障原子领取 |
| 应用形态 | 本地 Web 服务 + 浏览器 | Electron 首版不引入；核心稳定后可再套壳 |
| 技术栈 | TypeScript 全栈，pnpm monorepo | 一套语言覆盖 server/前端/CLI，便于并行开发 |
| 聊天集成 | 优先直连各 CLI 无头模式的结构化输出流 | coder/agentapi 的 PTY→HTTP 方案已归档，仅作设计参考；首发四家 CLI 均有结构化流式，PTY 兜底不进首版 |
| 会话执行模型 | 每轮对话 = 一次无头进程调用 + 会话 resume | PTY 常驻注入实现复杂且脆；opencode 长连接混合模式两套会话管理，留作后续优化 |
| 任务内容获取 | agent 以 issue id 经 `kb show` 拉取最新内容，不依赖派发快照 | 支持占用期间用户继续编辑任务 |
| 评论唤醒 | 参考 multica：评论即唤醒通道，占用中用户评论触发 agent 一轮 | 评论区与聊天共用队列规则，服务端单一入口防重复触发 |

### 技术栈明细

- 服务端：Node + Express + better-sqlite3 + ws
- 前端：React 19 + Vite + Tailwind；拖拽用 dnd-kit
- CLI：同仓 TS 包，安装为 `kb` 命令，走 HTTP API
- skill：一份通用 SKILL.md，引导 agent 使用 `kb`

## 3. 数据结构（SQLite 单库）

```sql
workspace (
  id TEXT PK, name TEXT, path TEXT UNIQUE,   -- 文件夹绝对路径
  created_at INTEGER
)

issue (
  id TEXT PK, workspace_id TEXT FK,
  title TEXT, description TEXT,              -- markdown
  priority TEXT CHECK (priority IN ('低','中','高'))
    DEFAULT '中',
  labels TEXT,             -- JSON 数组，自由文本标签
  status TEXT CHECK (status IN
    ('待规划','进行中','待验收','已关闭')),
  sort_order INTEGER,
  claimed_by TEXT,        -- agent 标识；NULL=未占用
  claimed_at INTEGER,
  session_id TEXT,        -- 当前占用会话
  created_at INTEGER, updated_at INTEGER
)

issue_comment (
  id TEXT PK, issue_id TEXT FK,
  author TEXT,            -- user / agent:<cli id> / system
  content TEXT, ts INTEGER
)  -- 评论区：人机互评 + done/fail 备注 + system 事件，扁平时间线

session (
  id TEXT PK, workspace_id TEXT FK,
  issue_id TEXT NULL,      -- NULL = 自由聊天
  cli TEXT, model TEXT,
  status TEXT CHECK (status IN ('运行中','已结束','失败')),
  adapter_session_id TEXT, -- CLI 侧会话 ID（resume 用）
  created_at INTEGER
)

message (
  id TEXT PK, session_id TEXT FK,
  role TEXT,               -- user / assistant / event / error
  content TEXT, ts INTEGER
)
```

状态机：`待规划 → 进行中 → 待验收 → 已关闭`，四列间允许双向拖拽。
排队、等待槽位为运行时内存态，不入库。

## 4. Agent 适配层

### 4.1 适配器接口

```ts
interface AgentAdapter {
  id: string;                 // 'codebuddy' | 'codex' | 'opencode' | 'dsh'
  displayName: string;
  detect(): Promise<boolean>;         // where 命令 + --version
  listModels(): Promise<ModelInfo[]>;
  applyModel(opts, model): CommandArgs; // 把模型落到各自 CLI 参数/配置
  runTurn(opts: {cwd, model, prompt,
                 adapterSessionId?: string}): TurnHandle;
  // 每轮 = 一次无头进程：adapterSessionId 缺省新建 CLI 侧会话，
  // 有值则以 resume 续上下文；TurnHandle 逐行吐 stdout
  parseEvent(line): UnifiedEvent | null; // 解析 stdout 流
}
// TurnHandle 结束时产出 { exitCode, adapterSessionId }
// （各 CLI 会话 ID 在输出流中的字段位置见 §10 待实测）

type UnifiedEvent =
  | {type:'text', delta:string} | {type:'tool', name:string, input:string}
  | {type:'error', message:string} | {type:'end', exitCode:number}
```

各适配器实现要点：

| CLI | 无头调用 | 流式 | 会话恢复 | 模型选择 |
|---|---|---|---|---|
| codebuddy | `codebuddy -p "任务" --output-format json` | JSON 流（是否逐行流式**待实测**） | `-c` / `-r <id>` | `--model`（取值待实测） |
| codex | `codex exec "任务" --json` | stdout JSON 事件流 | `codex exec resume <id>` | `-m <model>` |
| opencode | `opencode run "任务" --format json`，或 `opencode serve` HTTP API | JSON 事件 / HTTP SSE | `-s <id>` / `-c` | `-m provider/model` |
| dsh | `dsh --profile headless "任务" --json` | stdout NDJSON 事件流 | `--session-id <id>`（未知 ID 报错） | **无 CLI flag**，模型只读：由 profile 配置决定（`supportsModelSelection=false`）；内置目录 deepseek-v4-flash / deepseek-v4-pro |

### 4.2 模型选择三级降级

1. 动态探测：适配器自实现（opencode 走 `opencode models`；其余探测配置/账户侧可行路径）
2. 失败回退：适配器内置静态清单，启动时探测一次并缓存
3. 手输：UI 永远允许手输模型名，经 `applyModel` 透传

dsh 模型只读：模型由 CLI profile 配置决定，能力位 `supportsModelSelection=false`；UI 禁用模型选择并标注「由 profile 配置决定」，`runTurn` 忽略传入的 model。

### 4.3 通用探测

`where <cmd>`（Windows）/`which` + `<cmd> --version`，版本解析入缓存表。dsh 为 rc 版（0.2.x，官方明示破坏性变更）：适配器带版本判断，接口不匹配时明确报错，不假设接口不变。

### 4.4 实现底座（SDK 优先）

| 适配器 | 实现底座 | 依据 |
|---|---|---|
| codex | `@openai/codex-sdk` 官方 TS SDK；不满足再退自研 `exec --json` | 官方封装 spawn + JSONL 事件 |
| opencode | `@opencode-ai/sdk` 打 `opencode serve` HTTP API，免进程管理 | 官方 SDK + OpenAPI spec（/doc） |
| codebuddy | 自研 spawn `-p --output-format json`（协议同 Claude Code 族，借鉴 vibe-kanban claude.rs 模式） | 无官方编程接口 |
| dsh | 自研 spawn `--json` NDJSON | rc 版，无官方编程 SDK |

SDK 无法产出 adapter_session_id 等设计必需信息时退回自研 spawn；退回决策在实现首个适配器里程碑时验证。文件级代码参考见 `Docs/参考代码索引.md`。

## 5. 关键流程

### 5.1 服务启动
启动 HTTP 服务（默认 `localhost:端口`）→ 扫描四家 CLI → 可用性写入缓存 → 前端顶栏显示可用 agent 徽标。

### 5.2 手动派发

**入口条件**：状态 ∈ {待规划, 进行中} 且未占用。占用中按钮显示"会话进行中"；待验收/已关闭禁用。

**派发弹窗**：
- CLI 选择：未检测到的项禁用并标"未安装"
- 模型选择：默认该 CLI 上次使用的模型，否则清单第一项；可手输
- 会话选择：该 issue 有历史会话时单选——"新建会话（默认，干净上下文）/ 续用最近会话（保留 agent 已有进度）"；续用时 adapter_session_id 沿用
- prompt 模板：textarea 预填全文可编辑，变量 `{{title}} / {{description}} / {{workspace_path}} / {{issue_id}}` 确认时渲染；模板自动追加"历史备注"段（issue_comment 最近 10 条，含上次失败原因，弹窗内可删改）；历史备注段前端预览可编辑，服务端检测已含该段则跳过追加

**默认模板固定指令**：
1. 任务内容以 `kb show {{issue_id}}` 实时返回为准，开工前与关键节点重新拉取（覆盖占用期间用户编辑任务的情况）
2. 用户在评论区的留言视为补充指令，经 `kb show` 读取最新评论
3. 关键节点（开工、受阻、阶段性完成）用 `kb comment {{issue_id}}` 写进展总结
4. 完成后执行 `kb done {{issue_id}}`，失败执行 `kb fail {{issue_id}} --reason "…"`

**确认后**：事务内 claim（§5.4）+ 创建 session → 起第一轮无头进程（工作目录 = 工作空间路径）→ stdout 流经适配器归一 → WS 推送 → 自动切聊天视图。并发槽位满（≥3）时 claim 与建会话立即生效，首轮排队并显示"等待槽位"。

**UI 兜底**：会话与任务详情提供"标记待验收"按钮，等价 agent_id='user' 调 done 接口，释放占用。

### 5.3 自助领取
agent 侧执行 `kb claim <id>` → 服务原子领取 → 返回任务详情（标题/描述/评论/工作空间路径）→ agent 干活（内容以 `kb show` 拉取为准）→ `kb done`/`kb fail` 回报。skill（SKILL.md）指导该流程。

### 5.4 占用锁（显式领取 + 手动释放）

- 领取事务：`UPDATE issue SET claimed_by=?, claimed_at=?, session_id=?, status='进行中' WHERE id=? AND claimed_by IS NULL AND status IN ('待规划','进行中')`——并发领取仅一个成功，其余返回"已被占用"；允许从"进行中"领取是覆盖"用户手动拖到进行中后再派发"的场景
- 占用中的 issue 禁止拖拽流转，服务端同样拒绝其 status 变更（返回 409）；字段（标题/描述/优先级/标签/评论）允许编辑与追加，agent 经 `kb show` 拉取最新
- 卡片显示占用者徽标
- 解除占用仅两条路：agent 显式 `done`/`fail`；用户点"强制释放"（释放后状态回"待规划"并写 system 评论）
- `done` → 状态流转"待验收"，释放占用，notes 落评论流（author=agent:<id>）；`fail` → 回"待规划" + reason 落评论流
- 用户手动把任务拖到"进行中"不产生占用；卡片样式区分"占用/未占用"

### 5.5 聊天

- 自由会话（不绑 issue）与任务会话（绑 issue）共用聊天视图
- 每轮对话 = 一次无头进程调用（§4.1 runTurn）：首轮新建 CLI 侧会话，后续轮以 adapter_session_id resume 续上下文
- 运行中输入不禁用：新消息入会话队列（内存态，不入库）；本轮 end 后取全部排队消息合并为一条 prompt 自动发起下一轮
- 队列长度与等待槽位为运行时态，经 WS `session.runtime` 事件与 sessions 接口字段（`queued_count`/`waiting_slot`）对外暴露；排队中与停止后队列均只读可查（`GET /api/sessions/:id/queue`），不提供编辑
- 停止按钮：kill 当轮进程，会话标"已结束"，排队消息保留可编辑；续聊时 resume
- 会话内可改模型，下一轮生效；多会话并行：不同会话可同时各跑一轮；服务端并发进程上限可配（默认 3），超上限轮次排队等空闲槽位；聊天视图一次显示一个会话，运行中会话后台收流不丢，顶部切换器标"运行中/有新消息/失败"
- 消息与事件流持久化到 message 表；服务重启：运行中会话按失败处理（§5.7），队列丢弃

### 5.6 验收
agent done → 任务在"待验收"列 → 人工确认后拖"已关闭"；不满意拖回"待规划"。

### 5.7 错误处理
CLI 进程异常退出 / 非零退出码 → 会话标记"失败" → 占用自动释放 → issue 回"待规划"并写 system 评论。服务重启后：`运行中` 会话按失败处理并释放占用。

### 5.8 评论区（参考 multica）

评论区 = issue 的人机异步沟通流，与聊天会话解耦：聊天是会话内实时交互，评论是跨会话的持久留言。

- **用户发评论**：绑定会话占用（session_id 非空）→ 自动唤醒占用 agent（等效向其绑定会话发消息：会话空闲即起一轮，运行中入队合并；队列与合并规则与 §5.5 一致）；kb 自助领取占用（session_id=null）→ 无实时唤醒，留言作为待读留言，由占用 agent 下次 `kb show` 经 consume 端点标注并恰好一次消费；未占用 → 仅留言，留待下次派发被 agent 读取
- **agent 写评论**：`kb comment` 命令（进展总结、受阻说明）；done/fail 的 notes/reason 与 system 事件（失败回退、强制释放）自动落同一条评论流
- **agent 读评论**：`kb show` 输出含全部评论，经 consume 端点标注待读留言（新评论行 `[新]` 前缀 / `--json` 每条评论 `is_new` 字段）；模板固定指令引导开工前与关键节点读取
- **单一入口**：评论入库与唤醒触发在服务端同一函数内完成，不重复入队
- **UI 提示**：绑定会话占用显示"将唤醒 <agent>"；kb 自助领取占用显示"留言待 agent 下次读取"；未占用显示"仅留言"

## 6. 接口设计

### 6.1 REST + WebSocket（前端 / CLI / 二期 MCP 共用）

> 完整实时参考见 `Docs/api.md`，本表为设计概要。

```
GET    /api/workspaces              POST /api/workspaces        {name, path}
GET    /api/issues?workspace=       POST /api/issues            {workspace_id, title, description, priority?, labels?}
PATCH  /api/issues/:id              {title?, description?, priority?, labels?, status?, sort_order?}
GET    /api/issues/:id/comments     POST /api/issues/:id/comments  {content}
                                    绑定会话占用自动唤醒 agent（§5.8）；返回评论 + 是否已触发
POST   /api/issues/:id/comments/consume                         读全部评论 + 标注新评论（时间序 id 数组）并推进留言游标，恰好一次；返回 {comments, new_comment_ids}
POST   /api/issues/:id/claim        {agent_id}                  → 200 | 409 已被占用
POST   /api/issues/:id/release      （强制释放）
POST   /api/issues/:id/done         {agent_id, notes?}
POST   /api/issues/:id/fail         {agent_id, reason}
GET    /api/clis                    可用 CLI 清单（探测缓存）
GET    /api/clis/:id/models         模型清单（三级降级结果）
GET    /api/sessions?workspace=     POST /api/sessions          {cli, model, issue_id?, prompt?, reuse_session?}
POST   /api/sessions/:id/messages   {text}                      空闲即发起一轮；运行中则入队
POST   /api/sessions/:id/stop       kill 当轮进程
WS     /ws                          订阅：看板变更、会话事件流、评论流
```

### 6.2 CLI `kb`

```
kb list-spaces
kb list-tasks [--workspace <id|名>] [--status 待规划]
kb show <issue-id>
kb claim <issue-id>            # 原子领取；输出任务详情
kb comment <issue-id> "内容"   # 写评论；长文/中文经 stdin 传入
kb done <issue-id> [--notes ...]
kb fail <issue-id> [--reason ...]
```

CLI 均走本地 HTTP API；服务未启动时明确报错。list-tasks / show 输出含 priority、labels、占用者、评论列表。

### 6.3 Skill

通用 `SKILL.md`：说明看板概念、`kb` 用法、领任务→执行→汇报流程、占用规则（claim 失败即换任务）、任务内容与评论以 `kb show` 拉取最新为准、关键节点用 `kb comment` 写总结。分发方式：装到 agent 生态 skills 目录，或随工作空间提供。

## 7. UI 布局

整体三区：左栏（工作空间）| 中央（看板）| 右侧面板（聊天 / 任务详情，可收起）。桌面浏览器优先；主题跟随系统，可手动切换。

### 7.1 顶栏
当前工作空间名（名旁服务端版本号 `v<版本>`，取 GET /api/version，不可达或加载中显示 `v?`；悬停显示服务端名称与前端版本，不一致时警告）与路径、CLI 可用徽标（四家，悬停显示版本号）、服务状态、设置入口（端口 / 并发上限 / 主题；底部显示服务端与前端版本）、新建 issue 按钮。

### 7.2 左栏：工作空间列表
- 工作空间卡片：名称、路径、四列 issue 数量统计
- 新增：选文件夹 → 命名；选中态高亮，决定中央看板内容

### 7.3 中央：四列看板
- 列：待规划 / 进行中 / 待验收 / 已关闭，列头显示数量
- 拖拽（dnd-kit）：跨列与列内排序；占用中卡片禁止拖出（禁止光标），服务端 409 兜底
- 卡片：标题、左缘优先级色条（低/中/高）、标签 chips、占用徽标（占用者，会话运行中显示动效）、agent 徽标、评论数徽标、关联会话标记；点击开任务详情
- 空列显示占位提示

### 7.4 任务详情视图（右侧面板）
- 字段区：标题、描述（markdown 预览/编辑切换）、优先级、标签——随时可编辑（含占用中，agent 经 `kb show` 拉取最新）
- 评论区：issue_comment 扁平时间线（作者徽标 user / agent:<cli> / system，markdown 渲染）；输入框追加，发送按钮按状态提示"将唤醒 <agent>"（占用中）或"仅留言"（未占用）
- 关联会话列表：该 issue 全部历史会话（状态徽标 运行中/已结束/失败），当前占用会话高亮"当前"；点击切聊天视图
- 操作区按状态条件化：派发（可派发时）/ 会话进行中（占用中）/ 强制释放（占用中）/ 标记待验收（占用中）/ 删除（非占用中，二次确认，级联删关联会话与消息）
- 派发 → 打开派发设置弹窗（§5.2），确认后自动切聊天视图

### 7.5 聊天视图（右侧面板）
- 顶部：会话切换器（下拉 + 新建按钮 + 运行中/有新消息/失败徽标，自由/任务会话分组）、CLI/模型显示与修改（下一轮生效）、停止按钮（运行中显示）
- 消息流：markdown 渲染 + 代码高亮；tool/thinking 事件折叠块；运行中底部流式指示
- 输入框：多行，Enter 发送 / Shift+Enter 换行；运行中显示"排队中 N 条"提示

### 7.6 弹窗与空态
- 派发设置弹窗（§5.2）、新建 issue 弹窗（标题、描述、优先级、标签 → 落"待规划"）、新增工作空间弹窗
- 空态：无工作空间（引导创建）、空看板列、无会话
