# 新建任务的「智能创建」（AgentBoard）
- status: proposed
- date: 2026-11-03
- card: -
- supersedes: -

状态：待用户批准。参考 Multica 的实现，按 AgentBoard 既有结构裁剪。

## 1. 参考（Multica 实测文档）

创建任务对话框底部可切换**手动创建 / 通过智能体创建**，切换不丢已填内容；智能创建只需写一段需求 + 选创建者 → 后台整理成标题与描述并建任务 → 成功/失败都通知到收件箱，失败可从通知跳回**完整表单**继续手改。约束：智能体只按原意复述、不补没提的要求与验收条件；需求里点名负责人就分配，否则负责人＝创建者；对话框里选的项目/优先级/截止日期原样使用，不从文字推断。

## 2. 已确认决策

| # | 决策 | 取值 |
|---|---|---|
| D1 | 执行方 | **复用本机已装适配器**（`packages/adapters` 的 dsh / codex / opencode），起一次一次性会话，不新增 API key 配置 |
| D2 | 建卡后 | **只建卡，不自动派发运行**（不 claim、不起常驻会话） |
| D3 | 输出约束 | 只按需求原意复述；**不补**没提到的要求、验收条件、负责人；不推断优先级/标签 |
| D4 | 失败处理 | 解析或执行失败 → 把原需求灌回手动表单，并保留用户已选字段 |

## 3. 交互

```
新建任务
┌───────────────────────────────────────────┐
│ [手动创建] [智能创建]      ← 底部切换，不丢已填内容
├───────────────────────────────────────────┤
│ 需求：一段自然语言（多行）                 │
│ 执行方式：dsh ▾ | codex ▾ | opencode ▾     │
│ 优先级：中 ▾   （可选，原样使用，不推断）    │
├───────────────────────────────────────────┤
│                    [取消]  [生成草稿]      │
└───────────────────────────────────────────┘
生成后 → 草稿态表单（标题/描述/标签可编辑）→ [创建任务]
```

- 「生成草稿」只产出**可编辑草稿**，不直接落库；用户确认后再创建（比 Multica 的"直接建卡"多一步确认，防止误建）。
- 草稿至少含：`title`、`description`（含「背景/要求/验收」三段，缺哪段写「未提供」而不是编）、`labels`（只从已有标签里选，不新造）。
- 生成中显示进度与可取消；超时（默认 120s）视为失败走 D4。

## 4. 技术落点

- 服务端新增 `POST /api/issues/draft`（不落库）：body `{ workspace_id, requirement, adapter, priority? }`；返回 `{ title, description, labels, warnings[] }`。
- 复用 `packages/adapters` 已有的一次性调用能力；**不新建常驻会话**、不占 claim 槽位。
- 输出走严格 JSON schema 校验；不合法 → 重试 1 次 → 仍不合法走 D4。
- 审计：记录一次「草稿生成」事件（adapter、耗时、成功/失败、warning 条数），**不记录需求原文**（可能含敏感信息）。

## 5. 非目标

- 不做多轮对话式追问（一次生成 + 用户手改）。
- 不做自动派发、不自动 claim、不自动分派执行者。
- 不做「智能拆分父子卡」（留给 `writing-task` 技能）。

## 6. 验收

- 服务端：`/api/issues/draft` 的成功、适配器失败、JSON 不合法三条路径；schema 校验；超时。
- 前端：切换不丢内容、生成草稿可编辑、创建落库字段正确、失败回退到手动表单且原需求保留。
- 断言「不补要求」：需求只写一句话时，`description` 的未提供段落写「未提供」，不得出现编造的验收条件（用固定 fixture 断言）。
- test 无新增失败；build exit 0。
