# CB-UTF8 取证：中文 prompt 变 `???` 的根因

日期：2026-11-04 · 卡：`5d99f198-23fd-47c0-b55e-2e08bfd76d0d`

## 结论（三选一里选「其他」）

**不是产品侧转码问题**：应用链路（web → API → 落库 → 回读）严格 UTF-8，中文逐字节一致。
之前观察到的 `???` 来自**取证脚本本身** —— PowerShell `Invoke-WebRequest -Body <string>` 把请求体按控制台码页发送，非 UTF-8。

## 1. 进程内字符串是对的（hex 证据）

prompt = `请原样回显：中文测试`（10 字符）

```
Buffer.from(prompt, 'utf8').toString('hex')
e8afb7e58e9fe6a0b7e59b9ee698beefbc9ae4b8ade69687e6b58be8af95
```

## 2. 走真实 API（Node fetch，严格 UTF-8）往返

```
POST /api/sessions {cli:'codex', workspace_id} → 200
POST /api/sessions/<id>/messages {text: 请原样回显：中文测试} → 200 {"queued":false}
GET  /api/sessions/<id>/messages → user.content = 请原样回显：中文测试
     equalsPrompt = true
     hasTripleQ   = false
     hexHead      = e8afb7e58e9fe6a0b7e59b9ee698beefbc9ae4b8ade69687e6b58be8af95
```

**对照**：同样的中文用 PowerShell `Invoke-WebRequest -Body '<中文>'` 发出，落库即 `???` —— 请求体在脚本侧就被码页转掉了。

## 3. spawn 层检查（argv vs cmd.exe vs stdin）

| 方式 | 结果 |
|---|---|
| `cmd.exe /d /s /c codebuddy.cmd -p "<中文>" --output-format json` | **输出里能找到原文 `请原样回显：中文测试`**，无 `???` |
| `node <npm 包 bin/codebuddy> -p "<中文>"` | 进程正常退出（本次输出为空，见「未验证」） |
| stdin（`-p -` + 管道写入） | 该账号当时返回 **429 额度已用尽**，无法判断 |

`packages/adapters/src/spawn.ts:168`：`shell: false`、参数为数组、`StringDecoder('utf8')` 解码 stdout/stderr —— **没有拼命令行字符串、没有走 shell 转码**。Windows 上 `.cmd` 由 Node 自动经 `cmd.exe /d /s /c` 启动（`resolveWindowsSpawnForm`），但本次实测 argv 中文未丢。
