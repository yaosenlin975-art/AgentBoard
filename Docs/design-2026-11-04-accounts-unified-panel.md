# 账号管理统一平台面板设计（2026-11-04）

状态：设计稿。布局方案 C 已与用户确认；标注「（拍板）」的条目是我的决策，用户过目时可推翻。

## 1. 意图与背景

用户痛点：账号管理弹窗设计混乱——一屏堆了工具栏、三张额度卡、全局按钮、加载状态、三个平台折叠分区、批次面板六层内容；且"额度来源"（DeepSeek / OpenCode Go / Codex）与"账号平台"（WorkBuddy / MiniMax / Trae）是两套割裂的维度。

用户日常两个高频动作：
1. 看三个平台的额度；
2. 多平台多账号管理（增删账号、一键签到），额度最好也在同一处看到。

对话中已确认的决策：
- **统一模型**：额度来源与账号平台合并为一类"平台"列表，共六个；
- **资源类型区分绘制**：余额 / 时间窗口限额 / 积分；各自就地显示，能签到的显示签到状态；
- **积分占位**：WorkBuddy / MiniMax / Trae 本轮无积分读取接口，画"未接入"占位，结构预留；
- **位置**：仍在弹窗内（顶栏「账号管理」入口的 Modal，不升级独立页面）；
- **布局**：三版原型（A 折叠卡 / B 总览格 / C 高密度行式）中用户选 **C**。

## 2. 目标 / 非目标 / 反目标

**目标**
- 六平台一屏全见：打开弹窗不滚动、不展开即可看到全部额度与签到状态；
- 资源按类型就地绘制：余额=数字，时间窗口=迷你进度条，积分=占位灰标；
- 能签到的平台显示今日签到状态 `n/m`；
- 行展开承载账号管理：账号列表（脱敏）、切换、**删除**、单账号签到、捕获当前账号；
- 全局操作保留：一键签到（全部平台）、读取本机账号；
- 新增账号删除能力（后端此前没有，见 §7）。

**非目标**
- WorkBuddy / MiniMax / Trae 积分的真实读取（本轮占位）；
- 独立页面 / 新导航入口；
- 折叠状态持久化（保持现状：会话内状态，不写存储）；
- 新增额度来源或额度 API。

**反目标**（做成了也算失败）
- 又堆成混合六层内容的"大杂烩"；
- 同一平台信息出现在两个区域（方案 B 的硬伤）。

## 3. 约束

- 脱敏口径不变：不显示 token / `identity_hash` / vault ref / 文件路径；账号标识显示 `display_name`（用户别名）+ `identity_hint`（哈希前 8 位），与现状一致。
- 能力矩阵仍以服务端 `GET /api/managed-account-capabilities` 为准；能力矩阵读取失败时禁用全部写操作的行为不变。
- API 复用：`GET /api/managed-accounts`、`/api/managed-account-capabilities`、`/api/managed-account-quotas`、`POST …/capture-current`、`POST …/:id/switch`、`POST /api/checkin-runs`（带 Idempotency-Key）、本机导入。
- 今日签到状态数据源为 `last_checkin_day` / `last_checkin_status`（本地记录）；文案不得伪装成官方服务端当日状态（沿用 `design-2026-11-01-workbuddy-accounts.md` §7 口径，芯片 tooltip 注明"本地记录"）。
- `prefers-reduced-motion` 下展开/收起不做高度动画。
- 既有测试（`AccountsPanel` / `AccountReasonCodes` / `AccountsOneClick` / `CheckinBatch` 等）的 testid 保留或映射，映射写进任务说明。
- 视觉沿用看板既有中性色 + 主题绿 + 细分割线体系（`design-2026-11-03` D4）。

## 4. 方案（用户已选 C）

| 方案 | 描述 | 取舍 | 结论 |
|---|---|---|---|
| A 单列折叠卡 | 现状改良，额度并入平台卡头部 | 改动最小，但一屏放不下六个平台，看额度要滚动 | 否 |
| B 上总览格+下管理 | 六格额度总览 + 三个账号分区 | 额度全览，但同一平台信息出现两处 | 否 |
| **C 高密度单屏行式** | 六行一屏，资源就地绘制，账号收进展开层 | 高频动作零滚动；展开层多一跳 | **用户确认** |

## 5. 界面结构（C）

```
账号管理弹窗（Modal lg，scrollable）
├ 头部工具栏：[一键签到（全部平台）] [读取本机账号]      今日 n/m（右对齐小字）
├ WorkBuddy 行   名称 + 「积分 未接入」灰标 + 签到芯片 + [签到]      ▾ 可展开
│   └ 展开层：能力徽标（capture/switch/checkin ✓✗?）
│             账号行列表（identity_hint · 客户端当前标记 · 签到芯片 · 切换/删除）
│             [+ 捕获当前账号] · 通知/冲突批次/批次面板（收进本平台展开层）
├ MiniMax 行    同上（默认折叠）
├ Trae 行       同上（默认折叠）
├ DeepSeek 行   名称 + ¥ 余额数字 +「余额」注                不可展开
├ OpenCode Go 行 名称 + 三条迷你进度条（5h/周/月，% 标注）    不可展开
└ Codex 行      名称 + 两条迷你进度条（5h/周）               不可展开
```

**绘制规则**
- 排序（拍板）：可签到平台在前，仅额度平台在后；组内维持 `APP_ORDER` / 额度来源现有顺序。
- 默认全折叠（拍板）：弹窗打开即总览；展开是低频账号管理动作，不抢首屏。
- 余额：`{金额} {单位}`；`error` / `unsupported` 时显示中文原因（沿用 `QUOTA_REASON_LABEL` 口径，裸码只进可展开技术码）。
- 窗口进度条：填充宽 = `used_percent`；`limited=true` 芯片文案「已限额」+ 警示色；重置时间进 tooltip（`Resets in Xh Ym`）；Codex 不画 monthly 行（`design-2026-11-03` D3 不变）。
- 签到芯片：全完成→绿 `✓ n/n`；部分→琥珀 `n/m`；平台签到能力不可用→灰「签到不可用」。
- 「今日已完成」判定（拍板）：`last_checkin_day = 今天` 且 `last_checkin_status ∈ {succeeded, already_done}` 才计入分子；`unknown` 不计入分子、芯片追加 `?` 角标（tooltip「结果未知，未自动重发」）；`failed` 服务端不写 day，自然落回"未签到"；`authorized` 不算已完成。分母 = 可参与签到账号数（`checkinParticipation` 现有口径）。
- 头部「今日 n/m」= 可参与签到账号中今日已完成的比例（跨平台合计，本地记录）。
- 积分占位：灰芯片「积分 未接入」，位置与余额/进度条同栏，未来接入只换绘制分支。
- 仅额度行不展开、无账号操作；其数据仍来自 `/api/managed-account-quotas`。

## 6. 交互细节（均为拍板）

- **删除账号**：两步式——点「删除」→ 行内出现「确认删除」二次按钮（3 秒未确认自动收回）；成功→失效重拉账号列表；失败→`reasonLabel` 中文提示。删除只清 AgentBoard 元数据与 DPAPI 快照，不动客户端登录态（§7）。
- **删除确认文案**（拍板）：该账号 `is_current=true` 时确认行追加警示「该账号是当前客户端登录账号；删除记录不会退出客户端登录」。
- **折叠行点「签到」**（拍板）：自动展开该平台行——批次面板、通知、冲突「查看该批次」都在展开层内，点完必须能看到结果；不为折叠态另造实时进度控件。
- **切换**：沿用现有 `AccountCard` 切换确认与 operation 状态展示，收进展开层。
- **签到**：行上 `[签到]` = 本平台全部启用账号发起批次（复用现有 `POST /api/checkin-runs` 单平台语义）；展开层账号行保留单账号签到。批次进度面板显示在该平台展开层内。
- **一键签到（全部平台）**：保持现有 `useOneClickCheckin` 计划/结果流；结果面板浮在工具栏下方（现状位置），不塞进行内。
- 能力矩阵加载中/失败提示：保留现状（工具栏下方一行），失败时全部写操作禁用。

## 7. 后端补充

- 新增 `DELETE /api/managed-accounts/:id`（`design-2026-11-01` §8 既有提案落地）：
  - 本机同源 + CSRF 校验（与现有写接口一致）；
  - 删除 `managed_account` 元数据行 + 其 DPAPI 快照/凭据文件；**不**触碰客户端自身登录文件；
  - 删除阻塞条件（拍板，安全优先）：存在 `queued/running` 的 operation → 409 `ACCOUNT_BUSY`；存在未过期的进行中签到授权 → 409 `CHECKIN_AUTHORIZATION_EXISTS`（不静默级联销毁授权会话）；最近切换操作为 `recovery_required` → 409 `RECOVERY_REQUIRED`（快照是恢复依据，恢复完成前禁删）；`is_current=true` **不**阻塞删除，仅前端警示；
  - 响应只含 `{ deleted: true, id }`，不回显任何凭据信息。
- 不新增额度/积分端点。

- 变异测试至少 1 条 RED。
- `web build`、`pnpm -r build` exit 0。
- CDP 走查：弹窗默认态六行一屏全见、行展开/收起、删除确认流、能力矩阵失败禁用态、窄屏（375）不破版、`prefers-reduced-motion` 无动画。

## 10. 展开层视觉规格（2026-11-04 用户截图反馈追加）

用户反馈：展开层账号信息与签到批次面板依旧丑陋（截图证据：长原始标识占满整行、五个徽章挤一行、负向芯片、终态批次的死占位按钮行、裸英文状态枚举）。以下均为拍板，验收时可推翻措辞不可推翻口径。

**账号行（AccountCard）**
- 一行 = 一账号：`display_name`（超宽 truncate，tooltip 给全文；`com.minimax…` 类长原始标识不得占满整行）+ `identity_hint` 小字等宽。
- 只显示正向状态芯片：`客户端当前`（绿）、`签到当前`（蓝）；**不渲染**「客户端非当前」（缺席即非当前）；`区域未知` / `签到能力未知` / `不参与签到` 等低信息芯片收进 tooltip 或「技术信息」details，不占芯片位。
- 实例 / 快照 / 标识等元数据收进「技术信息」details，默认折叠；`最近签到` 显示中文（succeeded→签到成功、already_done→今日已完成、unknown→结果未知、failed→失败），不显示裸英文枚举。
- 按钮层级：每行至多一个主按钮——`捕获当前账号` 保持主按钮（平台级动作），`切换` 降为次级，`签到` / `删除` 为 ghost 小按钮。切换确认流与 operation 状态展示行为不变。

**签到批次面板（CheckinBatchPanel）**
- 头部一行：`签到批次 · 状态 chip · 本地日`；批次 ID 前 8 位等宽 + 点击复制。
- 条目行：display_name + 状态 chip + 中文原因同行（红色）；裸码只进可展开技术码（同 ACC-REASON-01 口径，「操作执行失败（未归类错误）」的括号裸码收进技术码）。
- 批次终态（`finished_at` 非空且无 queued/running 项）不渲染「取消排队项」按钮与提示行；「没有可取消的排队项」整句不再出现，仅存在 queued 项或需解释 running 项时显示取消区。

**一键签到结果流（OneClickCheckin）**
- 结果面板按同一口径收敛：状态 chip + 中文原因 + 短批次号；位置不变（工具栏下方），不复述原始码。
