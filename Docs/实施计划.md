# AgentBoard 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `Docs/设计文档.md` 实现多工作空间 Agent 任务看板（看板 + Agent CLI 聊天 + 占用锁 + kb CLI/skill）。

**Architecture:** pnpm monorepo：`packages/shared`（契约类型）→ `packages/adapters`（四家 CLI 无头适配）→ `apps/server`（Express + better-sqlite3 + ws，全部业务逻辑）→ `packages/cli`（kb，走 HTTP）→ `apps/web`（React 19 SPA）。服务端是唯一状态源；前端与 CLI 只经 REST/WS。

**Tech Stack:** TypeScript 5.x / Node ≥20 / pnpm；express 5、better-sqlite3 12、ws 8、zod 4、vitest 3、supertest；React 19、Vite 7+、Tailwind 4、@dnd-kit/core 6、@tanstack/react-query 5、commander 14。

**Spec:** `Docs/设计文档.md`（本计划从该文档取值）；代码级参考 `Docs/参考代码索引.md`。

## Global Constraints

- 平台：Windows 优先（Git Bash 可用）；路径用 `path.join`/`path.resolve`，不硬拼分隔符。
- 包名 `@agentboard/<name>`；CLI 命令名 `kb`；产品名 AgentBoard（用户可后续改名，先集中常量化于 `packages/shared/src/constants.ts`）。
- 状态枚举逐字使用：`'待规划' | '进行中' | '待验收' | '已关闭'`；优先级 `'低' | '中' | '高'`；会话 `'运行中' | '已结束' | '失败'`；评论作者 `user | agent:<cli id> | system`。
- 默认配置：端口 `8787`；DB `%APPDATA%\AgentBoard\agentboard.db`；配置文件 `%APPDATA%\AgentBoard\config.json`（`{ port, dbPath, maxConcurrentTurns }`，`maxConcurrentTurns` 默认 `3`）。常量与默认值定义在 `apps/server/src/config.ts`。
- 时间戳一律 `Date.now()`（毫秒整数）；主键 `crypto.randomUUID()`。
- 所有子包 `pnpm test`（vitest，`environment: node`）可独立运行；web 用 `vitest + @testing-library/react`。
- 每个任务结束 `git add <改动文件> && git commit`，信息用 `feat:/test:/chore: <task 简述>`。仓库为新建本地仓，直接提交 main。
- 禁改范围：`Docs/` 下已有文档除计划勾选外不改；不引入设计外的依赖（新增依赖须在任务说明中列出）。

### DB DDL（apps/server/src/db/schema.ts，逐字）

```sql
CREATE TABLE IF NOT EXISTS workspace (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, path TEXT NOT NULL UNIQUE, created_at INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS issue (
  id TEXT PRIMARY KEY, workspace_id TEXT NOT NULL REFERENCES workspace(id) ON DELETE CASCADE,
  title TEXT NOT NULL, description TEXT NOT NULL DEFAULT '',
  priority TEXT NOT NULL DEFAULT '中' CHECK (priority IN ('低','中','高')),
  labels TEXT NOT NULL DEFAULT '[]',
  status TEXT NOT NULL DEFAULT '待规划' CHECK (status IN ('待规划','进行中','待验收','已关闭')),
  sort_order INTEGER NOT NULL DEFAULT 0,
  claimed_by TEXT, claimed_at INTEGER, session_id TEXT,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS issue_comment (
  id TEXT PRIMARY KEY, issue_id TEXT NOT NULL REFERENCES issue(id) ON DELETE CASCADE,
  author TEXT NOT NULL, content TEXT NOT NULL, ts INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS session (
  id TEXT PRIMARY KEY, workspace_id TEXT NOT NULL REFERENCES workspace(id) ON DELETE CASCADE,
  issue_id TEXT REFERENCES issue(id) ON DELETE SET NULL,
  cli TEXT NOT NULL, model TEXT, status TEXT NOT NULL DEFAULT '运行中'
    CHECK (status IN ('运行中','已结束','失败')),
  adapter_session_id TEXT, created_at INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS message (
  id TEXT PRIMARY KEY, session_id TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK (role IN ('user','assistant','event','error')),
  content TEXT NOT NULL, ts INTEGER NOT NULL);
```

连接：`new Database(dbPath)` + `db.pragma('journal_mode = WAL')` + `db.pragma('busy_timeout = 5000')`。

### 领取事务（apps/server/src/services/claim.ts，逐字）

```ts
const row = db.prepare(
  `UPDATE issue SET claimed_by=?, claimed_at=?, session_id=?, status='进行中', updated_at=?
   WHERE id=? AND claimed_by IS NULL AND status IN ('待规划','进行中')`
).run(agentId, Date.now(), sessionId, Date.now(), issueId);
if (row.changes !== 1) throw new ConflictError('已被占用');
```

done：事务内 `status='待验收'` + 清空 claimed_by/claimed_at/session_id + notes 落 issue_comment(author=agent:<id>)。fail：`status='待规划'` + reason 落 issue_comment。release：`status='待规划'` + 清空占用 + system 评论。

### 会话轮次规则（apps/server/src/services/sessionManager.ts）

- 每 session 一个内存队列 `string[]`；空闲时 `POST messages` 直接起轮（message 表先写 user 消息），运行中入队返回 `{queued:true}`。
- 轮次结束（TurnResult）：若队列非空 → 取全部合并为一条（`\n\n` 连接）作为下一轮 prompt；否则 session 置 `'已结束'`（手动 stop）或按 exitCode（`!==0` → `'失败'` + issue 若被本会话占用 → fail 流程；`=0` 且无队列 → `'已结束'`）。
- 全局并发：同时运行的轮次进程数 ≤ `maxConcurrentTurns`；超出的轮次进全局 FIFO 等待槽位，槽位空闲按先到先发。
- `stop`：kill 当轮进程，session 置 `'已结束'`，队列保留。
- 服务重启：启动时把所有 `status='运行中'` 的 session 置 `'失败'`，其占用 issue 走 fail 流程（system 评论"服务重启，会话中断"）。
- 自由会话（issue_id=NULL）失败只标 session，不涉及 issue。

## Review Focus（每个失败模式都有对应测试钉死）

1. 并发领取同一 issue：N 个并行 claim 只有一个成功 → Task 6 集成测试。
2. 占用中 issue 的 status PATCH / 拖拽：服务端 409，不改状态 → Task 6。
3. 运行中重复评论唤醒：连续 3 条评论只合并为下一轮一次 prompt，不叠 3 个进程 → Task 8。
4. Windows 下 `kb comment` 中文/多行经 stdin：字符不损坏 → Task 11。
5. CLI 未安装时派发：适配器 detect=false，起轮报明确错误（会话标失败），不崩进程 → Task 7。
