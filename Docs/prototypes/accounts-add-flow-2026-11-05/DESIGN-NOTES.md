# 账号添加流程原型 · 设计说明（2026-11-05）

入口：`index.html`（单文件、纯静态、无外部依赖，浏览器直接打开即可）。示例数据写死在脚本里，不连服务端。

## 1. 与现状的差异（均按真实实现核对）

| 维度 | 现状 | 本原型 |
|:--|:--|:--|
| 左栏索引 | 恒定 8 行：`APP_ORDER` 三平台 + 能力矩阵里的 qoder_cn/zcode + CLI 三来源，零账号也占位 | 只列有账号的平台/来源（示例：Trae 2、WorkBuddy 1、DeepSeek 2） |
| 添加入口 | 每个平台行展开层里的 `AddAccountEntry` 协议向导；工具栏「刷新」是全局批量扫描 | 工具栏唯一「添加账号」→ 供应商选择页；行内加号迁出，详情页只留一句指路 |
| 读取本机 | 工具栏「刷新」一次扫 workbuddy / trae / minimax | 选择页按平台卡「读取本机」，对应 `import-credentials` 已有的 `platforms` 限定 |
| Codex | 只在额度区出现 | 进选择页，卡上只有一个「读取本机」；读取结果 0/0/0 后落到只读额度视图，不产生账号 |
| 零账号平台 | 一直显示 | 不进索引；刷新后新增账号会让平台自动出现 |

## 2. 本次修订：供应商卡只留名字 + 按钮

- 卡片结构：`供应商名字（单行，超长截断）` + `按钮行（左对齐）`。删除账号数、能力副标题、状态标签、说明段落、装饰性 agent 字形。
- 能力为真才渲染按钮；能力为假不渲染该按钮，也不出现禁用灰按钮。三类卡：
  - 可读可授权（WorkBuddy / MiniMax / Trae）：`读取本机` + `授权添加`；
  - 只授权（Qoder CN / ZCode）：仅 `授权添加`；
  - 仅读取（Codex）：仅 `读取本机`（读取后进入额度视图）。
- 原本靠文字表达的原因（Qoder/ZCode 本机读取未接入、Codex 无导入凭据）收进卡片的 `title`，hover / focus 时才出现，不占版面。
- 条目降到 7 条（WorkBuddy、MiniMax、Trae、Qoder CN、ZCode、DeepSeek、Codex），因此去掉搜索框与分组，整页一张平铺网格。
- **对实现意味着什么**：
  1. 按钮存在性本身就是能力表达，前端不应再维护一套「支持/未接入」状态文案；后端能力表（`accountCapabilities.ts` + `/api/add-account-protocols`）是唯一真值来源，加/撤一个动作只改能力表，卡片按钮自动增删。
  2. 每条不可用动作仍需要一句原因（title），建议由能力表/接口返回 `reason` 字符串，前端只负责挂到卡片上，避免文案散落在组件里。
  3. 原生 `title` 对键盘与读屏较弱；落地时应使用 Tooltip 原语 + `aria-describedby`，原型仅演示 hover/focus 出现的原生 title。
  4. 卡片高度统一由 `min-height` + `space-between` 保证；按钮行左对齐，名字与按钮之间留白固定。

## 3. 状态机

- **主视图**：`normal` / `empty`（控制条切换）。选中项在每次渲染前归一化到第一个可见平台；没有可见平台时右栏显示空态引导。
- **供应商选择页**：`closed → open`，单一网格、无搜索、无分组；打开后焦点落在第一张卡。
- **读取本机**：`idle → reading(约 0.9s，进度条) → done(结果停留约 0.85s) → 关闭弹层 → 选中该平台 + 顶部结果条 + 新账号高亮`。新账号 `current=false`，**不自动切换**。
- **Codex 读取**：同样两段延迟，结果为 `发现 0 · 新增 0 · 已存在 0`，随后进入额度视图（不建号）。
- **授权添加**：`idle → pending(卡内展示授权中) → 完成 / 取消`。完成建 1 个账号并回到该平台详情。
- **导入凭据（CLI）**：`idle → 表单 → 提交（空值给原因）→ 成功回详情`。
- **全局刷新**：`idle → busy → 结果提示`；首次刷新把 MiniMax 从 0 变 1，直接演示「索引只列有账号平台」。
- **空态**：清空可见账号但保留底层数据；任意一次成功添加会自动退出空态。

## 4. 拍板落点

| 拍板 | 落点 |
|:--|:--|
| Q1=A 运行时隐藏 | `visibleApps()` 过滤账号数为 0 的平台/来源；空态页与刷新后的 MiniMax 出现均是该规则的现场证明 |
| Q2=A 全局入口 | 工具栏「添加账号」打开选择页；`platformDetailHtml` 底部只留「行内加号已迁出」的指路文案 |
| Q3=A 一卡两动作 | `cardHtml` 按 `CAPS` 逐项渲染按钮；qoder/zcode 只有「授权添加」，原因收进 `CARD_TITLES` 的 title |
| Q4=A 直接建号后报数 | `readLocal()` 选平台即扫描，事后给「发现 3 · 新增 1 · 已存在 2」，并回该平台详情选中新账号 |
| Q5=B Codex 进选择页 | Codex 卡只有一个「读取本机」，title 写明「仅读取 rollout：无可导入凭据」，读取后落额度视图 |
| 默认 1 有账号口径 | 原型按「列表非空」判定；含停用账号仍算有账号（原型未放停用样例，仅写入口径） |
| 默认 2 搜索阈值 | 修订后 7 条 → 不加搜索、不加分组；条目更多时再评估 |
| 默认 3 不给假按钮 | 不可用动作不渲染按钮，也没有 `disabled` 灰按钮 |
| 默认 4 刷新与选中 | 工具栏「刷新」保留；添加成功后自动选中平台并高亮新账号，`current` 不变 |

## 5. 演示脚本

1. 打开页面：左栏 Trae / WorkBuddy / DeepSeek（各自账号数可见），右栏 Trae 详情。
2. 点「添加账号」：弹出「添加供应商」，7 张卡平铺；WorkBuddy / MiniMax / Trae 两张按钮，Qoder CN / ZCode 一张，DeepSeek 一张「导入凭据」，Codex 一张「读取本机」。
3. 在 Trae 卡点「读取本机」：进度条 → 「发现 3 · 新增 1 · 已存在 2」→ 自动回到 Trae 详情，新账号带「新添加」，当前账号不变。
4. 悬停/聚焦 Qoder CN 卡：title 显示「仅支持授权添加：本机读取尚未接入（provider 未实现）」；卡上没有读取按钮。
5. 悬停/聚焦 Codex 卡：title 显示「仅读取 rollout：无可导入凭据」；点「读取本机」后进入只读额度视图。
6. 控制条切「空态演示」：索引与右栏变为空态引导；再点「添加账号」并读取/授权成功后自动退出空态。

## 6. 已知取舍与未做

- 真实扫描、真实授权、真实导入、签到 / 切换 / 删除均未实现；授权用「模拟完成授权」，导入不校验格式、不落库。
- 真实实现里导入成功后立即清空明文输入框；原型提交即离开表单，未演示清空动作。
- 刷新只演示 MiniMax 0→1，不模拟 `PYTHON_UNAVAILABLE` / 超时 / 输出不可解析等失败分支。
- OpenCode Go 未列入示例清单：本机 0 凭据，且为把条目压到 7 条而不加搜索/分组；真实实现若保留该来源，需要重新评估 7 条阈值。
- 原因只挂在原生 `title` 上，键盘 focus 在部分浏览器不主动弹出提示；落地需换成可访问的 Tooltip。
- 窄屏：≤920px 左栏变横滑 rail、≤640px 网格单列；未做 375px 逐像素核对。
- 动效按本轮指令取 160ms `cubic-bezier(0.2,0,0,1)`；仓库现有 `--ab-ease` 是 `cubic-bezier(0.22,1,0.36,1)`，落地前需确认统一口径。
- Codex 额度为占位数字，真实来源是 rollout 读取，未实测。
