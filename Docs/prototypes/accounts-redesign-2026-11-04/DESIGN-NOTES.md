# 账号管理重设计 · 设计说明

基线：`Docs/designs/accounts/2026-11-04-accounts-unified-panel.md`（方案 C 六行总览）、`Docs/prototypes/accounts-redesign-2026-11-04/` 原型、本会话优化任务卡。

本轮不改业务规则，只重做视觉与信息结构。两个方向共用 `assets/mock.js`、`assets/api.js`、`assets/engine.js`、`assets/base.css`，只替换视图层与样式层，因此数据、状态机、签到口径、409 判定完全一致，差别只在于「同样的信息怎么摆」。

---

## 一、先回答「哪些信息不该出现在主视图」

| 信息 | 为什么不该在主视图 | 以前的问题 |
|---|---|---|
| 三枚能力徽标（签到 / 额度 / 区域未知） | 大多数账号三行全绿，等于零信息量的重复装饰 | 每行右侧一排灰芯片，主视图被灌满同期性噪声 |
| 「已脱敏，仅展示识别片段」说明块 | 一次性解释，看第二次就是废话 | 固定在头部常驻，占掉一整行 |
| 每个平台「n 个账号」计数 | 展开后自然可见，折叠时也不影响决策 | 与平台名并排重复，和展开层内容重复表达 |
| 「积分未接入」的完整灰芯片容器 | 占位信息不该做成一个框 | 一个空容器 + 文字，视觉重量等同真实数据 |
| 负向标签（客户端非当前 / 区域未知 / 签到能力未知） | 用「没有」来解释「没有」，制造焦虑 | 每行三四个灰标签，读起来像错误报告 |
| 账号实例 / 快照 / 版本等实例元数据 | 排障时才需要，日常决策不需要 | 直接平铺在账号行里，主视图变成调试面板 |
| 批次长 ID | 用户从来不认这个 ID | `ck-1f3a9e…` 占掉批次条一半宽度 |
| 终态批次的「取消」按钮 | 终态没有可取消的东西 | 保留了一个点了没反应的按钮 |
| 六卡同屏 + 每卡各自展开层 | 六个容器叠六个容器 = 视觉塌方 | 多层嵌套边框、内边距把可用宽度吃掉一半 |

## 二、方向 A · 台账（`a-ledger.html`）

**形态**：暖纸底 + 衬线标题 + 发丝线的单列台账，零圆角零卡片，一个平台一行。

### 砍掉了什么

- 三枚能力徽标 → 整行删除。能力只有在「不可用 / 异常」时才值得说，正常态不占像素。
- 脱敏说明块 → 删除，`identity_hint` 前 8 位本身就是解释。
- 每行「n 个账号」计数 → 删除，展开即见。
- 「积分未接入」灰芯片容器 → 改成一行极轻的斜体占位文字。
- 每行的灰芯片容器（状态标签外壳）→ 全部拆掉，状态直接是文字 + 语义色，不再套框。
- 六张卡片的边框、圆角、内边距、阴影 → 全删，改用 1px 发丝分割线。
- 负向标签 → 删除，只在真的异常（结果未知 / 授权中）时出现一行琥珀色文字。

### 信息移到了哪里

| 原位置 | 新位置 |
|---|---|
| 账号实例 / 快照 / 版本 | 账号行 hover / focus 才浮现的「技术」动作 → 行内展开 `<details>` 技术码 |
| 每个账号的切换 / 签到 / 删除 | 同一组 hover 浮现动作，静止态行内只有身份 + 最后签到状态 |
| 批次进度明细 | 平台行下方的一条 `.run` 细条（accent 左线 + 浅底），完成即收窄为一行口径说明 |
| 「结果未知」的计数说明 | 芯片 `2/3?` 的问号 + 批次终态的一句口径脚注 |

### 为什么不再冗余

主视图每行只保留三个决策要素：**这是哪个平台 → 今天签到了几个 → 现在要不要点**。其余全部按需浮现。静止态一屏能读完 6 个平台，密度接近日志/台账，不接近「卡片墙」。

## 三、方向 B · 工作台（`b-console.html`）

**形态**：冷白面板 + 244px 左栏平台索引 + 右侧单平台工作区，账号以卡片承载但做三级披露。

### 砍掉了什么

- 六卡同屏 → 主视图同一时刻只渲染一个平台的账号，其余平台在左栏以一行指标表达（`2/3?`、`¥128.60`、首个窗口百分比）。原来 6 个展开层嵌套的问题从结构上消失。
- 账号卡里的三行 `dl` 元数据（实例 / 快照 / 版本 / 区域）→ 全部收进「技术信息」`<details>`，默认折叠。
- 平台级能力徽章 → 删除，只在异常（授权中 / 结果未知 / 已限额）时出现提示。
- 重复的「签到当前」表达 → 合并为一条「参与签到」脚注 + 卡片内的一个动作按钮。
- 额度平台的多层容器 → 余额只有一个大数字 + 抓取时间；时间窗口只有三条 2px 进度条 + 重置时间；积分是一块虚线占位。

### 信息移到了哪里

| 原位置 | 新位置 |
|---|---|
| 跨平台总览 | 左栏 rail：每平台一行，指标 + 迷你条 + 异常色 |
| 账号技术元数据 | 账号卡底部「技术信息」折叠层 |
| 删除 / 切换的二次确认 | 卡片内就地展开 `acard-confirm`（含 3 秒倒计时条），不再是全局弹层 |
| 409 原因 | 卡片内 `acard-error`：中文原因 + `<details>` 技术码 |
| 批次状态 | 工作区顶部吸顶 `runPanel`：进度条 + 账号级状态列表，滚动时不丢上下文 |

### 为什么不再冗余

主从结构把「横向比较」和「纵向操作」拆开：左栏负责比较（6 行指标，扫读），右栏负责操作（单平台详情，专注）。同一时刻屏幕上只有一层容器在承载内容，嵌套深度从「卡 → 展开层 → 账号行 → 元数据」降到「面板 → 卡片 → 可选折叠」。

## 四、两方向共用的保底规则

- 仍在弹窗容器内（A 是 900×660 左右的居中弹窗；B 是弹窗内的工作台，不升级为独立页面）。
- 资源差异化：余额直接给数值；时间窗口给进度条；积分虚线占位。
- 完成口径：`succeeded` / `already_done` 计入；`unknown` 带 `?` 不计入；`failed` 落回未签到；`authorized` 不算完成。
- 账号标识：`display_name` + `identity_hint`（哈希前 8 位）。
- 删除边界：`ACCOUNT_BUSY` / `CHECKIN_AUTHORIZATION_EXISTS` / `RECOVERY_REQUIRED` 触发 409；删除当前使用账号追加警示确认。

## 五、推荐

**推荐方向 B**：主从结构天然解决了「六平台同屏堆叠」的根因，三级披露把技术信息彻底移出主视图，批次吸顶保证操作时上下文不丢。方向 A 作为「极致低密度」备选，适合账号少、希望一屏读完、偏编辑/台账审美的场景。
