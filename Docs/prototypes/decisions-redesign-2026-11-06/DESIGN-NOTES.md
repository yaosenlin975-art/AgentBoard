## 2. 设计目标

1. **先看哪条**：一条决策卡第一眼给出紧急度（剩余秒数 / 已锁多久 / 是否超时）、影响面（阻塞几个下游）、能否安全处置（停止是否已确认）。
2. **就地处置**：选一个选项 → 立刻看到后果 → 提交，不离开列表；回答完有明确的移出反馈与 6 秒撤销。
3. **双向可达**：看板 ↔ 待决策 ↔ 任务详情三处互跳，且跳过去能定位到那一条（高亮闪烁）。
4. **不骗人**：界面上出现的每个数字都要能落到真实字段；现在拿不到的字段，本文第 10 节列成「建议新增投影」，不假装已有。
5. **窄屏不降级成残废**：分层收起（rank/侧栏/操作行），核心动作（选项 + 提交）始终可用。

非目标：不改数据模型、不改 API。第 2 轮已补自由文本答案（API 本身已有 `answer_text`），但仍保持**单选**语义；通知权限只做原型态。

## 3. 信息架构：仍然是「侧栏第六入口 + 独立视图」

这不是本轮新决定：v3 设计文档 §3.7 已定方案 A（`Docs/design-2026-11-05-pending-decisions.md#L350-L355`），生产也已按此实现。本轮沿用，避免为了「看起来新」去推翻已实现的 IA。

原型里的边界写清楚了：

- 侧栏 6 入口、176px，与 `SideBar.tsx` 一致；待决策徽标 = `grace + open` 计数（0 时隐藏数字，入口保留）。
- 待决策是**独立整页视图**，右侧详情是 420px 覆盖式抽屉（宽屏不遮主区，窄屏全屏 + 遮罩）。
- 看板卡面新增可点的 `[待决策]` 标识，点击 → 切到待决策视图并定位该条。

### 3.1 范围：本工作区 / 所有工作区

- 控件形态对齐知识库区现有的那套：`范围 <select>`（label + 32px 高、8px 圆角、hairline 边框、card 底、12.5px 字），紧挨排序下拉，一起放在筛选栏右侧；窄屏各占半行。生产里知识库的范围是持久化的（`knowledgeScope`），决策区建议用独立 key（如 `agentboard.decisions.scope`）复用同一套读写，不要共用知识库那个 key。
- 默认「本工作区」= 当前 workspace；切到「所有工作区」后列表按 `workspace_id` 并集查询，**跨区卡在卡头标注工作区短名 + 全名**（`DNF · DNF 单机复刻`）。范围信息只由下拉表达，页头不再复述「范围：…」或「N 条来自其它工作区」。
- 侧栏徽标**只算本工作区**（与生产 `useDecisionsCount(workspace.id)` 一致），不随范围变化；任务看板本身是按工作区组织的，看板里只列本工作区的卡。
- 空态在「本工作区」范围下多一句说明：其它工作区的待决策不会出现在这里，切到「所有工作区」可查看。
- **跨区回答有额外限制**：回答会解锁*别人工作区*的任务卡并释放那边的占用，所以第一次点「提交回答」只做二次确认——按钮变成「确认跨区回答」，卡内出现一条说明（「提交后会在「DNF 单机复刻」解锁 AB-129 并释放该区占用」），再点一次才真正提交。真实实现还需要服务端校验调用者对目标工作区有写权限；没有权限时应直接禁用并提示，而不是让用户点两次空转。

### 3.2 自定义答案：选项末尾的「✎ 自定义」

**入口**：简略卡 chip 行与展开卡 / 详情面板的选项列表，**最后一个位置固定是「✎ 自定义」**（虚线边框，与真实选项区分）。选中后就地在它后面展开输入框，不弹窗、不跳页。

**与单选互斥**：决策本身是单选（当前回答 API 只接受一个 `option_id`），自定义不是「第 N+1 个选项」而是同一组的另一种取值。所以：

- 选自定义 → `selectedOpt = '__custom__'`，其它选项的 `aria-checked` / `.is-selected` 全部清掉；
- 再点某个真实选项 → 选中切回该选项，输入框收起但**草稿保留**（再次点自定义能接着改），错误态清空；
- 切到别的题、切 tab、刷新场景都按同一规则重置；已有的历史答案不受影响（append-only）。

**提交拦截**：

| 情况 | 行为 |
|---|---|
| 空文本 / 纯空白 | 不提交，输入框下方红字「先写一句答案再提交（不能为空）」，`aria-invalid="true"`，焦点留在输入框 |
| 超过 120 字 | 输入框 `maxlength=120` 硬截断（粘贴同样截断），提交时兜底再校验一次并提示「最多 120 字，当前 N 字」 |
| 未选自定义就点主按钮 | 主按钮是禁用态（与真实选项一致），不会用空字符串提交 |

**键盘**：输入框内 `Enter` = 提交（`isComposing` 为真时跳过，避免中文输入法选词回车误提交）；`Esc` = 收起输入框并回退到选中自定义之前的那一项（如果没有前一项则回到未选）。点击其它选项、收起卡片也会收起输入框。

**长度上限 120 字**：与卡片上「一句话答案」的定位一致；答案会写进卡评论并同步任务卡，过长会撑爆时间线与 toast。真实实现建议服务端同样限制（例如 `answer_text` 校验 ≤ 200 字符，前端 120 只作为 UI 软限），并在 `DecisionAnswerDto` 上补 `answer_text` 字段。

**选项很多时的滚动**：选项数 ≥7 时（AB-151 演示 6 个真实选项 + 自定义），简略 chip 行给 `max-height:76px` 内部滚动；展开态的选项列表给 `max-height:300px` 滚动。滚动只发生在选项区内部，页面本身不跳；自定义输入框展开时会被滚动到可见区域（`focus({preventScroll:false})`）。

**写答案**：自定义答案以保留 id `__custom__` 记录，真实文本存在答案的 `customText` 上；时间线、改答案（修订）都会按**那一条答案自己的文本**渲染，不会拿最新草稿顶替历史版本。

### 3.3 展开态去重：只保留详细卡

之前展开后 `chip 行 + 详细选项列表` 同时存在，同一组选项出现两次。现在改成**二选一渲染**：

- 收起态：`简略 chip 行 + 一行后果预览`；
- 展开态：`问题全文 + 详细选项列表（含自定义行）+ 关键值 + 时间线`，**chip 行不再渲染**；
- 已回答卡点「改答案」（修订态）同理，只保留详细卡，避免「旧答案 chip + 新选项列表」叠在一起造成误读。

实现上不是用 CSS 隐藏，而是 `cardHtml` / `answeredCardHtml` 在模板里直接分支，隐藏项不进入 DOM（对读屏与 tab 序也干净）。

### 3.4 「阻塞下游 N」可点开：本卡 blocks 了谁

**方向**：先把这个词钉死——统计行写「阻塞 22 个下游」，点开后标题是「**本卡 blocks 的下游**」，紧跟着两行副标题：

> 方向：这张卡 → 下游
> 列的是「这张卡挡住了谁」，不是「谁挡住了这张卡」。

「谁挡住了我」在真实产品里另有位置（卡角标的「等 N 项」= `blocked_by_count`，见 [dependency.ts](file:///d:/WorkSpaces/任务看板/apps/web/src/lib/dependency.ts#L32-L40)），两处措辞故意不复用。

**每一项给什么**（5 列 grid，窄屏隐藏占用者列）：

| 列 | 内容 | 真实来源 |
|---|---|---|
| 卡号 | 短码按钮，点击打开该卡详情面板（面板里可复制完整 UUID） | `DependencyRef.issue_id` |
| 标题 | 下游卡标题 | `DependencyRef.title` |
| 状态 | 当前状态 chip | `DependencyRef.status` |
| 占用者 | agent 名 / 「未派工」 | ⚠️ 现接口没有，需新增投影 |
| 跳转 | ↗ 图标按钮，打开该卡 / 回看板定位 | 前端路由 |
| 原因行 | 跨整行：「为什么被这条决策挡住」，间接项额外标「经 AB-164 转手」 | ⚠️ 现接口没有，需新增投影 |

**空态**：无下游时统计行本身文案变成「无下游阻塞」（弱化色），仍可点开，面板里给「这张卡目前没有 blocks 任何下游：没有别的卡因为它被挡住。」——不做成不可点，避免用户以为数字是假的。

**很多下游（演示 22 张直接 + 4 张间接）**：超过 6 张时出现筛选框（按卡号 / 标题 / 占用者 / 原因做子串匹配，输入时就地只重渲染列表容器，不整页重渲染），列表给 `max-height:268px` 内部滚动。没有做「按状态分组折叠」——下游数量大时真正需要的是定位某一张，筛选比折叠更快；如果后续要加，建议加在筛选框右侧做成状态多选，而不是再套一层折叠。

**间接下游**：默认折叠，按钮显示「间接下游 4 张（经 1 层转手）」，展开后与直接下游同样式。**建议**：间接下游默认折叠、最多展开一层；理由是间接阻断通常归因不到单条决策（中间还隔着 AB-164 这类卡），全量递归既难解释也会爆炸。若产品坚持要全量，建议改成「按层数筛选 + 只显示路径上的卡」，而不是把整棵子树平铺进来。这一点原型没有定死，留给实现卡拍板。

**修复记录（第 3 轮）**：点击「阻塞下游」没反应的根因不是事件绑定，而是清单里只存在于 `BLOCKED` 的下游卡（如 AB-152）没有对应的 `issues[]` 条目；点卡号时 `effectiveStatus()` 直接读 `issues[key].status` 抛错，`openIssue` 在设置面板前中断，表现就是「点了没反应」。修法是回退到按需生成的 `extraIssues[key]`，并补了真实点击复测：`22 行 + 筛选 + 滚动 + 点 AB-152 打开面板（aria-hidden=false）+ 空态文案` 全部通过。

**数据诚实**：清单里的卡号、标题、状态、占用者、原因全部是**示例数据**（`app.js` 顶部 `BLOCKED`，注释里写明非真实数据）。面板底部固定一行：

> 示例数据。真实实现：`GET /api/issues/:id/dependencies` 的 `blocked[]`（issue_id / title / status / resolved）；占用者与「为什么被挡」需另加投影（见设计说明 §10）。

即：**关系本身**用现有依赖接口拿（`DependencyView.blocked`，见 [dependency.ts](file:///d:/WorkSpaces/任务看板/apps/web/src/lib/dependency.ts#L13-L23)），`claimed_by` 要从 issue 列表/DTO join，而「为什么被挡」当前没有任何字段，要么由决策卡作者在 `context_md` 里写结构化原因，要么新加一个 `blocked_reason` 投影——不要在前端拼假理由。

### 3.5 延长宽限：`＋1 分钟`

**按钮位置与形态**：只在 `grace` 卡的**动作行最左侧**出现，形态是 24px 高的幽灵按钮 `＋1 分钟`，右侧带一个 10px 的累计计数 `1/5`（已延分钟 / 上限分钟）；不放进展开区，因为延长是「来不及回答」时的即时动作，不该多点一次。`open` / `stale` / `answered` 卡**不渲染**该按钮。

**点击后的即时反馈**：

1. 倒计时 chip 立刻从 `剩 2:45` 变 `剩 3:45`，并闪一下描边（700ms）；
2. 进度条按「总宽限 = 原宽限 + 已延长」重算，不会超过 100%；
3. toast：`AB-142 宽限 +1 分钟 · 剩余 3:45`；到上限那次追加「· 已达延长上限」；
4. 展开区的关键值同步：`宽限合计 4:00（原 3:00）`、`已延长 1 / 5 分钟`。

**连点与上限**：允许连点，每次 +60 秒，按请求顺序累加。上限取两者较小值：

```
max_extend = min(300 秒, max(0, 600 秒 - 原始 grace_seconds))
```

即**最多再延 5 分钟**，且总宽限不超过设计里的 600 秒硬上限；原始宽限已是 600 秒时按钮直接禁用。达到上限后按钮文案变「宽限已达上限」并 `disabled`，hover 提示「每点一次 +60 秒；累计最多 +300 秒」。原型里连点 5 次后实测 `disabled=true`、倒计时停在 `剩 7:44`（原 2:44 + 5 分钟）。

**LOCKED 不能延**：一旦落锁（state 变 `open`），agent 已按契约停手并轮询 stop 信号，再延长宽限不会让它恢复等待，只会制造「界面说还有时间、agent 已经停了」的假象。因此已锁卡不显示延长按钮；要重新给机会应该走「重新提问」或「撤回后重开」，这是另一条流程。

**谁有权限**：与回答同权——对目标工作区有写权限的人/agent 都能延；服务端记录 `extended_by`，并在响应里回显。原型不区分角色（页面本身就是人类视角）。跨区延长沿用 §3.1 的口径：需要目标工作区写权限；Web 端建议与跨区回答一样做二次确认，CLI 直接 403。

**临界态（最后 60 秒）**：按钮**保留且可用**，这是最需要它的时刻。视觉上升级为 accent 描边 + 加粗（`.is-critical`），文案不变；延长后若剩余回到 60 秒以上，`warned` 标记清零，下一次逼近临界会重新提示。

#### 生产契约（写入本文件，实现见 `61310826`）

**CLI**

```
kb ask-extend <decision-id> --seconds 60 [--by <actor>] [--fence <n>] [--json]
```

- `decision-id` 与 `kb answer` 一致，支持 ≥8 位前缀；解析失败 → 退出码 3。
- `--seconds` 默认 60，必须为 1–300 的整数；`--by` 缺省用当前 actor；`--fence` 可选，用于 agent 自证持有当前 claim。
- 成功退出 0，`--json` 输出响应体；状态/权限/上限类失败退出 2；参数非法退出 3；其它退出 1（与 `kb answer` 现有口径一致）。

**HTTP**

```
POST /api/decisions/:id/extend
{ "seconds": 60, "by": "human", "fence": 123 }
```

```json
{
  "decision_id": "...",
  "state": "grace",
  "grace_until": 1793931234000,
  "remaining_grace_seconds": 227,
  "extended_seconds": 120,
  "extension_count": 2,
  "max_extend_seconds": 300
}
```

**错误码**

| HTTP | code | 触发条件 |
|---|---|---|
| 400 | `INVALID_SECONDS` | 非整数 / <1 / >300 |
| 403 | `FORBIDDEN` | 无目标工作区写权限 |
| 404 | `DECISION_NOT_FOUND` | id 不存在 |
| 409 | `DECISION_NOT_GRACE` | 已 open / answered / withdrawn（含刚好到点落锁） |
| 409 | `EXTEND_LIMIT_EXCEEDED` | 累计延长会超过 `max_extend_seconds`，响应带当前 `extended_seconds` 与上限 |
| 409 | `STALE_FENCE` | 传了 fence 但与当前 claim fence 不一致（复用既有错误码，不新造） |

**落库与 fence**

- `grace_until = max(now, grace_until) + seconds`（按原到期时间顺延，不按「现在 + seconds」白送已流逝的时间）；同时 `extended_seconds += seconds`、`extension_count += 1`、记录 `extended_by` 与时间。
- `grace_seconds` 保留**原始值**不动，作为计算 `max_extend_seconds` 与展示「原宽限」的依据；总宽限由 `grace_seconds + extended_seconds` 得出。
- **不续 fence**：fence 属于 claim 租约，延长只移动宽限墙钟；传 fence 仅做一致性校验，不刷新租约。claim 仍按原规则持有/释放。
- 写一条决策事件（`decision.extended`，payload 含 seconds / extended_seconds / grace_until），Web 通过 WS 即时更新倒计时；随后按既有 `issue.changed` 口径刷新卡面（不新造第二套锁标识事件）。

**`skills/ask-user` 需要同步改的内容**（由实现卡负责，本轮只写契约）：在「宽限」一节增加「什么时候该延 / 什么时候不该延」（只在等待人类输入、且接近到期时延；LOCKED 后停手不延）、命令示例、连点与 300 秒/600 秒上限、跨区需写权限；并在 `Docs/api.md` 记录命令与退出码。

**如果以后要改成「内嵌看板页」**，需要同时变的东西（本轮不做，仅记录代价）：

1. 看板列宽本来就只有 ~300px，卡片里塞不下选项 + 后果，内嵌只能退化成一条提示条 → 仍然要跳出去回答；
2. 侧栏徽标、深链（通知点击）、`navStore.view` 三处都以「独立视图」为前提，内嵌要新增一套选中态；
3. 锁卡本来就在「待规划」列，内嵌会让锁卡和普通卡混排（§3.7 方案 B 已论证不推荐）。

## 4. 处置队列模型

三层，按「现在必须做什么」排，而不是按 state 枚举：

| 层 | 含义 | 排序键（默认「紧急度」） | 视觉 |
|---|---|---|---|
| `grace` | 还在宽限，agent 在等 | `grace_until` 升序（谁先到点谁在前）；≤60s 升级为 `critical` | 琥珀，2px 进度线，秒级倒计时 |
| `open` | 已落锁，agent 已停手 | 先按阻塞下游数降序，再按 `locked_at` 升序 | 石墨色轨，显示已锁时长 + 停止确认状态 |
| `stale` | `open` 且锁后 ≥72h | `locked_at` 升序（积压最久在前） | 红色轨 + 「建议处置」 |
| `answered` | 已处理，保留最近记录 | `answered_at` 降序 | 绿色轨 + 结论行 |

三种排序（紧急度 / 等待最久 / 任务优先级）在原型右上角可切；筛选 tab（全部 / 宽限中 / 待回答 / 已超时 / 已回答）带计数。RANK（`#1 #2 …`）只在未处理层连续编号，回答后自动重排。

为什么 `grace` 整体排在 `open` 前面：宽限是**唯一会自己变坏的状态**（到点变成锁，且 agent 收不到答案），`open` 已经是稳定态，晚 5 分钟回答不会更糟。

## 5. 卡片信息层级（自上而下）

1. **头部**：`#rank` · 状态 chip（`剩 2:47` / `已锁 26 分` / `超时 3 天 2 小时`）· 任务号 + 标题（可点进详情）· 优先级 · 同卡历史条数 · ↗
2. **问题**：默认 2 行截断，展开后全文（长问题场景专门演示）
3. **选项**：一行 chip（A/B/C…），点选即高亮；**末尾固定一个「✎ 自定义」**，选中后就地展开输入框（见 §3.2）；下方单行「选了会怎样」（后果预览），默认选项用灰字预展示默认后果。
4. **统计行**：提问者 · 触发原因 · **「阻塞 N 个下游」按钮**（点开就地展开下游清单，见 §3.4）·（open 时）停止已确认 N 秒 / **停止未确认**（红色）
5. **动作行**：`＋1 分钟`（仅 grace 卡，见 §3.5）+ `展开` + `提交回答`（未选时禁用；跨区卡首次点击变 `确认跨区回答`）；open 卡额外有 `稍后`（本会话隐藏）与 `撤回`（需理由）
6. **展开区**：背景全文 → 选项与后果（列表版，带「默认」标 + 自定义行）→ 关键值网格（阻塞下游 / 宽限合计 + 已延长 / 已锁时长 / 停止确认 / 答案版本）→ agent 断点 → 答案时间线 → 同一张任务卡上的其它决策（可跳）。**展开时不再渲染收起态的 chip 行**（见 §3.3）。

设计原则：**默认态就能完成一次处置**（1 选 1 提交）；展开区只服务「我要判断」而不是「我要操作」。

## 7. 关键交互与状态机

- **内联作答**：`选中选项` → `提交回答`（未选中禁用）。提交即进入 `leaving` 态：卡片不可点、覆盖「已记录 · 正在移出」；420ms 后写入答案、移入已回答、弹 undo toast。`prefers-reduced-motion` 下 420ms 变 0。
- **撤销**：6 秒内点「撤销」回滚到回答前状态（含 grace 剩余时间），卡片回到原分组。
- **改答案**：已回答卡点「改答案」→ 就地展开选项 → 保存为第 N+1 版（对应 append-only revision）；时间线保留每一版，当前版高亮点。
- **撤回**：open 卡「撤回」→ 必填理由（≥2 字，写进卡评论）→ 卡片移出、任务卡解锁；理由为空就地报错，不静默成功。
- **稍后**：本会话隐藏（不是改状态），底部出现「本会话已隐藏 N 条 · 恢复」。
- **双向跳转**：`goDecision(id)` 会强制回 `全部` 筛选、展开该条、清空详情面板并闪烁 720ms ×2。
- **延长宽限**：grace 卡动作行「＋1 分钟」→ `graceUntil += 60000`、`extendedSeconds += 60`，倒计时 chip 闪 700ms、toast 报剩余时间、进度条按合计宽限重算；到 `max_extend` 后按钮禁用。已锁卡没有该入口（见 §3.5）。
- **阻塞下游**：统计行按钮切换 `blocksOpen`，清单内卡号按钮打开该卡详情（含只存在于清单里的下游卡）；方向标题固定为「本卡 blocks 的下游」。
- **落锁**：倒计时归零 → 本地立刻转 `open`（`lockedAt = now`、写 `stop_requested_at`、`stop_ack_at = null`），弹 warn toast「已回待规划并上锁，agent 收到停止信号」。
- **计数**：侧栏徽标 = 未被隐藏的 `grace + open`，随回答实时减。

## 8. 视觉与动效

- 令牌全部沿用生产 `apps/web/src/index.css` 的 `--ab-*`（暖石墨 + 琥珀），本原型只是复制一份到 `styles.css` 顶部，未改值：`--ab-page/card/raised/hairline/ink/ink-2/ink-3/accent/accent-ink/accent-soft/add/del/add-soft/del-soft/shadow` + `.dark` 覆盖。
- 动效统一 `--ab-dur: 160ms` / `--ab-ease: cubic-bezier(0.2, 0, 0, 1)`；唯一例外是回答移出的 420ms（需要「看清发生了什么」）与进度线的 1s 线性更新。
- `@media (prefers-reduced-motion: reduce)`：所有 animation/transition 压到 1ms，进度线取消过渡，面板不做滑入。
- 卡片左缘 3px 强调条 = 状态色（琥珀 grace / 红 critical+stale / 石墨 open / 绿 answered）；进度线 2px 贴底边，不占内容行。
- 信息密度靠**对齐与字号层级**（10.5 / 11.5 / 12.5 / 14 / 18），不靠加边框和花纹；分割线只用 `--ab-hairline`。

## 12. 已知取舍

1. **选项 chip 只放标签，后果放下一行**：4 个选项各带一句说明会撑爆卡片高度；展开区才是完整对比。窄屏下 chip 会换行成 2 行。
2. **`answered` 段默认折叠到列表底部**：用户要的是「刚回答完看到它移走」，不是长期历史；超过 24h 的记录在真实实现里应交给日志/详情，不进列表。
3. **「稍后」只是本会话隐藏**：不引入新的服务端状态（v3 没有 snooze 语义），避免和「撤回」混淆。
4. **自定义答案仍是单选**：原型加了自由文本，但不改「一个问题只有一个答案」的口径——自定义只是第 N+1 种取值，不是多选。API/CLI 已支持 `answer_text`（见 §10），Web 端只需接线，不需要改服务端契约。
5. **自定义长度 120 字**：够写一句结论，不够写方案。选 120 而不是 500，是因为答案会进卡评论和时间线；如果产品后面要「长答案 + 附件」，应该单独设计，不要靠把 `maxlength` 调大解决。
6. **阻塞下游清单不递归展开**：间接下游只演示一层且默认折叠（见 §3.4）。真正的多跳依赖需要服务端给 `depth` / `path`，前端递归请求既慢又难解释；本轮给出建议、没定死实现。
7. **阻塞清单是示例数据**：`app.js` 的 `BLOCKED` 为演示用，真实实现只应从 `GET /api/issues/:id/dependencies` 的 `blocked[]` 取关系；占用者与原因字段当前不存在，已在 §10 标为「建议新增投影」，不在原型里假装已有。
8. **范围切换只做前端过滤**：原型切「所有工作区」是在内存里按 `ws` 字段过滤；真实实现要按 `workspace_id` 并发/并集查询，并处理各工作区的权限差异（见 §3.1 的跨区确认）。
9. **原型不接真实 API**：数据写死在 `app.js` 顶部，切换场景只改内存状态；所有数字都是演示值。
10. **延长固定 60 秒，不做自定义输入**：Web 上把「延多久」交给用户输入会把即时动作变成二次表单；CLI 保留 `--seconds 1–300` 给自动化/批处理用，Web 只发 60。若以后要「延 5 分钟」，做成下拉或长按，而不是在按钮旁再放个输入框。
11. **累计上限 300 秒 + 总宽限 600 秒双封顶**：只按次数封顶（比如 10 次）会让 600 秒配置下的总时长失控；只按总时长封顶又可能一次延太多。两者取小最简单，也最容易在服务端校验。
12. **LOCKED 后不提供延长**：延长只对「还在等」的决策有意义；对已锁卡延长会破坏「LOCKED 即停手」的契约。需要重开就走重新提问/撤回，不在这个按钮上做例外。
13. **页头只留总数**：范围交给下拉、状态条数交给 tab，避免同一信息三处重复；「其它工作区 N 条」也删掉——卡片上的 ws-chip 已经能看出跨区。
